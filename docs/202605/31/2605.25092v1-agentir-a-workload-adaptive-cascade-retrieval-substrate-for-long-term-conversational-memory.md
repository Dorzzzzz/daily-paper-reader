## 摘要
长期对话记忆是一种传统信息检索未针对其构建的检索工作负载：索引在查询流期间增长，查询类型在会话内发生变化，每次检索的延迟预算低于10毫秒。Lucene类引擎将索引视为静态、查询视为无状态，未利用工作负载的结构。AgentIR将融合视为沿两个轴线的每查询决策：应用哪种融合（BM25、Dense、RRF或agent-aware RRF），以及大约52毫秒的密集通道是否值得运行。第二个轴线是一个置信度触发的级联路由器，仅根据BM25 top-k间距做出决策，并在无需重新训练的情况下跨工作负载重新调优。在LongMemEval（n=500）上，密集通道确实增加了信息，级联在LLM判断准确率相当的情况下跳过了63%的查询（在两个评判者下快2.67倍，配对bootstrap p≥0.88）；每查询类型阈值在5折交叉验证下将其扩展到5.76倍。在LoCoMo（n=1,982）上，仅BM25已是最强的单一系统，同一触发器自动调优至100%跳过率（快132倍，+0.089 Hit@5）。共享8核VM上的容量从约154个并发代理增加到约1,400个（9倍）。在级联之下，时间分区索引执行与语料库大小无关的O(log 1/ε)工作：1234倍的语料库增长仅带来3.6倍的延迟，在500万记录上顺序扫描的1769倍性能下，p50低于100微秒。在多达880万文档的9个BEIR数据集上，与Lucene质量相当的情况下，该基座在Pyserini 8T上运行速度快10倍几何平均，在PISA-1T BlockMax-WAND上快11倍；A100相对于Pyserini 8T达到1.8-39倍；分块索引构建在MS MARCO上维持每秒56.8K文档。记录了三个微妙的BM25/GPU正确性陷阱，这些陷阱会无声地使nDCG@10下降6-8倍，并进行了修复；修复后，在适合单个A100的所有八个数据集上，CPU和GPU在nDCG@10上的差异在0.0002以内。

## Abstract
Long-term conversational memory is a retrieval workload classical IR was not built for: the index grows during the query stream, query types shift intra-session, and the latency budget per retrieval is sub-10 ms. Lucene-class engines treat the index as static and the query as stateless, leaving the workload's structure unexploited.   AgentIR treats fusion as a per-query decision along two axes: which fusion to apply (BM25, Dense, RRF, or agent-aware RRF), and whether the ~52 ms dense channel is worth running at all. The second axis is a confidence-triggered cascade router that decides from the BM25 top-k margin alone and re-tunes across workloads without retraining. On LongMemEval (n=500), where the dense channel does add information, the cascade skips 63% of queries at parity LLM-judged accuracy (2.67x faster under two judges, paired bootstrap p>=0.88); per-qtype thresholds extend this to 5.76x under 5-fold cross-validation. On LoCoMo (n=1,982), where BM25 alone is already the strongest single system, the same trigger auto-tunes to a 100% skip rate (132x faster, +0.089 Hit@5). Capacity on a shared 8-core VM rises from ~154 to ~1,400 concurrent agents (9x).   Underneath the cascade, a time-partitioned index does O(log 1/epsilon) work independent of corpus size: 1234x corpus growth costs only 3.6x latency, ending in 1769x over sequential at sub-100 us p50 on 5M records. At parity quality with Lucene on 9 BEIR datasets up to 8.8M docs, the substrate runs 10x geo-mean over Pyserini 8T and 11x over PISA-1T BlockMax-WAND; an A100 reaches 1.8-39x over Pyserini 8T; chunked index build sustains 56.8K docs/sec on MS MARCO. Three subtle BM25/GPU correctness pitfalls that silently regress nDCG@10 by 6-8x are documented and fixed; post-fix CPU and GPU agree within 0.0002 nDCG@10 on all eight datasets that fit a single A100.

## 1. 核心问题与整体含义（研究动机和背景）

长期对话记忆（Long-term Conversational Memory）是LLM代理在工作时不断积累的历史交互记录（对话轮次、工具调用、中间计划等），代理自身在几乎每一步推理中都需要查询这些记忆。该工作负载具有以下特殊性：

- **索引持续增长**：单次会话中语料库可从数千条增长至数百万条；
- **查询类型动态变化**：同一会话内会依次出现事实查找、推理查询、时间查询等，不同查询类型的最优检索策略不同；
- **延迟预算严格**：代理每步可能发起5–20次检索，每次检索必须控制在**10毫秒以内**，否则用户会感知到停顿。

现有检索系统（Lucene、FAISS、PISA）均未针对此场景设计：它们假设索引静态、查询分布平稳、延迟预算宽松。因此，需要一种专门为**工作负载动态自适应**的检索基座，能同时处理索引增长、查询异构和严格延迟约束。

## 2. 方法论：核心思想、关键技术细节

### 2.1 双轴自适应控制

AgentIR提出沿两个维度做每查询级别的自适应决策：

- **轴1：选择哪种融合策略**（BM25、Dense、RRF、或agent-aware RRF）；
- **轴2：是否值得运行约52毫秒的密集通道**（Dense channel）。

### 2.2 级联路由器（Cascade Router）

核心组件是一个**置信度触发的级联路由器**：

- 首先执行轻量级BM25搜索（~0.4 ms）；
- 计算**BM25 top-1与top-2分数间隔**：\( c(q) = (s_0 - s_1) / s_0 \)；
- 若置信度 \( c(q) \geq \tau_c \)（默认 \(\tau_c=0.10\)），则**跳过密集通道**，直接返回BM25结果；
- 否则**升级到密集通道**（BGE-small编码 + HNSW + RRF + 时效性加权），总耗时约53 ms。

该路由器无需重新训练即可跨不同工作负载自动调优（仅需调整阈值 \(\tau_c\) 或每查询类型阈值）。

### 2.3 时间分区索引

针对**强时效性偏置**（最近记录命中概率高），设计时间分区索引：

- 将文档按时间窗口（7天）划分成有序分区；
- 查询时从最新分区开始搜索，累积概率质量达 \(1-\varepsilon\) 后停止；
- **定理4.1**：在指数衰减的时效性分布下，预期工作量 \(W(\varepsilon) = O(\log(1/\varepsilon))\)，与总语料大小 \(N\) 无关；
- 实际中，语料从4K增长到5M（1234倍），仅造成3.6倍延迟增长，最终较顺序扫描快1769倍。

### 2.4 SIMD加速与GPU并行

- CPU端：使用AVX2/NEON向量化的BM25内积循环，8线程时可达12.6倍加速；
- GPU端：两核流水线（BM25评分核 + top-k选择核），CSR扁平索引布局，原子加操作；
- 文档化并修复了三个正确性陷阱（预归一化TF、线性增益nDCG、GPU共享内存脏数据），修复后CPU与GPU的nDCG@10差异<0.0002。

### 2.5 软路由器与融合

除硬路由外，还设计了**软路由器**：利用TF-IDF + BGE-small特征训练查询类型分类器，将后验概率作为权重，对多个系统的排名列表进行加权RRF融合。软路由器在gpt-4o-mini评判下显著优于所有静态系统（\(p<0.05\)）。

- **工程完备性**：全系统实现（C++17 CPU + CUDA GPU），文档化了3个易忽视的正确性陷阱并修复，确保可复现；
- **全面评估**：覆盖质量、延迟、缩放、多租户、鲁棒性、消融、统计检验，且所有对比在相同硬件下进行；
- **实用导向**：级联路由器仅需50条标注数据即可在数秒内调优，适合部署；给出了5分钟部署教程；
- **开放性好**：计划开源全部代码和数据。

## 8. 不足与局限

- **多租户仅CPU**：未评估GPU多租户共享、跨租户写入竞争；
- **静态索引头对头比较**：BEIR/PISA/SPLADE实验使用预构建索引；增量写入路径仅设计未基准测试；
- **LLM judge依赖**：下游准确率基于gpt-4o-mini/gpt-4o评判，换用其他LLM家族可能改变排序；
- **5M缩放使用合成语料**：真实生产环境5M记录跟踪数据未获得，80/20偏置虽受LongMemEval实证支持但非完全一致；
- **级联路由器延迟为推导值**：每阶段延迟和跳过率均测量，但总延迟为代数计算，非端到端墙壁时钟测量；
- **数据集仅英文**：未评估跨语言部署；
- **GPU top-k核效率**：\(k=100\)时因共享内存限制导致性能明显下降，未采用更优的bitonic sort等算法；
- **向量数据库基线仅引用公布数字**：未重新运行Pinecone/Milvus等做头对头实验。
