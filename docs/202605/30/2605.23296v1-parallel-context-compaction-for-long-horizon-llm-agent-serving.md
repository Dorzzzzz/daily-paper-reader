## 摘要
长视野LLM智能体会积累不断增长的对话历史，最终超出模型的上下文窗口。基于LLM的摘要进行上下文压缩可以保持对话有界，但摘要本质上有损，阻塞调用会使智能体推理停顿数十秒。此外，操作员无法细粒度控制摘要大小，因为提示指令在很大程度上被忽略，随着上下文增长，模型生成的输出令牌数量及其保留的信息量在不同运行之间波动很大，使得智能体保留的知识在不同运行间不可预测。我们引入了面向长视野智能体流的**并行压缩**，并在跨越8B到120B参数的四个骨干网络上（混合密集和MoE架构，以及推理和非推理模型），在HotpotQA多跳QA和LoCoMo长上下文对话基准上，与顺序同步基线进行了对比。并行压缩使操作员能够细粒度、可预测地控制摘要大小，并实现每个块更有针对性的提示工程。在匹配的压缩解码量下，它减少了端到端墙钟时间，并提高了相比顺序基线的压缩吞吐量。

## Abstract
Long-horizon LLM agents accumulate growing conversation histories that eventually exceed the model's context window. Context compaction via LLM-based summarization keeps the conversation bounded, but summarization is inherently lossy and the blocking call stalls agent inference for tens of seconds. Moreover, the operator has no fine-grained control over summary volume since prompt instructions are largely ignored, and as context grows, both the amount of output tokens the model produces and the information it retains fluctuate substantially from run to run, making the agent's retained knowledge unpredictable across runs. We introduce \textbf{parallel compaction} for long-horizon agentic flows and characterize it against the sequential synchronous baseline across four backbones spanning 8B to 120B parameters, mixing dense and MoE architectures with reasoning and non-reasoning models, on the HotpotQA multi-hop QA and LoCoMo long-context dialogue benchmarks. Parallel compaction gives the operator fine-grained, predictable control over summary volume and enables more targeted prompt engineering per block. At matched compaction decode volume, it reduces end-to-end wall time and improves compaction throughput over the sequential baseline.

### 1. 论文的核心问题与整体含义

- **研究动机**：长视野LLM智能体（如多轮对话、多跳QA、编码代理）会积累不断增长的对话历史，最终超出模型的上下文窗口，导致推理质量下降、延迟增加。基于LLM摘要的顺序上下文压缩（sequential compaction）被广泛使用，但存在三个关键问题：① 摘要本质上有损，且阻塞调用使智能体停顿数十秒；② 操作员无法细粒度控制摘要体积——模型几乎忽略提示指令，输出长度几乎不受输入长度和提示措辞影响；③ 随着上下文增长，输出长度和内容在不同运行之间波动巨大，导致智能体保留的知识不可预测。
- **整体含义**：需要一种可预测、细粒度、高吞吐的上下文压缩方法，以支持长视野代理的稳定高效服务。

### 2. 论文提出的方法论

- **核心思想**：将长对话历史划分为多个连续块，对每个块并行执行LLM摘要，最后合并各块摘要形成压缩上下文。块大小（block size）B是用户可控的旋钮，直接决定每个摘要的输入长度和总输出体积。
- **并行压缩流程**（三阶段）：
  1. **快照与分区**：复制当前对话X，记录长度，将其划分为N个连续块，每块B个token（N=⌈|X|/B⌉，B为固定配置）。
  2. **分派**：为每个块k构建提示：包含从块1到块k的完整前缀，并将块k用<TARGET_BLOCK>...</TARGET_BLOCK>标记包裹。所有N个提示并发发送给vLLM服务。
  3. **合并**：等待所有worker完成后，将N个逐块摘要按块顺序拼接成压缩历史Ĥt，替换原始快照。
- **关键技术细节**：
  - **前缀感知目标在末尾布局**：每个worker看到完整历史前缀（保持缓存复用），目标块放在末尾（注意力最强处），同时维持跨块上下文依赖，比“独立块”或“全前缀”更优。
  - **控制旋钮**：阈值τ控制触发频率；块大小B控制并行worker数和输出体积。二者独立可调。
  - **提示工程**：块大小控制粗粒度体积；在块内可通过提示（简洁/详细）进一步微调输出长度。

### 6. 论文的主要结论与发现

1. **顺序压缩的输出体积具有输入不变性和提示不变性**：输入从2k增长到96k（48×），输出仅增长约3倍；切换提示指令对输出长度几乎无影响。模型自限输出长度，源于训练数据中的摘要长度先验。
2. **顺序压缩的稳定性随上下文增长急剧恶化**：长输入下输出长度变异系数可达171.6%，余弦相似度低至0.47，信息保留不可预测。
3. **并行压缩提供细粒度、可预测的体积控制**：通过调整块大小，输出体积可从~3%提升至~50%的原始上下文；结合提示，可实现双向微调。
4. **并行压缩在匹配解码量下提升吞吐量**：例如Llama-3.3-70B在HotpotQA上，并行（4k块）比顺序在类似输出量下吞吐量提升2.13×。
5. **并行压缩提高下游准确性**：随着块变小（更多worker），总结保留更多上下文，准确率单调提升。
6. **块大小的选择影响稳定性**：4k块在稳定性和信息保留之间取得良好平衡。

### 7. 优点

- **方法创新**：首次系统刻画了顺序压缩的不稳定性和不可控性，并提出并行分块压缩，将压缩体积控制从被动转向主动。
- **设计实用**：无需离线训练、无需检索基础设施、无需白盒访问模型内部；完全基于现有LLM服务中间件（vLLM）实现。
- **控制灵活**：通过块大小和提示两轴控制，操作员可按需调节输出体积，适应不同任务对上下文长度的要求。
- **实验全面**：覆盖多种模型架构、输入规模、提示变体，并采用统计指标量化稳定性，结论可靠。
- **工程友好**：前缀感知布局保持缓存复用，减少实际预填开销，对比“独立块”方案更优。

### 8. 不足与局限

- **实验覆盖有限**：仅两个基准（HotpotQA和LoCoMo），均为问答型；未涉及真实代理场景（如代码编辑、工具使用），可能低估方法在复杂流式任务中的收益或问题。
- **性能瓶颈**：并行压缩中，每个worker需预填自己的独特块内容（无法缓存），尤其在大块（16k）时预填开销可能导致性能下降（见表7中16k块端到端时间反而更差）。
- **准确性仍受限**：即使2k块，准确率仍未达100%，表明模型自身推理能力是上限。
- **未评估异步压缩**：当前实现仍是阻塞（等待所有worker完成），但论文提及异步压缩可作为未来工作；现实场景中异步可能进一步降低感知延迟。
- **标记感知问题**：模型未专门训练识别XML标记，可能影响摘要忠实性；未来或需微调。

- **资源需求**：并行压缩需要同时运行多个worker，可能增加GPU资源竞争或排队延迟；论文中未研究多请求并发对系统吞吐的影响。
