## 摘要
大语言模型智能体积累的历史记录会超出其上下文窗口，这激发了越来越多关于记忆系统的研究。然而，大多数现有设计仅针对单一场景（多会话聊天或单一轨迹格式）进行调优，几乎没有证据表明它们能够推广到智能体在部署中遇到的各种异质轨迹。我们在五个场景上重新审视了八个记忆系统以及一个用于搜索问题的智能体工具集：单轮问答、多会话聊天、智能体轨迹问答、记忆压力测试以及长周期智能体任务。该工具集通过工具调用来自我管理纯文本文件存储，在跨任务排名中表现最佳，这表明记忆性能的关键在于赋予智能体对存储和检索的主动控制权，而不是依赖固定流水线背后的被动存储。我们将这一见解实例化为AutoMEM，一个具有自我管理工具接口的智能体记忆工具集，在我们评估的系统中实现了最佳的跨场景通用性。

## Abstract
LLM agents accumulate histories that outgrow their context windows, motivating a growing literature on memory systems. Yet most existing designs are tuned to a single scenario (multi-session chat or a single trajectory format), and there is little evidence that they generalize across the heterogeneous trajectories agents encounter in deployment. We revisit eight memory systems plus an agentic harness for search problems, on five scenarios: single-turn QA, multi-session chat, agentic-trajectory QA, memory stress tests, and long-horizon agentic tasks. The harness, which self-manages flat text-file storage via tool calls, achieves the best cross-task ranking, suggesting that memory performance hinges on giving the agent active control over storage and retrieval rather than on a passive store behind a fixed pipeline. We instantiate this insight in AutoMEM, an agentic memory harness with a self-managed tool interface that achieves the best cross-scenario generality among the systems we evaluate.

## 2. 方法论：核心思想、关键技术细节与算法流程

- **核心思想**：记忆系统的关键在于让智能体在查询时主动决定如何检索和聚合信息（query-time commitment），而非事先提交构建时的固定模式（build-time commitment）。  
- **关键技术细节**：AutoMEM是一个智能体循环（Agentic Loop），流程如下（算法1）：
  1. **规划（Plan）**：规划器LLM从四个动作中选择一个：  
     - `rg`：基于正则表达式搜索原始记录。  
     - `read`：通过标识符提取整条记录。  
     - `dump`：将短语料直接发送给答案LLM。  
     - `index_query`：对预构建的索引执行类型化查询（默认使用LightMem构建的Cypher图，包含`SAID_BY`、`OF_TOPIC`、`FOLLOWS`等边）。  
  2. **执行（Execute）**：执行对应工具调用，将结果追加到运行记录（trace）。  
  3. **判官（Judge）**：LLM检查运行记录是否足够回答当前问题；若足够则生成最终答案，否则返回缺失信息的提示（hint）并重新进入规划步骤。  
  4. **答案（Answer）**：基于足够的运行记录调用答案LLM。  
- **默认实现**：一个LLM骨干（Qwen3-32B）承担所有角色；默认index_query使用LightMem的摘要索引构建的Cypher图。  
- **算法伪代码**（算法1）：  
  ```
  输入：记忆存储M，问题q，预算K_max  
  动作集：{rg, read, dump, index_query}  
  初始化 trace=[], hint=∅  
  循环 k=1..K_max:  
    a_k = PLAN(q, trace, hint)         // LLM调用  
    o_k = EXECUTE(M, a_k)               // 工具调用  
    trace = trace || (a_k, o_k)  
    v = JUDGE(q, trace)                // LLM调用  
    if v.sufficient then break  
    else hint = v.reason  
  返回 ANSWER(q, trace)                 // LLM调用  
  ```

## 6. 主要结论与发现

1. **无方法占优**：没有任何记忆系统在所有场景上胜出；DCI-Lite（agent harness）取得最佳跨任务通用性排名。  
2. **索引方法的两种失败模式**：  
   - **表示级失败**：构建时的模式丢弃步骤级和动作级信息（如HippoRAG）。  
   - **检索级失败**：被动检索无法取出仍然存储在底层原始轨迹中的答案（如PlugMem）。  
3. **长上下文比假设更强**：在多数基准上性能与索引方法相当甚至更好，且成本有竞争力。  
4. **动态智能体任务瓶颈在于策略**：记忆方法收敛到相似水平，而golden procedural memory仅能部分提升，状态依赖型决策（Gap 2）需要参数更新（如RL后训练）。  
5. **AutoMEM整合了工具集与选择性索引**：在LoCoMo上比DCI-Lite提高22.3个百分点（49.6%相对提升），在整体排名上最优（平均排名3.10 vs 4.10）。  
6. **结构化率预测索引何时有效**：只有当问题需要跨单元聚合且模式能表达所需谓词时，索引才发挥价值。

## 7. 优点

- **系统性诊断**：首次跨5个场景、多维度（准确率、token成本、延迟、系统效率）全面评估记忆系统。  
- **清晰问题定位**：揭示索引方法内在的两种失败机制，明确指出“主动控制 vs 被动管道”这一核心区别。  
- **强基线设计**：AutoMEM简洁有效，通过工具调用实现主动检索，并可以按需加入索引组件。  
- **实验设计严谨**：使用固定子集、统一判官协议、多种消融和探针（结构性率、Oracle可回答性、系统效率分类）。

## 8. 不足与局限

- **未实现分层预算路由**：AutoMEM的所有角色（规划、判官、答案）均使用同一强骨干，可将规划和判官分配给低成本模型以降低总成本（论文承认此为上限）。  
- **判官协议的方差**：严格事实判官可能影响绝对得分；在不同判官设置下相对排名可能有变化（作者已说明使用严格判官）。  
- **数据规模有限**：各基准均使用固定子集（如HotpotQA 200问），可能不完全代表全量性能。  
- **动态任务记忆高度收敛**：在ALFWorld等环境中记忆方法差异不大，主要改进来自策略而非记忆系统设计。  
- **框架仅限于Qwen系列模型**：实验骨干和嵌入模型均来自Qwen系列，未验证在GPT-4、Llama等其他架构上的泛化性。  
- **仅考虑了静态QA和动态任务**：未涉及持续学习、知识编辑等更宽泛的长期记忆需求。  
- **部署风险**：论文仅在基准环境中实验，未涉及用户数据隐私、安全防护等实际部署问题（虽在伦理部分提及）。
