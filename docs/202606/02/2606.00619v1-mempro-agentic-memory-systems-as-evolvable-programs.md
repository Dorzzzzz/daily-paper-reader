## 摘要
长周期自主智能体需要记忆系统来保留历史信息、跟踪不断演化的状态，并在有限上下文窗口之外复用相关知识。现有的智能体记忆系统通常遵循记忆构建-检索（MCR）流水线，但往往主要调整记忆库，而保持部署后的外围流水线固定。这种固定的流水线设计难以处理异构的特定任务故障模式，并可能随着时间的推移与规模和结构不断演化的记忆库失配。为了解决这些限制，我们提出了MemPro，一种系统级进化框架，将整个MCR流水线视为一个可进化的程序，而不仅仅是调整记忆库或提示文本。MemPro维护一个可运行记忆系统实现的版本树，其中进化智能体迭代地选择有前途的版本，诊断重复出现的故障，并通过故障模式引导的编辑-调试改进创建改进的子版本。在LongMemEval、LoCoMo、HotpotQA和NarrativeQA上的实验表明，MemPro在几次迭代内始终优于强大的静态和提示级进化基线，随着进化继续改进，并实现有利的性能-成本权衡。代码可在https://github.com/wanghai673/MemPro获取。

## Abstract
Long-horizon autonomous agents require memory systems to retain historical information, track evolving states, and reuse relevant knowledge beyond finite context windows. Existing agentic memory systems typically follow a memory construction-retrieval (MCR) pipeline, but often adapt mainly the memory bank while keeping the surrounding pipeline fixed after deployment. This fixed-pipeline design struggles to handle heterogeneous task-specific failure modes and can become misaligned with memory banks that evolve in scale and structure over time. To address these limitations, we propose MemPro, a system-level evolution framework that treats the entire MCR pipeline as an evolvable program rather than adapting only the memory bank or prompt text. MemPro maintains a version tree of runnable memory-system implementations, where an Evolving Agent iteratively selects promising versions, diagnoses recurring failures, and creates improved child versions through failure-mode-guided edit-debug refinement. Experiments on LongMemEval, LoCoMo, HotpotQA, and NarrativeQA show that MemPro consistently outperforms strong static and prompt-level evolving baselines within a few iterations, continues to improve with evolution, and achieves a favorable performance-cost trade-off. Code is available at https://github.com/wanghai673/MemPro.

### MemPro：作为可进化程序的智能体记忆系统 (MemPro: Agentic Memory Systems as Evolvable Programs)

#### 1. 论文的核心问题与整体含义

- **研究动机与背景**：大型语言模型（LLMs）驱动的自主智能体需要记忆系统来处理长周期任务。现有智能体记忆系统普遍采用“记忆构建-检索”（MCR）流水线。
- **核心问题**：论文识别出当前MCR流水线的两个关键缺陷：
    1.  **任务异构性**：固定流水线无法针对不同类型的记忆任务（如时间推理 vs. 跨会话推理）调整不同的记忆使用策略。
    2.  **记忆-流水线失配**：随着记忆库的规模和结构在运行中不断演化，固定不变的流水线逻辑（如构建和检索策略）会与记忆库的实际组织方式错位，导致检索不完整或证据噪声。
- **整体含义**：该论文主张，记忆系统的自我进化不应仅限于调整存储的记忆内容（记忆库）或提示文本，而应升级到“系统级”层面，即将整个可执行的MCR流水线本身作为一个可优化的程序。

#### 2. 论文提出的方法论：MemPro

- **核心思想**：MemPro将整个MCR流水线视为一个“可进化程序”（evolvable program），通过维护一个“版本树”，并利用一个“进化智能体”进行迭代式的故障诊断与代码级修改，实现系统的自我优化。
- **关键技术细节**：
    1.  **MCR版本树 (Version Tree)**：
        - 结构：维护一棵树 `T = (V, E)`，每个节点 `v` 代表一个完整的、可运行的MCR流水线实现 `Fv` 及其评估日志 `Lv`。日志包含总体得分、分类别得分、父节点信息和综合评估（故障模式分析）。
        - 作用：允许从历史上表现优异的版本分支出去探索，而非仅沿着当前最新版本做线性优化。
    2.  **迭代进化过程（由“进化智能体”Aevo 驱动）**：
        - **选择 (Selection)**：进化智能体根据所有节点的日志，基于高总体得分、可推广的改进方向和频繁的故障模式，选择最有可能的父节点 `v*` 进行扩展，并生成诊断分析 `Rℓ`。
        - **扩展 (Expansion)**：在选中的父节点上，通过“编辑-调试”循环创建子版本 `uℓ`。智能体可选择三种动作：
            - **EDIT**：根据诊断分析修改流水线的提示或可执行代码。
            - **DEBUG**：在不修改流水线的前提下，选择一个诊断性示例运行，获取执行跟踪，并据此更新诊断分析，以更深入理解问题。
            - **TERMINATE**：完成扩展，形成新的流水线版本。
        - **评估 (Evaluation)**：新版本在完整训练集上运行，收集执行跟踪，再由进化智能体生成其评估日志，并将其作为新节点加入版本树。
