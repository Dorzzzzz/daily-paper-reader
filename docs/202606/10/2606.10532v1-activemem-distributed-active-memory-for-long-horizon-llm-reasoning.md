## 摘要
记忆对于使大型语言模型（LLM）智能体能够处理长程推理任务至关重要。现有的记忆机制大多是集中式的，通常将检索到的信息和交互历史组织在单个模型上下文中。这种设计带来了一个根本性的权衡：扩展推理轨迹可能导致上下文过载，而激进的内容修剪则可能导致不可逆的信息丢失。为了寻求更好的权衡，我们从人类认知系统中汲取灵感，特别是前额叶皮层（执行控制）与海马体（记忆管理）之间的功能互补，这表明这种权衡并非必然存在，而可能源于集中式的记忆组织。为此，我们提出了ActiveMem，一种将智能体记忆与核心推理过程解耦的异构框架。具体而言，高层规划器利用提炼的语义要点进行推理，而轻量级分布式记忆系统并行运行，在整个任务中主动累积和巩固这些要点。在BrowseComp-Plus和GAIA上的实验表明，ActiveMem以显著降低的开销实现了最先进的准确性，证明了分布式主动记忆在长程推理中的有效性。

## Abstract
Memory is essential for enabling large language model (LLM) agents to handle long-horizon reasoning tasks. Existing memory mechanisms are largely centralized, typically organizing retrieved information and interaction history within a single model context. This design imposes a fundamental trade-off: scaling reasoning trajectories risks context overload, whereas aggressive content pruning may result in irreversible information loss. Seeking a better trade-off, we draw inspiration from human cognitive systems, especially the functional complementarity between the prefrontal cortex (executive control) and the hippocampus (memory management), suggesting that such a trade-off need not be inherent, but may instead stem from centralized memory organization. To this end, we propose ActiveMem, a heterogeneous framework that decouples agent memory from the core reasoning process. Specifically, a high-level Planner utilizes distilled semantic gists to execute reasoning, while a lightweight, distributed memory system operates in parallel to actively accumulate and consolidate these gists throughout the task. Experiments on BrowseComp-Plus and GAIA show that ActiveMem achieves state-of-the-art accuracy with significantly reduced overhead, demonstrating the effectiveness of distributed active memory for long-horizon reasoning.

- **核心问题**：现有LLM智能体的记忆机制多为**集中式**，将检索到的信息和交互历史全部堆积在单个模型上下文中。这种设计导致一个根本性权衡：随着推理轨迹增长，上下文迅速膨胀引发“过载”和“中间信息丢失”问题；若激进地修剪或压缩上下文，又会造成不可逆的信息丢失。
- **背景**：受人类认知系统中前额叶皮层（执行控制）与海马体（记忆管理）的功能互补启发——前额叶不存储细节，而是发出顶层查询；海马体并行完成模式补全并提取抽象语义要点。论文认为上述权衡并非固有，而是源于集中式组织，并据此提出**解耦记忆与推理**的新范式。
- **整体含义**：ActiveMem通过将智能体记忆从核心推理解耦为分布式主动记忆系统，在保持推理上下文紧凑的同时避免信息丢失，从而在长程推理任务中实现更优的准确率和效率。

## 2. 方法论：核心思想、关键技术细节、公式或算法流程

- **核心思想**：构建**异构框架**，包含一个高层**规划器（Planner）**和一个**分布式记忆系统**。规划器仅处理紧凑的推理上下文（原始问题+最近K步历史+蒸馏语义要点），而记忆系统并行、持久地管理文档级信息。
- **关键技术细节**：
  - **Planner**：使用Qwen3.5-397B-A17B生成检索查询，接收记忆系统返回的语义要点，更新状态并决定下一步动作或提交答案。通过`Trim`保留最近K步交互历史，丢弃的历史信息已由记忆系统存储。
  - **Distributed Memory System**：
    - **Memory Shards**：固定数量的逻辑分片（论文设16个），每个以键值对形式存储文档ID对应的蒸馏要点`gc`和历史查询集合`Hc`。
    - **Memorizers**：轻量级（4B参数）模型，对每个查询-文档对`(q, c)`生成条件语义要点`gc = ω(c, q)`（或`∅`表示无关）。通过SFT训练学习从Planner真实交互数据中蒸馏。
    - **Operator**：协调层，执行路由、相似性判断（`J(q, Hc)` → `SIMILAR`或`NEW`）和异步合并（`Consolidate`）。
  - **算法流程**（Algorithm 1）：
    1. 初始化所有分片和历史。
    2. 循环直到`submit_answer`：
       - Planner从状态`st = (x, ht, mt-1)`生成查询集合`Qt`。
       - 检索器获取文档集`Dt`，Route分配至对应分片（并行，最多N个）。
       - 对每个文档：若未见过则蒸馏并写入；若见过且查询相似则直接复用（Memory Hit）；若见过但新查询则蒸馏新要点并异步合并。
       - 收集所有要点作为观察`ot`，更新历史并裁剪至K步。
- **公式**：
  - 裁剪：`ht = Trim(ht-1 ∪ {at, ot})`。
  - 蒸馏：`gc = ω(c, q)`。
  - 合并：`(g'c, H'c) = Consolidate(gc, gnew, Hc, q)`。
  - SFT损失：`LSFT = -E_{q,c,gc} ∑log pω(gc,t | q, c, gc<t)`。
- **自动训练数据构建**：在BrowseComp-Plus训练集上先运行完整ActiveMem，收集12,000个真实查询-文档对，用gpt-oss-120b生成目标要点，训练Memorizer。

- **准确率最高且开销最低**：ActiveMem在BrowseComp-Plus上LasJ=0.79（第二0.72），ACT=0.785；在GAIA上LasJ=0.62，PFLOPs=187（最少）。

- **更强的Memorizer提升质量**：SFT训练后的Memorizer相比原始思维模型，在降低总PFLOPs的同时提高准确率。
- **Trim窗口适度最佳**：k=10给出最好权衡；太小导致Planner信息不足，太大引入噪声。
