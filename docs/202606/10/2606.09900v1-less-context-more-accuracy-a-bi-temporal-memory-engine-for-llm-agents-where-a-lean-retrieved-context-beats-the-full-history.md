## 摘要
长期记忆是LLM代理缺失的一层：跨会话时它们会遗忘，而常见的变通方法——将整个历史重放到提示中——昂贵、缓慢，且随着干扰物积累，准确率下降。大多数记忆系统在成本或延迟上胜出，但在准确率上仍不及完整上下文基线，且基准测试结果报告于不一致、不可复现的测试框架上，因此同一系统在不同来源中得分差异巨大。我们提出Engram，一个基于双时态数据模型的开源双过程记忆引擎。快速写入路径在关键路径上无需LLM即可追加无损事件；异步路径抽取原子（主语、谓语、宾语）事实，构建双时态知识图，并无需对每个事实调用LLM即可解决矛盾——使无效化，从不删除，因此每个事实都保留来源和继承链。混合读取路径融合稠密、词汇、图和近因/显著性信号，应用时间点（'as-of'）过滤器，并组装紧凑的、带有来源标记的上下文。在完整的500个问题的LongMemEval_S上，由官方类别特定评判器评分，Engram的精简配置——从约9.6k令牌的检索片段回答，从不使用完整历史——得分为83.6%，而完整上下文为73.2%（+10.4分，McNemar p < 10^-6），令牌数减少约8倍（9.6k vs 79k），且0/500错误。增益需要混合读取路径：仅事实丢失召回率，而事实加上检索片段恢复细节。我们还贡献了一个中立的、库内评估框架，内置官方评判器，并在每个表格中提供完整上下文基线，发布每个问题的原始日志，并记录那些悄然扭曲记忆基准测试的测量完整性陷阱（截断、自建评判器、完整历史泄露）。每个数字都附带可复现它的命令。

## Abstract
Long-term memory is the missing layer for LLM agents: across sessions they forget, and the common workaround -- replaying the whole history into the prompt -- is expensive, slow, and, as distractors accumulate, less accurate. Most memory systems win on cost or latency but still lose to the full-context baseline on accuracy, and benchmark numbers are reported on inconsistent, non-reproducible harnesses, so one system appears at wildly different scores across sources. We present Engram, an open-source, dual-process memory engine on a bi-temporal data model. A fast write path appends lossless episodes with no LLM on the critical path; an asynchronous path extracts atomic (subject, predicate, object) facts, builds a bi-temporal knowledge graph, and resolves contradictions without an LLM call per fact -- invalidating, never deleting, so every fact keeps provenance and a supersession chain. A hybrid read path fuses dense, lexical, graph, and recency/salience signals, applies a point-in-time ("as-of") filter, and assembles a compact, provenance-tagged context. On the full 500-question LongMemEval_S, graded by the official category-specific judge, Engram's lean configuration -- answering from a ~9.6k-token retrieved slice, never the full history -- scores 83.6% vs. 73.2% for full-context (+10.4 points, McNemar p < 10^-6) at ~8x fewer tokens (9.6k vs. 79k), with 0/500 errored. The gain needs a hybrid read path: facts alone lose recall, while facts plus retrieved chunks recover detail. We also contribute a neutral, in-repo evaluation harness with the official judge baked in and the full-context baseline in every table, publish the raw per-question logs, and document the measurement-integrity pitfalls (truncation, home-grown judges, full-history leaks) that silently distort memory benchmarks. Every number ships with a command to reproduce it.

## 1. 核心问题与整体含义（研究动机和背景）

- **核心问题**：LLM 智能体在跨会话交互中缺乏长期记忆机制，每次会话结束后状态丢失。常见的变通方法——将整个历史对话拼接到 prompt 中（全上下文基线）——面临三个主要瓶颈：
  - 令牌成本随历史线性增长；
  - 延迟随之增加；
  - 准确率下降：历史中的无关干扰（distractors）会掩盖关键信息，LLM 容易“迷失在中间”（Lost in the Middle）。
- **现有记忆系统不足**：多数面向 LLM 智能体的记忆系统（如 MemGPT、Generative Agents、Mem0、HippoRAG 等）在成本或延迟上优于全上下文，但在准确率上仍无法超越它。同时，不同系统报告的基准分数来自不一致的评估框架（不同的数据摄入、答案提示、评判器），导致同一系统的得分在不同来源间差异巨大（如 58%、66%、92%），缺乏可复现性和公平比较。
- **整体含义**：论文认为，长期记忆不应仅作为成本优化手段，而应能提升智能体回答的准确性。通过精心设计的检索和结构化存储，一个紧凑的、精准检索的上下文片段可以胜过膨胀的全历史上下文，同时节省大量令牌。

## 2. 方法论：核心思想、关键技术细节

### 2.1 核心思想：双过程架构 + 双时态数据模型 + 混合读取路径

- **双过程（Dual-Process）架构**：灵感来自认知科学的 System-1/System-2 划分。
  - **System-1（热写路径）**：在线、快速、无 LLM 阻塞。追加无损事件（episode），进行身份解析，计算轻量嵌入，并加入队列。
  - **System-2（异步合并路径）**：离线执行，从事件中抽取原子事实，构建双时态知识图，检测冲突并无效化，计算显著性并应用遗忘曲线。
- **双时态数据模型**：
  - **事件（Episode）**：原始、无损的对话轮次，带有事件时间（世界时间）和摄入时间（记录时间）。
  - **事实（Fact）**：原子化的 (subject, predicate, object) 三元组，附带表面文本、嵌入、显著性、置信度、来源事件 ID，以及两个时间轴：有效时间（valid_at / invalid_at）和事务时间（created_at / expired_at），外加一个 supersedes 指针指向被替换的事实。
  - **实体/关系（Entity/Relation）**：图节点和边，同样携带双时态戳。
  - **核心理念**：被矛盾的事实不会被硬删除，而是被无效化（设置 invalid_at），保留完整历史以支持审计和时序查询。
- **廉价升级冲突解决（Cheap-then-Escalate Conflict Resolution）**：
  - 步骤 1：精确槽匹配（slot match）检测可能的更新；嵌入相似性捕获同一属性在不同自由形式谓语下的表述；内容包含关系区分增加与矛盾。
  - 步骤 2：若为明显矛盾且有时序，则仅通过设置 old.invalid_at ← new.valid_at 和 supersedes 指针来无效化旧事实，无需 LLM 调用。
  - 步骤 3：仅当真正模糊时，才升级到 LLM 裁决。
- **混合读取路径（Hybrid Read Path）**：
  - 查询分解（多跳问题分解为子查询）。
  - 并行检索四种信号：稠密语义（dense embedding）、BM25 词汇、图 n-hop 近邻、近因/显著性。
  - 通过**倒数秩融合（Reciprocal Rank Fusion, RRF）** 融合排序列表，可选交叉编码器重排序（默认关闭）。
  - 应用**双时态“as-of”过滤器**：返回在指定时间点被认为为真的信息。
  - **弃权门（Abstention Gate）**：当证据不足时拒绝回答，避免幻觉。
  - 组装去重、带来源标记、满足令牌预算的上下文。
- **评分公式**：  
  score(item | q) = w_sem·cos(q, item) + w_lex·bm25(q, item) + w_graph·prox(item) + w_rec·e^{-Δt/τ} + w_sal·sal(item)  
  权重可配置，在评估框架上调优。

### 2.2 关键技术细节

- **System-1 实现**：add(messages) 在 <50ms 内完成（身份解析 + 轻量嵌入 + 队列），关键路径无 LLM 调用。
- **System-2 实现**：默认使用基于规则的抽取（可配置 LLM 模型）；知识图构建（如支持 Kuzu/Neo4j）；无效化而非删除；显著性衰减与强化。
- **冲突解决的具体策略**：先精确匹配 → 再嵌入相似度判断 → 再内容包含判断 → 再明显矛盾无害化处理（无 LLM） → 最后 LLM 裁决。
- **读取路径中的抽象层级**：除了原子事实，还检索原始事件块和会话摘要（session summaries）。
- **可插拔后端**：LLM、嵌入器、向量存储、图存储、词汇索引均通过接口可替换，且提供零依赖离线回退（哈希嵌入、内存存储），保证端到端可复现。

## 3. 实验设计

### 3.1 数据集和基准

- **评判器**：使用官方类别特定评判 prompt（包括时序的 off-by-one 容差、知识更新的旧信息容差、偏好评判的宽松语义等），评判器为 DeepSeek-V3.2。
- **同一个答案生成器（Answerer）应用于所有系统**：doubao-seed-2.0-pro。
- **嵌入器**：BAAI/bge-small-en-v1.5（本地，无需 API 密钥）。

### 3.2 对比系统

- **Engram_lean**（核心配置）：仅从检索得到的混合上下文（~9.6k tokens）回答，从不接触完整历史。

- **engram_full**（额外变体）：将冲突解决后的事实拼接在完整历史之上，测试事实贡献。

### 3.3 检索配置

- 5 个信号通过加权 RRF 融合，RRF 常数 k=60。
- 权重：w_sem=1.0, w_lex=0.6, w_graph=0.8, w_rec=0.3, w_sal=0.25。
- 精简片段组成：最多 8 个冲突解决事实、15 个融合项目、2 个原始会话块、28 个会话摘要。
- 所有超参数在框架上统一调优，并非每个问题单独设置。

## 6. 主要结论与发现

- **核心结论**：在 LongMemEval S 的 500 个问题上，Engram_lean（~9.6k 令牌检索上下文）达到 83.6% 准确率，远超全上下文基线（73.2%），绝对提升 10.4 个百分点（McNemar p<10^-6），同时令牌使用减少约 8 倍（9.6k vs 79k）。Engram_full（事实+全历史）得分 83.4%，证明结构化事实带来了几乎全部增益，而完整历史只是增加令牌。
- **启发**：精炼的检索上下文确实可以超出全上下文准确率，验证了“迷失在中间”假设——去除干扰物后，LLM 能更好聚焦。
- **混合读取路径不可少**：仅事实路径丢失细节，必须与原始块结合才能恢复召回率。
- **双时态建模特别有效**：在知识更新类别（87.5%）和时间推理类别（81.1%）表现出色；弃权类别 86.7%。
- **改进空间**：多会话聚合（79.3%）和单会话偏好（73.3%）仍是难点。

## 7. 优点

1. **创新方法论**：双过程架构将写路径与 LLM 解耦，大幅降低写操作延迟；双时态数据模型天然支持“as-of”查询和非破坏性冲突解决，保留完整审计轨迹。
2. **超越成本优化**：实现了准确率提升，将长期记忆从“省钱”工具转变为“提效”组件。
3. **高度可复现**：开放源代码、全部配置、原始日志、单命令复现，解决领域内基准不一致的顽疾。
4. **中性评估框架**：嵌入官方评判器、统一答案器、在每个表格中报告全上下文基线、记录测量完整性陷阱（如截断、自制评判器、全历史泄露）。
5. **隐私友好**：支持完全本地运行（无 API 密钥）、无效化而非删除便于“被遗忘权”、显著性衰减让个人信息自动淡出。
6. **低成本冲突解决**：大多数矛盾通过规则（无 LLM 调用）解决，只有极少数模糊情形才调用 LLM，节省成本。

## 8. 不足与局限

1. **实验覆盖狭窄**：仅用一个基准（LongMemEval S）和一个答案生成模型（doubao-seed-2.0-pro），未验证在其他基准（如 LOCOMO）或其他容量级模型（如小型开源模型和前沿模型）上的泛化性。
2. **缺乏运行间方差评估**：仅报告单次运行结果，未评估答案生成器随机性带来的波动。
3. **组件消融不完整**：未在完整 500 问题上进行正式的控制消融实验（如事实 vs 事实+块 vs 纯原始块等），仅作为观察性陈述。
4. **分类局限性**：多会话聚合和偏好类别仍存在显著不足，未提出针对性改进方案。
5. **检索阈值固定**：hyperparameters（融合权重、top-k 等）虽在框架上调优，但未探讨不同历史长度下的自适应策略。
6. **潜在偏差**：基于单一 API 模型可能隐含模型偏好，且只使用一个嵌入模型（bge-small），未测试其他嵌入器。
7. **假设依赖**：依赖准确的实体识别和事实提取；在噪声较大的对话中，提取质量可能下降，论文未充分讨论鲁棒性。
