## 摘要
长期LLM agent需要持久记忆，能够跨会话跟踪变化的事实并提供相关证据。现有的记忆系统通常将观察结果存储为孤立的记录、摘要或索引片段，这使得证据聚合、事实修正和记忆维护变得困难。我们提出Infini Memory，一种可维护的基于文本的持久记忆架构，将agent记忆视为主题结构化文档。每个主题文档作为一个语义单元，用于收集相关证据、保存元数据并随时间修正事实。新的观察结果首先暂存在缓冲区中，然后定期合并成连贯的文本上下文。在推理时，一种agent检索过程允许LLM通过迭代工具调用（而非单次检索步骤）读取记忆。在MemoryAgentBench上，Infini Memory取得了64.7%的总分。消融实验表明，主题结构维护和迭代证据检查改善了长期记忆使用的互补方面。

## Abstract
Long-term LLM agents need persistent memory that can track changing facts and provide relevant evidence across sessions. Existing memory systems often store observations as isolated records, summaries, or indexed fragments, which makes evidence aggregation, fact revision, and memory maintenance difficult. We propose Infini Memory, a maintainable text-based persistent memory architecture that treats agent memory as topic-structured documents. Each topic document serves as a semantic unit for collecting related evidence, preserving metadata, and revising facts over time. New observations are first staged in a buffer and periodically consolidated into coherent textual contexts. At inference time, an agentic retrieval procedure lets the LLM read memory through iterative tool calls rather than a single retrieval step. On MemoryAgentBench, Infini Memory achieves 64.7% overall score. Ablations show that topic-structured maintenance and iterative evidence inspection improve complementary aspects of long-term memory use.

## 1. 论文的核心问题与整体含义（研究动机和背景）

- **核心问题**：现有LLM agent的长期记忆系统通常将观察结果存储为孤立记录、摘要或索引片段，导致**四个常见故障模式**：
  1. **记忆碎片化**：同一用户/任务/事件的证据分散在许多小记录中；
  2. **记忆冲突**：新旧观察相互矛盾时，附加式存储保留两个版本；
  3. **压缩损失**：长历史压缩为摘要时丢失时间顺序和来源线索；
  4. **检索不足以支持推理**：单次检索返回孤立片段，缺乏足够上下文进行多跳推理。
- **研究动机**：构建一个可维护的持久记忆架构，支持三个核心操作——**写入**（将交互中的持久信息存入记忆）、**维护**（分组、核对、保留线索）、**读取**（检索具有足够局部上下文的证据）。
- **整体含义**：记忆模块的质量取决于“如何维护”和“如何检索”，两者互补。主题文档结构和迭代检索可显著提升长期记忆任务的性能。

## 2. 论文提出的方法论：核心思想、关键技术细节

- **核心思想**：将agent外部记忆表示为**主题结构化文档（topic documents）**，每个文档作为一个语义单元，收集相关证据并保存元数据；新观察先进入缓冲区（CURRENT），定期合并（consolidation）后写入主题库；推理时通过agentic检索（迭代工具调用）获取证据。

- **关键技术细节**：
  - **主题文档格式**：每个文档包含元数据头（id、summary、token_count、create_time、update_log等）和层次化正文（使用主题/子主题标题组织条目，每个条目带有`<seq=..., time=..., source=...>`签名）。
  - **缓冲写入与合并**：
    - **CURRENT缓冲区**：新提取的记忆先追加到缓冲区，避免频繁重写主题库。
    - **冲刷条件**：`|C| ≥ τtok` 或 `Δt(C) ≥ τtime`（默认5000 tokens或时间阈值）。
    - **合并流程**：冲刷时重写CURRENT为REWRITE_CURRENT（归一化草稿），然后规划（Plan Update）决定更新已有主题文档还是创建新文档，最后应用重写、拆分、合并等操作。
    - **周期性维护**：过大的文档拆分（默认>5000 tokens），过小的文档合并（<1000 tokens）。
  - **agentic检索**：
    - **混合检索（Infini Memory-H）**：LLM根据摘要选择候选文档，BM25补充词汇匹配的分区。
    - **agentic检索（Infini Memory-A）**：LLM控制多步搜索过程，调用工具（grep、grep_doc、search、list_docs、read_lines），迭代检查、扩展上下文，直到足够证据或达到最大迭代（默认7轮）。如果证据不足，回退BM25。
  - **扩展性**：默认使用纯文本文档存储和词法索引，不需要向量数据库或图数据库；元数据区域可扩展命名空间、实体模式、访问规则等。
