## 摘要
LLM智能体越来越多地部署在需要持续推理的长时任务上，这些任务涉及对扩展交互历史的持久推理。大规模实现这一点要求智能体跨会话持久存储、检索和更新自己的记忆。已经涌现出丰富的智能体记忆系统生态系统，包括平面检索、LLM中介提取、整合事实存储以及自主控制流。然而，它们的系统级行为仍未得到表征。我们首次对智能体记忆进行系统特征描述。首先，我们引入了一个面向系统的分类法，沿四个轴对智能体记忆系统进行分类。其次，我们构建了一个阶段感知的性能分析框架，将成本归因于构建、检索和生成。第三，我们对两个基准套件中的十个代表性系统进行特征描述，揭示了设计选择如何在写入和读取路径上转移成本。最后，我们提出了10条系统建议，涵盖构建调度、能力下限、通过查询量的摊销、新鲜度-延迟权衡以及集群规模管理。

## Abstract
LLM agents are increasingly deployed on long-horizon tasks requiring sustained reasoning over extended interaction histories. Realizing this at scale requires agents to persistently store, retrieve, and update their own memory across sessions. A rich ecosystem of agent memory systems has emerged spanning flat retrieval, LLM-mediated extraction, consolidating fact stores, and agentic control flows. Yet, their system-level behavior remains uncharacterized. We present the first systems characterization of agent memory. First, we introduce a system-oriented taxonomy classifying agent memory systems along four axes. Second, we build a phase-aware profiling harness attributing cost to construction, retrieval, and generation. Third, we characterize ten representative systems across two benchmark suites, uncovering how design choices shift cost across the write and read paths. Finally, we derive 10 system recommendations covering construction scheduling, capability floors, amortization via query volume, freshness-latency tradeoffs, and fleet-scale management.

## 2. 方法论：核心思想、关键技术细节

### 核心思想

- 提出一个**面向系统的四轴分类法**，将智能体记忆系统按四个维度归类：
  1. **构建机制（Construction）**：无、确定性（如分块/索引）、LLM中介（如事实提取）、自主（Agent-based，LLM控制写入）。
  2. **存储结构（Storage）**：原始文本缓冲、倒排索引、稠密向量索引、知识图谱、多存储混合。
  3. **检索策略（Retrieval）**：单次稀疏/稠密搜索、多级流水线（稀疏+稠密+图遍历+重排序）、自主控制循环。
  4. **可变性（Mutability）**：追加（append-only）、合并（consolidate）、变异（mutate）。

- 将智能体记忆执行流水线分解为七个阶段：**摄取（Ingestion）→ 记忆构建（Memory Construction）→ 存储（Storage）→ 检索（Retrieval）→ 提示组装（Prompt Assembly）→ 生成（Generation）→ 维护（Maintenance）**。

- 构建了一个**阶段感知性能分析工具**，将成本归因于三个逻辑阶段：记忆构建、检索和生成。该工具记录API遥测（token数、模型调用、延迟）和硬件遥测（GPU利用率、功耗、VRAM、SM活动等），实现精细化成本分析。

### 关键技术细节

- 标准化了可控因素：所有系统使用相同的生成LLM和嵌入模型（当需要时）；历史数据以4096-token块流式输入；查询时检索上限为10条记忆；对本地模型限制上下文窗口。

## 6. 论文的主要结论与发现

1. **构建成本主导生命周期**：对于LLM中介的记忆系统，构建能耗超过300次查询的总查询阶段能耗。每正确回答的能量消耗跨度达47倍以上。
2. **构建是预填充和嵌入主导的工作负载**：构建阶段反复读取长块并生成紧凑输出（如事实列表），解码token占比中位数仅4.6%。嵌入流量因范式而异：范式III.a产生大批量离线索引流量，范式III.b和IV产生顺序单事件写入流量。
3. **构建LLM选择受算法约束**：无严格输出合约的系统（如Mem0, SimpleMem, A-Mem）可以平滑降级到小模型；有严格输出合约的系统（如MIRIX）在弱模型上完全失败，存在能力下限。
4. **不存在在所有轴上都最优的系统**：系统在构建成本、查询延迟和准确率之间做出不同权衡，需要根据工作负载特性选择。
5. **跨会话构建带来新鲜度-延迟权衡**：当构建慢于会话到达间隔时，系统面临阻塞用户（同步）或服务过时记忆（异步）的抉择。每会话构建时间跨度达五个数量级。
6. **每用户记忆足迹与token成本增长斜率不同**：足迹差异约9倍（1M token下），但构建token成本斜率差异更大：自主系统（Letta, A-Mem, MIRIX）随记忆增长超线性增长，需要主动压缩策略。
7. **延迟结构受算法绑定 vs LLM绑定影响**：算法绑定的系统（如BM25）具有窄尾延迟；LLM绑定的系统（如GraphRAG, Letta）因工具调用或推理轮次可变而产生更宽的尾延迟。
