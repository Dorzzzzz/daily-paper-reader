## 摘要
长周期自主智能体需要记忆系统来保留历史信息、跟踪演化状态，并在有限上下文窗口之外重用相关知识。现有的智能体记忆系统通常遵循记忆构建-检索（MCR）流程，但往往主要调整记忆库，而部署后固定了周围流程。这种固定流程设计难以处理异构的任务特定失败模式，并可能随着时间推移与规模和结构演变的记忆库不匹配。为解决这些限制，我们提出MemPro，一种系统级进化框架，将整个MCR流程视为一个可进化程序，而不仅仅是调整记忆库或提示文本。MemPro维护一个可运行记忆系统实现的版本树，其中进化代理迭代地选择有前途的版本、诊断重复出现的失败，并通过失败模式引导的编辑-调试细化创建改进的子版本。在LongMemEval、LoCoMo、HotpotQA和NarrativeQA上的实验表明，MemPro在几次迭代内始终优于静态和提示级进化的强基线，随着进化持续改进，并实现了良好的性能-成本权衡。代码可在https://github.com/wanghai673/MemPro获取。

## Abstract
Long-horizon autonomous agents require memory systems to retain historical information, track evolving states, and reuse relevant knowledge beyond finite context windows. Existing agentic memory systems typically follow a memory construction-retrieval (MCR) pipeline, but often adapt mainly the memory bank while keeping the surrounding pipeline fixed after deployment. This fixed-pipeline design struggles to handle heterogeneous task-specific failure modes and can become misaligned with memory banks that evolve in scale and structure over time. To address these limitations, we propose MemPro, a system-level evolution framework that treats the entire MCR pipeline as an evolvable program rather than adapting only the memory bank or prompt text. MemPro maintains a version tree of runnable memory-system implementations, where an Evolving Agent iteratively selects promising versions, diagnoses recurring failures, and creates improved child versions through failure-mode-guided edit-debug refinement. Experiments on LongMemEval, LoCoMo, HotpotQA, and NarrativeQA show that MemPro consistently outperforms strong static and prompt-level evolving baselines within a few iterations, continues to improve with evolution, and achieves a favorable performance-cost trade-off. Code is available at https://github.com/wanghai673/MemPro.

### 1. 论文的核心问题与整体含义（研究动机和背景）

- 长期自主智能体（如基于LLM的助手）需要记忆系统来超越有限上下文窗口，保留历史信息并跟踪演化状态。
- 现有智能体记忆系统普遍采用**记忆构建-检索（MCR）流水线**，但大多仅自适应调整记忆库（memory bank），而部署后流水线中的提示和可执行代码保持固定。
- 这种固定流水线设计面临两大局限：
  1. **任务异构性**：不同长期记忆任务（如时间推理 vs. 多会话推理）具有不同的失败模式，固定策略难以通用。
  2. **记忆-流水线失配**：随着记忆库规模和结构在应用过程中演化，固定流水线可能不再与记忆的组织和使用方式匹配。
- 提示级进化方法（如GEPA、MetaMem）只能修改文本提示，无法改变可执行的流水线逻辑。
- 因此，论文提出**系统级进化**思想：将整个MCR流水线视为一个可进化的程序，不仅更新记忆库或提示，而是同时进化提示和可执行代码。

### 2. 论文提出的方法论：核心思想、关键技术细节

**核心思想：**
- 将MCR流水线（包括记忆构建、检索、整合、反思、回答等步骤）视为一个**可进化程序**，维护一个**版本树**，通过一个**Evolving Agent**迭代地选择、扩展和评估新版本，从而系统级优化整个记忆系统。

**关键技术细节：**
- **版本树 (Version Tree)**: 每个节点代表一个可运行的MCR流水线实现 `F_v` 及其评估日志 `L_v`（包括整体分数、类别分数、父节点、总体评估）。
- **进化过程（每次迭代三步）**：
  1. **Selection**: Evolving Agent 根据所有日志，按高整体分数、可推广的改进方向、频繁失败模式等标准，选择最有前途的节点作为父节点 `v*_ℓ`，并产生诊断分析 `R_ℓ`。
  2. **Expansion**: 从选中的父节点开始，通过**编辑-调试**循环创建新版本。内循环中，Evolving Agent 选择动作 `a_j ∈ {EDIT, DEBUG, TERMINATE}`：
     - **EDIT**: 根据诊断分析修改当前流水线（可改提示和代码）。
     - **DEBUG**: 挑选诊断示例，执行当前流水线获得完整跟踪，更新诊断分析但不改流水线。
     - **TERMINATE**: 停止内循环，当前版本作为新流水线 `F_uℓ`。
  3. **Evaluation**: 在新版本 `F_uℓ` 上对整个训练集 `D_train` 评估，收集跟踪并生成评估日志 `L_uℓ`，作为新节点加入版本树。

- **Evolving Agent**: 使用强大的代码生成模型（如GPT-5.4-medium）作为优化器，通过特定提示引导编辑和调试，避免依赖样本ID或金答案。

### 6. 论文的主要结论与发现

1. **MemPro 在少量迭代内即超越强基线**：仅5次迭代，在LongMemEval和LoCoMo上的平均分即超过所有非MemPro基线，达到SOTA。
2. **持续改进**：随着迭代次数增加（从5到10到15），性能稳定提升，没有过拟合或饱和迹象。
3. **系统级进化优于提示级进化**：移除代码编辑（w/o Code）后性能下降，表明同时进化可执行代码比仅进化提示更重要。
4. **版本树优于链式进化**：移除版本树（退化为链式）导致性能下降，说明维护历史强版本可以从中分支，避免局部最优。
5. **编辑-调试循环有效**：移除内循环的迭代扩展会降低性能，表明一步编辑不够，需要诊断性调试。
6. **良好的性能-成本权衡**：MemPro在比直接上下文方法更少的token消耗下达到最高准确率，且与GAM/GEPA等强基线token成本相近时准确率更高。
7. **检索工具互补**：BM25最基础，嵌入和PAGE-ID提供额外增益，三者配合最佳。

- **视角创新**：首次系统地将智能体记忆流水线本身作为可进化程序，而非仅优化提示或记忆库。
