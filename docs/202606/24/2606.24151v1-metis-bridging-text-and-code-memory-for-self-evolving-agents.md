## 摘要
自我进化智能体通过从过去执行中提炼经验并在未来任务中重复利用这些经验来随时间改进。现有系统将这些经验表示为注入智能体上下文的自然语言文本，或表示为可作为可调用工具暴露的代码。然而，这两种表示之间的选择通常在设计时做出，而非根据经验本身的特征推导得出，导致它们之间的权衡尚不明确。我们提出了首个在相同经验集上隔离文本记忆和代码记忆的受控研究。结果表明，两种形式在构建成本、执行效率和可迁移性方面表现出互补的权衡，因此单独一种表示并不足够。基于这些发现，我们提出了Metis，一个构建在层次化双表示记忆上的自我进化智能体系统。Metis将文本经验组织为执行计划、环境事实和常见陷阱，并选择性地将重复出现的计划结晶为经过验证的可调用工具。这种设计结合了文本记忆的广泛适用性与代码记忆的执行效率，同时仅在重复使用证明合理时才产生工具生成成本。我们在AppWorld（一个具有挑战性的交互智能体基准）上评估了Metis。结果表明，与ReAct相比，Metis将任务准确率提高了多达20.6%，同时将执行成本降低了多达22.8%。与代表性的自我进化智能体系统相比，Metis在准确率、执行效率和记忆构建成本之间始终实现了更好的平衡。

## Abstract
Self-evolving agents improve over time by distilling experience from past executions and reusing it in future tasks. Existing systems represent such experience either as natural-language text injected into the agent context or as code exposed as callable tools. However, the choice between these representations is typically made at design time rather than derived from the characteristics of the experience itself, leaving the trade-offs between them poorly understood. We present the first controlled study that isolates text memory and code memory over an identical set of experiences. Our results show that the two forms exhibit complementary trade-offs in construction cost, execution efficiency, and transferability, such that neither representation alone is sufficient. Guided by these findings, we propose Metis, a self-evolving agent system built on a hierarchical dual-representation memory. Metis organizes textual experience into execution plans, environment facts, and common pitfalls, and selectively crystallizes recurring plans into validated callable tools. This design combines the broad applicability of text memory with the execution efficiency of code memory while incurring tool-generation cost only when justified by repeated reuse. We evaluate Metis on AppWorld, a challenging benchmark for interactive agents. The results show that Metis improves task accuracy by up to 20.6% over ReAct while reducing execution cost by up to 22.8%. Compared with representative self-evolving agent systems, Metis consistently achieves a better balance between accuracy, execution efficiency, and memory-construction cost.

- **研究动机**：大语言模型驱动的智能代理在部署后需要持续适应开放环境，但现有LLM是无状态的，经验仅在有限上下文窗口内保留，任务结束后丢失。自我进化智能体通过从过去执行中提炼经验并重用解决此问题。
- **核心问题**：现有系统将经验表示为**自然语言文本**（注入上下文）或**可执行代码**（包装为工具），但这种表示选择通常是设计时固定而非根据经验特征自适应决定。两类表示的权衡（构建成本、执行效率、可迁移性）尚未被系统理解。
- **关键发现**（通过受控研究）：文本记忆构建成本低、可迁移性好，但执行效率低；代码记忆执行效率高，但构建成本高（约2.5×反思轮数）、可迁移性差（转移时精度下降22.3点 vs 文本仅5.6点）。两者互补，单一表示不足以同时满足低成本、高效和鲁棒转移。

## 2. 论文提出的方法论：核心思想、关键技术细节

- **核心思想**：提出**Metis**，一个分层双表示记忆系统。以文本记忆为低承诺基础层，组织为三类差异化知识：执行计划、环境事实、常见陷阱；仅将重复出现且稳定的执行计划选择性提升为可调用代码工具。
- **关键技术细节**：

  - **差异化文本反思（Differentiated Text Reflection）**：将成功/失败轨迹提炼为三类文本记忆：
    - 执行计划 (plan)：可重用的子过程模板，可被提升为代码。
    - 环境事实 (fact)：环境独立属性与约束。
    - 常见陷阱 (pit)：失败模式，形如(触发条件, 错误, 后果)。
  - **模式感知代码生成（Pattern-Aware Code Generation）**：仅当某个执行计划被选择次数超过阈值θ时才触发工具合成。合成时仅使用计划和相关任务查询（不暴露原始轨迹），生成的工具需通过依赖扫描、编译检查和沙盒验证。
  - **记忆管理器（Memory Manager）**：联合检索文本与代码，先用嵌入检索出候选池，再用LLM选择最相关的文本和工具。选定计划自动引入其关联工具集。
  - **反思框架（Reflection Harness）**：提供渐进式轨迹披露（仅保留头尾、中间截断），可按需扩展细节；强制依赖闭包（确保引入工具及其依赖均可用）；编译门控校验工具可执行性。
- **算法流程**（文字描述）：
  1. 对新任务，记忆管理器选择相关文本记忆和代码工具。
  2. 执行器在注入的记忆下完成任务，生成轨迹。
  3. 若选定计划积累了足够多的历史选择（≥θ），触发代码生成：根据计划、相关任务查询、现有工具库，合成候选工具，通过编译和测试后加入代码库。
  4. 差异化文本反思器观察轨迹及更新后的工具库，创建/合并/更新三类文本记忆。
  5. 所有反思路径在离线阶段运行，不影响在线推理延迟。

## 6. 论文的主要结论与发现

- 文本记忆与代码记忆在构建成本、执行效率、可迁移性上互补，单独使用均不足以同时满足三方面需求。
- Metis通过分层双表示设计，在**准确率**（提升8.3~11.3点）、**执行效率**（token降低13.5%~22.8%）和**记忆成本**（低于SkillX）之间实现更优平衡。
- 选择性代码生成（基于重复门槛）避免了盲目工具化的高成本与过拟合，优于立即编码策略（Eager）或纯文本/纯代码方案。
