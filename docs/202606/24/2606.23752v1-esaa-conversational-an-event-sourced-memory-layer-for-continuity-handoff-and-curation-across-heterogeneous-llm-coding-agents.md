## 摘要
软件开发者日益使用多个LLM编码代理，在Codex、Grok、Claude Code等工具间切换，原因是上下文窗口填满、会话结束或某个代理更适合子任务。然而，每个代理将其对话保存在私有且供应商特定的日志中，导致对话状态漂移：当一个代理接手时，先前另一个代理建立的目标、决策、开放任务和理由无法可靠获取。本文提出\emph{ESAA-Conversational}，这是事件溯源代理架构（ESAA）~\cite{esaa}的领域特化，用于跨异构代理的共享对话记忆。该方法将可见对话视为本地事件存储：钩子和监视器捕获可见轮次，将其标准化为仅追加的\texttt{activity.jsonl}，并确定性投影出诸如\texttt{handoff.md}、\texttt{state.md}、\texttt{decisions.md}和\texttt{tasks.json}等读模型。机械式捕获不需要LLM推理；代理仅在显式策划时使用判断，通过领域命令记录持久决策和对话任务。公开v1.1.0版本实现了PowerShell CLI，包含\texttt{init}、\texttt{enable-hooks}、\texttt{sync}、\texttt{project}、\texttt{verify}、\texttt{context}、\texttt{decide}和\texttt{task}命令；包括\texttt{workspace\_root}隔离和写入路径锁文件；并以包含空公共日志的新建包形式分发。一项具有570个开发实验室事件的自引用案例研究表明，异构代理可以通过共享日志协作，无需直接代理间通道，而公开分发通过排除私有对话历史来保护隐私。

## Abstract
Software developers increasingly work with multiple LLM coding agents, switching among tools such as Codex, Grok, Claude Code, and other assistants as context windows fill, sessions end, or a particular agent becomes better suited to a subtask. Each agent, however, persists its conversation in a private and vendor-specific log. The result is conversational state drift: goals, decisions, open tasks, and rationales established with one agent are not reliably available when another agent takes over. This paper presents \emph{ESAA-Conversational}, a domain specialization of Event-Sourcing Agent Architecture (ESAA)~\cite{esaa} for shared conversational memory across heterogeneous agents. The method treats the visible conversation as a local event store: hooks and watchers capture visible turns, normalize them into an append-only \texttt{activity.jsonl}, and deterministically project read models such as \texttt{handoff.md}, \texttt{state.md}, \texttt{decisions.md}, and \texttt{tasks.json}. Mechanical capture does not require LLM inference; agents use judgment only for explicit curation, recording durable decisions and conversational tasks through domain commands. The public v1.1.0 release implements a PowerShell CLI with \texttt{init}, \texttt{enable-hooks}, \texttt{sync}, \texttt{project}, \texttt{verify}, \texttt{context}, \texttt{decide}, and \texttt{task}; includes \texttt{workspace\_root} isolation and a write-path lockfile; and is distributed as a greenfield package with an empty public log. A self-referential case study with 570 development-lab events shows that heterogeneous agents can collaborate through a shared log without a direct agent-to-agent channel, while the public distribution preserves privacy by excluding the private conversational history.

## 2. 论文提出的方法论

### 2.1 核心思想
- 将可见对话视为**事件存储**：通过钩子（hooks）和监视器（watchers）机械捕获每个对话轮次（turn），标准化后追加到仅追加的日志 `activity.jsonl`。
- 从事件日志**确定性投影**出多个读模型：`handoff.md`（交接契约）、`state.md`（对话状态摘要）、`decisions.md`（持久决策列表）、`tasks.json`（对话任务积压）。
- **分离机械捕获与策划**：捕获不需要LLM推理（零token）；代理只通过领域命令 `decide`、`task` 显式记录持久性决策和任务，才能进入事件日志。
- **逆摄取**：系统不要求代理遵循统一协议，而是通过适配器从原生日志/钩子/轮询中读取事件，归一化为统一事件格式。

### 2.2 关键技术细节
- **事件模型**：
  - 机械事件：`conversation_turn`（含 event_id, ts, actor, agent_id, workspace_root, summary, text）。
  - 策划事件：`decision.recorded`、`task.created`、`task.updated`、`task.closed`（包含决策内容、理由、相关轮次等）。
- **工作空间隔离**：`workspace_root` 作为强制字段，避免项目间日志混淆。
- **并发控制**：写入路径使用锁文件 `run/*.lock` 序列化同步/策划/投影操作。
- **CLI命令**（v1.1.0 PowerShell）：
  - `init`、`enable-hooks`（自动配置钩子）、`sync`（同步一次日志）、`project`（重新投影读模型）、`verify`（校验一致性）、`context`（分页/按代理/主题/时间窗口读取）、`decide`、`task`（创建/更新/关闭）。
- **读取策略**：代理通过 `context` 命令获取聚焦窗口，而非读取完整日志，缓解长上下文退化问题。

## 7. 优点

- **架构清晰**：严格分离证据（机械捕获）与知识（显式策划），避免LLM不必要的推断。
- **逆摄取模式**：不要求代理修改自身协议，通过标准化适配器兼容异构系统，实用性强。
- **零token机械开销**：捕获、归一化、投影、验证均无需LLM推理，大幅降低token消耗。
- **确定性可审计**：事件日志作为不可变事实源，所有读模型可重复重建，支持操作审计。
- **隐私友好设计**：绿场分发、`.gitignore` 排除、限制捕获范围（仅可见文本）等措施。
- **自引用案例**：工具用于自身开发，既验证了功能，又产生了一个真实的多代理工作负载实例，具有示范价值。

## 8. 不足与局限

- **平台与移植性**：仅支持本地Windows/PowerShell 7，无跨平台支持。
- **依赖第三方接口**：钩子和监视器依赖于各代理的日志格式和表面，变动可能导致同步失败。
- **缺少语义能力**：`context --topic` 仅为纯文本匹配，无嵌入或向量检索，无法实现语义搜索。
- **缺乏强审计保证**：无哈希链、签名或外部锚定，不提供司法级可审计性。
- **无法处理内部状态**：仅记录可见对话，不包括内部推理、工具调用等。
- **并发机制简单**：锁文件不如事务日志或单写入队列健壮。
- **无快照机制**：旧事件无法压缩，冷开始时代理需读取大量历史。
- **案例研究局限**：仅一个工作空间、有限代理、自引用（可能引入偏差），未在更大规模或不同团队中验证。
- **隐私靠操作纪律**：用户可能意外提交 `activity.jsonl`，无内置红action或匿名化工具。
- **未支持冷重放**：无法从干净日志确定性重建所有读模型并比对哈希。
