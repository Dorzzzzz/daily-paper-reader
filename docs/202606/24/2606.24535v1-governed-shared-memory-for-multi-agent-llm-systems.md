## 摘要
多智能体LLM环境需要稳健的共享知识管理机制。本文形式化描述了群体记忆问题，并识别了四种基础失效模式：未授权泄露、陈旧传播、矛盾持久化和溯源崩溃。为解决这些问题，我们定义了明确的系统级原语：作用域检索、时间性替代、溯源追踪以及策略驱动的记忆传播。这些原语在MemClaw（一个生产级多租户内存服务）中实现，并通过ArgusFleet（一个可复现的测试框架，覆盖四个治理维度）进行评估。本研究并非基线对比，而是测量一个实际生产服务，强调真实世界的架构洞察与负面结果。关键评估结果：溯源——成功重建100%的深度为四的推导链，每跳延迟在亚秒级别，且写入者身份正确。传播——展现高群体内可见性，零跨群体泄露。在强写入模式下，写入到可见的延迟优化至单次搜索往返。发现的生产架构问题：非对称作用域强制——租户隔离有效，但子租户作用域最初能够通过直接按ID获取代理作用域凭证的请求绕过（在研究中披露并修复）。流水线顺序冲突——虽然矛盾替代对已接受的写入有效，但同步的近重复门可能在异步矛盾检测器评估之前过早拒绝矛盾的写入。结论：仅靠长上下文检索不足以满足生产级多智能体记忆需求。受控共享内存需要明确的系统级抽象，而实时评估对于揭示设计处理无法发现的强制和流水线顺序故障至关重要。

## Abstract
Multi-agent LLM environments require robust mechanisms for shared knowledge management. This paper formalizes the fleet-memory problem and identifies four foundational failure modes: unauthorized leakage, stale propagation, contradiction persistence, and provenance collapse. To address these, we define explicit systems-level primitives: scoped retrieval, temporal supersession, provenance tracking, and policy-governed memory propagation. These primitives are implemented in MemClaw, a production multi-tenant memory service, and evaluated via ArgusFleet, a reproducible harness testing four governance dimensions. Rather than a baseline comparison, this study measures a live production service, emphasizing real-world architectural insights and negative results. Key Evaluation Results Provenance: Successfully reconstructed 100% of depth-four derivation chains with correct writer identity at sub-second per-hop latency. Propagation: Demonstrated high intra-fleet visibility with zero cross-fleet leakage. Under strong write mode, write-to-visible latency was optimized to a single search round-trip. Production Architectural Issues Discovered Asymmetric Scope Enforcement: Tenant isolation held, but sub-tenant scope was initially bypassed on direct GET-by-id requests for agent-scoped credentials (disclosed and remediated during the study). Pipeline Ordering Conflict: While contradiction supersession works for admitted writes, a synchronous near-duplicate gate can prematurely reject contradictory writes before the asynchronous contradiction detector can evaluate them. Conclusion: Long-context retrieval alone is insufficient for production multi-agent memory. Governed shared memory demands explicit systems-level abstractions, and live evaluation is vital to expose enforcement and pipeline-ordering failures missed by design-only treatments.

## 1. 核心问题与整体含义（研究动机和背景）
- **问题**：当前大语言模型（LLM）系统的内存架构多基于单智能体抽象（一人、一对话、一检索流），但在多智能体舰队（fleet）部署中，多个代理共享内存时会出现新的正确性与治理需求：谁可以检索哪些记忆？冲突事实如何解决？知识如何安全跨代理传播？记忆如何溯源？陈旧记忆如何被替代？
- **背景**：现有AI内存系统（如MemGPT、Mem0、Zep等）主要优化检索相关性、对话召回和长上下文压缩，但缺乏作用域访问、时间一致性、溯源和同步等系统级治理原语。论文认为AI内存正从“上下文窗口问题”演变为“分布式系统问题”，需要显式的分布式系统抽象。

## 2. 方法论：核心思想、关键技术细节、公式或算法流程
- **核心思想**：将多智能体共享内存定义为**受控的分布式操作状态**，形式化为五元组 \( F = (A, M, G, P, T) \)，其中A为代理集，M为内存基底，G为治理与策略层，P为溯源元数据，T为时间排序与替代语义。
- **关键技术细节**：
  - **内存写入**：\( w_i = (a_i, c_i, s_i, t_i, p_i) \)（写入代理、内容、作用域、时间、溯源元数据）

  - **作用域**：定义四级作用域（代理本地、团队共享、租户全局、受控限定）
  - **时间性替代**：矛盾写入通过时间顺序和策略规则解决，而非共存
  - **溯源图**：每个记忆存储写入者身份、源系统、派生历史，支持审计追踪
  - **策略驱动的检索**：语义候选生成 → 策略过滤 → 时间性解析 → 溯源富化 → 排序输出
- **算法/流程**：无显式算法伪代码，但通过REST API操作（写入、搜索、按ID获取、再分发）实现原语，并在MemClaw中实例化。

## 3. 实验设计：数据集/场景、基准、对比方法
- **实验环境**：针对MemClaw生产服务（2026年5月30日测量），在一个新开租户内进行。
- **实验场景/探针**：
  - **泄露实验**：4个舰队×6个代理，编写含唯一标记的秘密（舰队作用域和代理作用域），然后用搜索探测，共192个探针（164个预期拒绝，28个预期允许）。
  - **矛盾实验**：100个事实对（来自20个主体-谓词模板），每个事实对包含顺序写入和并发写入，共400次写入，检测替代关系。
  - **溯源实验**：50条深度为4的派生链（共200次写入），每个链对应一个操作事件（观测→假设→缓解→验证），追踪后向链。
  - **传播实验**：两个阶段：速率阶段（40个舰队作用域事实，200个探针）检测可见性和跨舰队泄露；窗口阶段（8个专用事实，密集轮询）测量写入到可见的时间。

## 6. 主要结论与发现
- **正面结果**：
  - 溯源完全重建（50/50链，每跳延迟p50=291ms）
  - 传播中舰队内可见性97.5%，零跨舰队泄露
  - 强写入模式下写入到可见延迟约0.83秒（一个搜索往返），一致性成本在写入端支付
  - 矛盾检测在写入双方都被接受时100%正确（90/90）
- **生产中发现的问题**：
  - **作用域强制不对称**：租户隔离有效，但子租户作用域在直接按ID获取时被绕过（代理ID被忽略），已披露并修复
  - **去重门"饿死"矛盾检测**：同步近重复门（409错误）在异步矛盾检测器之前拒绝近似文本的矛盾写入，导致矛盾检测输入缺失
  - **跨代理传播权限过于粗放**：重分发端点要求信任等级≥3，将群体内传播与特权迁移混淆

## 7. 优点：方法或实验设计上的亮点
- **形式化框架**：给出清晰的形式化定义（F=(A,M,G,P,T)、写入/检索操作、不变式Inv-Scope），使故障模式可预测、可验证。
- **真实世界测量**：在生产服务上实时评估，暴露了设计层面无法发现的强制与流水线问题。
- **负面结果透明报告**：主动披露自身服务中的漏洞（GET-by-id子租户绕过），并提交流追溯，体现了科学诚信。

- **注重偏差分离**：通过分离速率阶段与窗口阶段，避免调度干扰对传播延迟的测量。
