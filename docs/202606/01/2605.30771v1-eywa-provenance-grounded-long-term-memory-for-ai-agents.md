## 摘要
跨会话持久化的AI智能体需要可检索、可审计、可更新、可擦除的记忆。现有记忆系统常将源证据、提取事实、检索上下文与回答策略折叠为一条不透明的提示路径，导致故障难以诊断：错误答案可能源于缺失证据、未经支持的提取、过期状态、检索损失或答案模型行为。我们提出Eywa，一种以证据先于信念为核心的基于来源的记忆架构。Eywa在推导规范事实前先存储不可变源证据，通过类型化信号和源支持验证提取的记忆，并通过确定性多路径读取路径（检索内部零LLM调用）检索有界记忆上下文。检索得到的上下文与回答指令分开返回，使同一记忆基底可跨前沿模型、预算模型和本地答案模型进行评估。在冻结的、制品记录的检索配置下，Eywa在LoCoMo C1-C4数据集上结合Claude Sonnet 4.6的写入和问答角色达到90.19%的评判准确率；在LongMemEval-S上达到88.2%的检索充分性准确率；在包含700个问题的技术记忆压力基准测试BEAM上达到81.45%的平均nugget得分和85.29%的pass@score≥0.5。完整的每问题制品（包括问题、标准答案、模型答案、检索上下文和标签）发布于https://eywa.to/research。

## Abstract
AI agents that persist across sessions need memory they can retrieve, audit, update, and erase. Existing memory systems often collapse source evidence, extracted facts, retrieved context, and answer policy into one opaque prompt path, making failures difficult to diagnose: a wrong answer may come from missing evidence, unsupported extraction, stale state, retrieval loss, or answer-model behavior. We present Eywa, a provenance-grounded memory architecture built around evidence before belief. Eywa stores immutable source evidence before deriving canonical facts, validates extracted memories against typed signals and source support, and retrieves bounded memory context through a deterministic multi-route read path with zero LLM calls inside retrieval. Retrieved context is returned separately from answer instructions, allowing the same memory substrate to be evaluated across frontier, budget, and local answer models. Under a frozen, artifact-recorded retrieval configuration, Eywa reaches 90.19% judge accuracy on the LoCoMo C1-C4 split with Claude Sonnet 4.6 write and QA roles. On LongMemEval-S, it reaches 88.2% retrieval-sufficiency accuracy. On BEAM, a 700-question technical-memory stress benchmark, it reaches 81.45% mean nugget score and 85.29% pass@score >= 0.5. Full per-question artifacts, including questions, gold answers, model answers, retrieved context, and labels, are published at https://eywa.to/research.

- **整体含义**：提出Eywa架构，旨在构建一个**可审计、可调试、可擦除**的长期记忆系统，实现**证据先于信念**的原则，将记忆推理过程分解为写路径（证据捕获与验证）、读路径（确定性检索）和答案策略，使错误可归因、可修复。

### 2. 论文提出的方法论：核心思想、关键技术细节、算法流程

- **核心思想**：**证据先于信念**。将不可变的源证据作为权威基底，再从证据中推导出可修订的规范信念（事实）。检索路径不依赖LLM，保持确定性，且将检索出的上下文与答案指令显式分离。
- **关键技术细节**：
  - **写路径（Write Path）**：
    - **Tier 0（不可变捕获）**：将所有用户交互存储为不可变证据行，同时使用规则/信号检测器（无LLM调用）抽取硬锚点（日期、实体、金额、版本号等）。
    - **Tier 1（验证提取）**：LLM提取候选事实，通过验证函数 `V(f̂, E, S)` 检查：
      - `V_support`: 与源文本的词汇/模糊重叠
      - `V_hard`: 确定性硬锚点匹配
      - `V_subject`: 主体出现在支持窗口
      - `V_act`: 保留否定/不确定性信号
    - 通过验证的事实成为规范事实，并保留指向原始证据行的溯源链接 ℓ(f) → e。
  - **读路径（Read Path）**：**零LLM调用**的确定性多路由检索。
    - 查询规划器（手写规则表）分析问题形状，分配通道权重。
    - 活跃通道包括：向量相似度（cosine）、关键词（BM25）、时间范围、实体/图遍历、原始事件救援。
    - 融合使用加权RRF（Reciprocal Rank Fusion）融合各通道排序。
    - 后处理：人员降级（非目标实体×0.05）、保留下限（保护已验证候选不被掩埋）。
    - 上下文打包：按实体分组后按排序填充到token预算内。
  - **答案策略分离**：检索器返回的`ReadResult`包含独立的`context`和`answer_instructions`，支持严格/平衡/高级三种模式。
- **算法流程**（文字说明）：
  1. 输入用户消息 → 存储为不可变证据 → 检测信号。
  2. LLM提取候选事实 → 验证函数过滤 → 写入规范事实（带溯源链接）。
  3. 新查询到来 → 确定性规划器分析 → 多通道检索 → RRF融合 → 后处理排序 → 上下文打包。
  4. 将上下文与答案指令发送给下游答案模型 → 答案模型输出回答。

### 7. 优点：方法或实验设计上的亮点

- **分层架构清晰**：证据 → 信号 → 信念 → 检索 → 答案策略，每一层职责明确，支持独立优化和审计。
