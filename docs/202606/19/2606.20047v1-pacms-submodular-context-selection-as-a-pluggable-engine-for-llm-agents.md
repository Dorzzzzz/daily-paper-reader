## 摘要
会话型和使用工具的LLM代理在一个从多个方向同时填充的上下文窗口中运行。随着会话的进行，代理会累积用户和助手的轮次、从持久记忆存储中提取的条目，以及通常最大的部分——工具调用的逐字输出，如文件读取、搜索结果和API响应。一旦累积的上下文超过模型的token预算，框架必须决定保留什么。当前的主要机制是最近截断，有时辅以周期性摘要。这是主题盲目的：会话早期建立的事实仅仅因为陈旧而被丢弃，即使当前用户查询正是关于该事实；反之，冗长但无关的近期材料却被保留。那些必须在多轮中回忆信息的代理——记忆的典型情况——正是最近截断失败的地方。现有的替代方案位于代理的组装步骤之外。检索增强生成将外部文档提取到提示中，但不仲裁代理已经存在的池化上下文。上下文压缩方法通过重写或修剪文本来减少token数量，但操作是查询盲目的且有损的。两者都没有将记忆条目、会话轮次和工具输出视为一个单一的候选池，以便在提示组装时通过相关性进行选择。

## Abstract
Conversational and tool-using LLM agents operate over a context window that fills from several directions simultaneously. As a session proceeds, the agent accumulates user and assistant turns, entries drawn from a persistent memory store, and often largest of all, the verbatim outputs of tool calls such as file reads, search results, and API responses. Once the cumulative context exceeds the model's token budget, the framework must decide what to keep.   The prevailing mechanism is recency truncation, sometimes paired with periodic summarization. This is topic-blind: a fact established early in a session is discarded simply because it is old, even when the current user query is about exactly that fact; conversely, verbose but irrelevant recent material is retained. Agents that must recall information across many turns, the defining case for memory, are precisely where recency truncation fails.   Existing alternatives sit outside the agent's assembly step. Retrieval augmented generation fetches external documents into the prompt but does not arbitrate the agent's \emph{already-present} pooled context. Context-compression methods reduce token count by rewriting or pruning text, but operate query-blind and lossily. Neither treats memory entries, conversation turns, and tool outputs as a single candidate pool to be selected from by relevance at the moment the prompt is assembled.

# 论文总结：PACMS: 作为LLM代理可插拔引擎的子模上下文选择

## 1. 核心问题与整体含义

**研究动机：** 在长时间运行的LLM代理（如聊天助手、工具使用代理）中，上下文窗口会因多轮对话、持久记忆、工具调用输出等快速被填满。当累积的token数超过模型预算时，现有默认策略是“最近截断”（recency truncation）——保留最近的、丢弃最早的内容，这是一种话题盲目的方法：它会丢弃早期建立但当前查询相关的事实，同时保留最近但无关的噪声。这种机制在需要跨多轮回忆信息的场景（即内存典型场景）中表现严重不足。

**整体含义：** 论文提出将代理上下文组装问题重新定义为预算约束下的子模选择问题，并设计了一个名为PACMS的可插拔上下文引擎，在提示组装时刻根据查询相关性从记忆、对话轮次、工具输出构成的统一候选池中选取子集，从而提升长对话中的信息保留和下游问答准确性。

## 2. 方法论：核心思想与关键技术细节

### 2.1 核心思想
将代理上下文中所有候选信息单元（记忆条目、对话轮次、工具输出）视为一个池 \( C = \{c_1, \dots, c_n\} \)，给定最新查询 \( q \) 和 token 预算 \( B \)，选择一个子集 \( S \subseteq C \) 最大化覆盖相关性，同时最小化冗余，并强制包含必需集合 \( M \)。

### 2.2 技术细节
- **相关性定义：** \( \text{rel}(i, q) = \max(0, \cos(e_i, e_q)) \)，其中 \( e \) 是嵌入向量。
- **覆盖权重：** \( w_{ij} = \text{rel}(i, q) \cdot \max(0, \cos(e_i, e_j)) \)，衡量候选 \( j \) 对候选 \( i \) 的覆盖程度，且被目标项的相关性加权。
- **目标函数：** 最大化 \( F(S) = \sum_{i} \max_{j \in S} w_{ij} \)，这是一个单调子模的设施选址（facility-location）目标。
- **约束条件：** 总token数不超过预算 \( B \)，且必须包含 \( M \)。
- **求解算法：** 使用CELF lazy-greedy算法（一种成本感知的贪心算法），具有常数因子近似保证。

### 2.3 与MMR的关键差异
- **范围：** MMR只考虑已选集内的冗余惩罚；PACMS对所有候选池求和，奖励覆盖池中未被表示的区域。
- **相关性加权：** PACMS中覆盖权重乘以目标项的相关性，只计算对相关区域的覆盖；MMR的惩罚是纯相似度，与查询相关性无关。
- **保证：** PACMS的目标是单调子模函数，有贪心近似保证；MMR是成对惩罚启发式，无类似边界。

### 2.4 系统集成
- 实现为OpenClaw代理框架的可插拔上下文引擎（context-engine），接管`assemble()`步骤，但将压缩（compaction）委托给运行时。
- 使用FastAPI本地服务（端口8077）暴露`/select`和`/select_debug`端点。
- 嵌入缓存保持热状态（使用本地Ollama的nomic-embed-text模型）。
- 支持五种策略切换：PACMS、top-k、last-k（最近截断）、MMR、RAG。
- 服务不可用时优雅降级为最近截断。

## 3. 实验设计

### 3.1 数据集和基准
- **数据集：** LongMemEval，这是一个多会话聊天历史基准，用于测试长时间记忆。涵盖6种问题类型（单会话用户、单会话助手、单会话偏好、时间推理、知识更新、多会话）。
- **采样：** 随机抽取100个问题（统一覆盖所有类型），用于召回率和QA评估。
- **嵌入：** 所有选择器共享本地Ollama的nomic-embed-text嵌入。

### 3.2 对比方法
- **top-k：** 基于余弦相关性的前k个。
- **lc-mmr：** LangChain实现的MMR（默认λ=0.5），通过遍历其输出排名实现预算约束。
- **last-k：** 最近截断，查询盲目的。

### 3.3 评估指标
- **证据轮次召回率（Evidence-round recall）：** \( |S \cap E| / |E| \)，其中E是标注的证据轮次。
- **端到端问答准确率（QA accuracy）：** 读者模型根据所选上下文回答，由GPT-4o-mini裁判使用LongMemEval的CORRECT/WRONG提示评分。

### 3.4 实验设置
- **召回率实验：** 注入模板化改写（冗余级别R=0,2,4,8）的填充轮次，并扫描三个预算水平（20%, 45%, 70%）。
- **QA实验：** 固定冗余R=2，预算45%，使用两个读者：GPT-5-mini（reasoning_effort=minimal）和GPT-5.4-mini（reasoning_effort=low）。

### 5.2 充分性与客观性

## 6. 主要结论与发现

### 6.1 召回率方面
- 在20%低预算下，top-k优于PACMS（纯相关排名在小预算下更强）。
- 在45%和70%预算下，PACMS和MMR通过抑制冗余超越top-k，且随着冗余增加优势扩大。
- PACMS和MMR在召回率上非常接近（差异在几个百分点内），未声称召回率优势。

### 6.2 QA准确率方面（核心发现）
- PACMS在两个读者下均领先：GPT-5-mini 52.0%，GPT-5.4-mini 68.0%。
- 与MMR相比：尽管召回率相近（0.909 vs 0.895），但PACMS在QA上领先+8至+12个百分点。
- 与top-k相比：PACMS在召回率落后（0.909 vs 0.933）的情况下，仍能在QA上领先+2至+4个百分点。
- 结论：**设施选址覆盖产生的提示比成对多样化（MMR）或纯相关排名（top-k）更易于下游读者提取有用信息。** 召回率和QA准确率之间的分歧是论文的核心发现。
- 最近截断（last-k）在更强读者下仍然崩溃，无法从更强的推理能力中受益。

### 6.3 排序
在两个读者下，QA准确率排序一致：**PACMS > top-k > MMR ≥ last-k**。

## 7. 优点

- **问题定义新颖：** 将代理上下文组装形式化为预算约束下的子模选择问题，统一处理异构候选源（记忆、对话、工具输出），而非分别截断或压缩。
- **可插拔系统架构：** 作为框架无关的引擎插件，允许A/B测试不同选择策略，且软降级保证可靠性。
- **理论保证：** 使用单调子模设施选址目标，CELF贪心提供常数因子近似保证，而MMR是启发式无保证。
- **实验结果有意义：** 揭示了召回率与QA准确率的分歧——PACMS虽在召回率上不占优，但在实际任务准确率上显著领先，表明现有基线可能优化了错误指标。
- **交互式演示：** 提供了实时keep/drop可视化、可调整预算和策略切换，有助于理解选择行为。
- **开源可复现：** 代码、评估工具和插件均已开源。

## 8. 不足与局限

- **实验规模有限：** 仅使用100个问题，冗余注入是模板化的而非真实用户数据，可能缺乏多样性。QA实验仅一个预算/冗余组合，未探索不同条件下的鲁棒性。

- **仅一个数据集：** 仅在LongMemEval上评估，代理记忆基准还有其他（如LoCoMo、MemoryAgentBench），未覆盖。
- **资源信息不完整：** 未披露GPU型号、训练细节（无训练）、推理具体耗时等。
