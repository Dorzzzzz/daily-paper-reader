## 摘要
个人助手记忆的核心作用是将存储的信息和先前的交互转化为面向未来的辅助。在日常使用中，有用的线索来自智能体观察到的事物以及用户与之互动的方式，而智能体必须将这些线索从当前请求延续到类似的未来任务中。现有的记忆基准通常孤立地测试对话回忆或任务改进，使得从流式观察到后续辅助的轨迹在很大程度上未经测试。我们引入了StreamMemBench，一个流式基准，它围绕来自EgoLife自我中心流的每个证据锚点构建了一个两步任务序列。初始任务测试证据的使用，而后续任务测试反馈和交互经验是否被重用。四个指标评估了证据回忆、初始证据使用、反馈整合和后续重用。在两个骨干网络上对八个记忆系统进行的实验表明，当前的系统通常无法使用观察到的证据，也无法将反馈转化为可靠的后续行为，即使证据被存储或反馈被本地整合。StreamMemBench公开可用，网址为https://github.com/landian60/StreamMemBench。

## Abstract
A central role of personal-agent memory is to turn stored information and prior interactions into future-oriented assistance. In daily use, useful cues come from what the agent observes and how the user interacts with the agent, and the agent must carry them forward from the current request to similar future tasks. Existing memory benchmarks usually test dialogue recall or task improvement in isolation, leaving the trajectory from streaming observations to later assistance largely untested. We introduce StreamMemBench, a streaming benchmark that constructs a two-step task sequence around each evidence anchor from EgoLife egocentric streams. The initial task tests evidence use, while the follow-up task tests whether feedback and interaction experience are reused. Four metrics diagnose evidence recall, initial evidence use, feedback incorporation, and follow-up reuse. Experiments with eight memory systems across two backbones show that current systems often fail to use observed evidence or turn feedback into reliable follow-up behavior, even when evidence is stored or feedback is incorporated locally. StreamMemBench is publicly available at https://github.com/landian60/StreamMemBench.

## 1. 论文的核心问题与整体含义（研究动机和背景）

- **核心问题**：现有个人代理（personal agent）的记忆基准通常孤立地测试对话回忆或任务改进，忽略了从**流式观察**（egocentric streams）到**后续辅助**的完整轨迹。代理需要从持续的自我中心观察和交互中识别用户相关信息，存储并在当前任务中使用，同时将用户反馈整合后用于未来相似任务。然而，当前系统即使存储了信息，也常无法在需要时提供有效辅助。
- **研究动机**：为了全面评估代理记忆的“未来导向辅助”能力，需要测试两个关键层次：（1）**证据使用（evidence use）**：代理能否利用过去的观察作为上下文证据支持当前用户任务；（2）**经验重用（experience reuse）**：代理能否将包含用户反馈的交互经验泛化到相似场景。
- **整体含义**：该论文通过构建流式基准 StreamMemBench，填补了现有基准在**证据来源**（真实egocentric流）、**用户参与**（真实反馈）、**经验重用**（跨任务）和**可追溯性**（从源头到行为）方面的空白，揭示了当前记忆系统在流式场景中的根本性缺陷。

## 2. 论文提出的方法论：核心思想、关键技术细节

### 核心思想
围绕 **EgoLife** 自我中心数据流中的“证据锚点”（evidence anchors），构建两个步骤的一系列任务：
- **初始任务**：测试代理是否使用了观察到的证据。
- **后续任务**：测试代理是否重用了先前的交互经验（包括用户反馈）。

### 关键技术细节
1. **基准构建阶段**：
   - **证据锚点代理（Aanchor）**：将EgoLife的5分钟片段转化为三元组 (ak, T1, T2)，其中 ak 是用户特定证据，T1 是初始任务查询，T2 是后续任务查询。证据必须能在未来个人辅助请求中发挥作用（如长期偏好、计划、承诺、能力等）。
   - **审核代理（Areview）**：检查每个候选三元组是否满足：不泄露证据（Leak=0）、必须依赖证据才能正确回答（Need=1）、查询自然（Natural=1），且两个查询基于相同锚点但不同应用场景。

2. **评估阶段**：对每个锚点执行以下轨迹（τk）：
   - 代理按时间顺序摄入数据流至锚点所在片段。
   - 接收初始任务 T1 → 生成响应 R1。
   - 用户模拟器 Auser 提供反馈 F（确认或修正）和任务分数。
   - 若反馈为修正，代理生成修正后响应 RF → 记录反馈部分（FI）。
   - 将完成交互 (T1, R1, F, RF) 提交给代理的记忆系统（通过其记忆形成接口）。
   - 接收后续任务 T2 → 生成响应 R2 → 评分 FUR。

3. **四个评估指标**：
   - **Fidelity（Fid）**：在任务序列前，检查代理暴露的记忆增量（ΔMi）是否包含锚点证据（语义匹配，无需字面一致）。
   - **Initial Evidence Use（IEU）**：初始响应是否正确使用了锚点证据。
   - **Feedback Incorporation（FI）**：在修正反馈场景中，修正后响应是否整合了反馈。
   - **Follow-up Reuse（FUR）**：后续响应是否重用了锚点证据或反馈经验。

   所有评分由 Auser 或 Aeval 基于 LLM 判断，三次投票决定。

## 3. 实验设计

### 数据集与场景
- **数据来源**：EgoLife 数据集：来自 6 名参与者的 7 天连续自我中心记录。
- **基准处理**：将原始数据分割为 **3,347 个 5 分钟片段**，每个片段约 200 个带时间戳的观察（自我中心叙述或对话转录）。
- **证据锚点**：从中提取 **8,107 个证据锚点**，每个锚点生成 2 个任务查询，共计 **16,214 个查询**，覆盖任务分配、活动规划、社交沟通、计划评估、礼品建议等自然辅助类型。
- **评估轨迹**：每个轨迹摄入流前缀（到锚点所在片段为止），然后执行两步任务。

### 对比方法（8个记忆系统，2个骨干网络）
- **检索基线**：
  - **RAG raw**：以原始片段存储流数据，查询时检索最相关片段。
  - **RAG ext**：先用LLM提取结构化事实，再对事实进行检索。
- **主动管理记忆系统**：
  - **Mem0**：存储单个事实，新信息冲突时覆盖。
  - **EverMemOS**：保存事件描述、个人特征、情境上下文等多层结构。
  - **A-Mem**：基本保留原内容，但链接相关观察，不重写。
  - **MemOS**：多层信息合并，每层按计划从下层重建。
  - **MemoryOS**：按时效性分为短、中、长期存储，不同刷新率。
  - **MemSkill**：存储从过去交互中提取的可复用技能（程序性记忆），而非事实。
- **骨干网络**：DeepSeek-V4-Flash 和 Gemini-3-Flash（解码确定性温度=0，固定种子）。
- **评估模型**：Aanchor、Areview、Aeval、Auser 均使用 DeepSeek-V4-Pro。

### 设置细节
- 嵌入检索使用 **bge-m3**，top-k=10。
- 每个锚点运行三次，多数投票决定。
- 人工审计（N=100）显示 T1 自然度 90.0%，F 自然度 93.5%，Cohen's κ 分别为 0.336 和 0.424。

## 6. 论文的主要结论与发现

### 核心发现
1. **存储不等于使用**：即使系统完美保留证据（Fidelity 高），初始证据使用（IEU）和后续重用（FUR）仍可能很低。例如 A-Mem 和 MemoryOS 的 Fidelity 100%，但 IEU 仅约 30% 左右。
2. **反馈可局部整合，但难长期留存**：FI 分数普遍高于 FUR，说明系统能即时利用修正反馈，但无法可靠地将其转化为后续任务中的行为。
3. **时序漂移**：随着流增长（早期→晚期锚点），RAG raw 的 IEU 下降，而 FI 和 FUR 上升；MemSkill 的 Fidelity 晚期下降；Mem0 的 FUR 晚期减弱。单一聚合指标会掩盖这些变化。
4. **生命周期失败模式**：不同系统的失败点不同。RAG raw、A-Mem、MemoryOS 等“高保真”系统主要失败在初始使用或后续重用；Mem0 和 EverMemOS 有较高比例的形成失败（证据未存入）；MemOS 的失败以“修正整合失败”为主（高 FI 但极低 FUR）。
5. **效率与效果不协同**：紧凑存储器（如 EverMemOS、Mem0）存储小但 token 成本不一定低；A-Mem 和 MemoryOS 存储大、token 成本高，任务表现并非最好。

### 总结结论
当前记忆系统在流式未来导向辅助方面仍然有限，即使能存储信息或即时响应反馈，也无法可靠地用于后续任务。StreamMemBench 提供了诊断性评估，有助于定位从证据保留到任务行为链条中的断裂点。

## 7. 优点

1. **创新的流式评估范式**：首次从“观察→初始任务→反馈→后续任务”的完整流式轨迹评估代理记忆，而非仅孤立测试对话回忆或任务改进。
2. **证据锚点可追溯**：每段证据都关联到原始流中的具体观察，可精确追踪从证据出现到最终使用或丢失的完整路径。
3. **四维指标诊断细粒度**：Fidelity、IEU、FI、FUR 分别诊断不同阶段，帮助定位缺陷是在存储、初始使用、反馈整合还是后续重用环节。
4. **真实世界数据基础**：使用 EgoLife 自我中心数据（连续7天日常生活记录），比合成对话更贴近真实代理应用场景。
5. **开源且可控**：代码和数据集公开，使用确定性解码，便于复现和对比。
6. **多维度成本分析**：同时报告存储、延迟和 token 成本，揭示效率与效果之间的权衡。

## 8. 不足与局限

1. **系统覆盖有限**：仅评估 8 种代表系统，未涵盖大量商业系统（如 ChatGPT 记忆、Gemini 记忆、Claude 记忆）或更多研究变体；骨干网络只有两个。
2. **用户反馈为模拟**：反馈由 LLM 模拟生成，可能无法完全反映真实用户的语言习惯、情绪或交互模式。人工审计虽评估自然度，但样本量有限（N=100）。
3. **评估依赖 LLM 判断**：Fidelity、IEU、FI、FUR 均由 LLM 代理评判，尽管三次投票，但 LLM 自身可能存在系统性偏见（如偏好冗长回答、特定风格）。
4. **数据集偏倚**：EgoLife 仅 6 个参与者，场景集中于日常生活（如烹饪、外出、会议等），可能无法代表所有个人助手使用场景（如专业领域、多语言）。
5. **未考虑跨会话长期演变**：每个轨迹只处理单个锚点对应的上游流，未评估在更长时间内（多天、多锚点）记忆系统的持续更新和泛化能力。
6. **隐私风险**：基准使用自我中心记录包含敏感信息，虽声明仅用于学术，但可能鼓励在未经充分保护下部署类似存储系统。
7. **缺乏对内部机制的分析**：评估是黑盒的（仅看文本响应和暴露的记忆增量），未深入分析系统内部如何表示、更新和检索信息，导致“成功率低”的具体原因难以完全归因。
8. **消融实验不足**：未对基准自身的参数（如片段长度、证据类型、任务模式）进行系统的消融研究，以验证设计选择的有效性。
