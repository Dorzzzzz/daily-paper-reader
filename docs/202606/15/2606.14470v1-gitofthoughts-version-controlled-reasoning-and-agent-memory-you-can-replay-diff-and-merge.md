## 摘要
大型语言模型（LLM）的推理是短暂的：思维链随着上下文窗口消失，被剪枝的搜索分支没有留下记录，而记忆缓冲区无法进行比较、合并或审计。其他所有复杂的软件过程（代码、基础设施、数据、实验）都进行了版本控制，但推理没有。我们提出了GitOfThoughts，它将智能体的推理树存储为git仓库：每个评分的想法是一个提交，分数是笔记，结果是标签，检索是智能体自身历史中的“git log”。这使得推理可以在近乎零工程成本的情况下实现可重放、可审计和跨智能体可合并。然后我们提出了一个更困难的问题：记忆在任何基质上是否真的能提高准确性？在五种基质（无、markdown、向量、图、git）上，两个基准测试，两种模型规模，以及预注册的复制中，对于新问题的答案是否定的。没有一种记忆格式能可靠地帮助，而且一个有希望的早期结果在其自身的预注册复制中崩溃了。记忆仅在我们所谓的可复制性阈值之上才有价值：当检索到的案例是当前问题的近似副本（相似度>~0.8）时，准确性急剧提升；低于该阈值则无效。这种提升是答案检索带来的，而非方法迁移：一个4.5倍大的模型使近似副本的收益加倍，但仍然无法从解决示例中提取可迁移的方法。我们发现的唯一通用杠杆是测试时采样。因此，基于git作为基质的价值在于在准确性持平的情况下实现可审计性、溯源性和可合并性。我们记录了一个被撤回的结果和一个被证伪的假设，以展示我们所遵循的评估标准。

## Abstract
Large language model (LLM) reasoning is ephemeral: chains of thought vanish with the context window, pruned search branches leave no record, and memory buffers cannot be diffed, merged, or audited. Every other complex software process (code, infrastructure, data, experiments) is version-controlled; reasoning is not. We introduce GitOfThoughts, which stores an agent's reasoning tree as a git repository: every scored thought is a commit, scores are notes, outcomes are tags, and retrieval is "git log" over the agent's own history. This makes reasoning replayable, auditable, and mergeable across agents at near-zero engineering cost.   We then ask the harder question: does memory, in any substrate, actually improve accuracy? Across five substrates (none, markdown, vector, graph, git), two benchmarks, two model scales, and pre-registered replications, the answer for novel problems is no. No memory format reliably helps, and a promising early result collapsed under its own pre-registered replication. Memory pays only above what we call the copyability threshold: when the retrieved case is a near-duplicate of the current problem (similarity >~ 0.8), accuracy jumps sharply; below it, nothing. The gain is answer retrieval, not method transfer: a 4.5x larger model doubles the near-duplicate payoff yet still cannot extract a transferable method from a worked example. The only general lever we find is test-time sampling. The case for git-as-substrate is therefore auditability, provenance, and mergeability at accuracy parity. We document a retracted result and a refuted hypothesis to model the evaluation standard we hold ourselves to.

## 1. 核心问题与整体含义（研究动机与背景）

- **研究动机**：当前大语言模型（LLM）的推理过程是短暂的、不可审计的。思维链随上下文窗口消失，被剪枝的搜索分支没有记录，记忆缓冲区无法进行 diff（比较）、merge（合并）或 audit（审计）。相比之下，其他软件过程（代码、基础设施、数据、实验）都已实现版本控制，而推理仍是最后一个未被版本化的过程。
- **核心问题**：能否用 git 作为推理的版本控制基质？跨问题记忆是否能真正提高模型在新问题上的准确性？
- **整体含义**：论文旨在证明 git 作为推理记忆基质的工程价值（可审计性、可重放、可合并、可 diff），同时通过严格实验揭示记忆对准确性的真实影响——只有在检索案例与当前问题高度相似（近似副本）时才有帮助，否则任何格式的记忆都无效。

## 2. 方法论：核心思想、关键技术细节

- **核心思想**：将智能体的推理树建模为 git 仓库。每个评分思考节点是一个 git commit，分数用 git notes 存储，验证结果用 git tags 标记，检索操作通过 `git log`、`git grep`、`git -S`（pickaxe）等原生命令完成。
- **关键技术细节**：
  - **映射关系**：推理概念 ↔ git 原语（表1）：节点 → commit，父节点 → parent edge，分支 → branch，评分 → git notes，验证结果 → tag（success_* / failed_*），检索 → git log --grep / git log -S，合并 → git fetch + git merge，重现 → git bundle，签名 → git commit -S。
  - **推理管道**：外层为深度1、分支因子4的思维树；内层为 ReAct 循环（最多3步），配备计算器、sympy 求解器、pulp 线性规划器。评分公式：s = 0.6 * s_local + 0.4 * s_cross；最佳子节点被验证并标记为 success/best 或 failed；每个问题最多允许一次重扩。
  - **记忆检索**：使用标准 git 命令——关键词检索（--grep）、内容检索（-S pickaxe）、结果过滤（git tag -l 'success_*'）、边界检索（git log master..memory），并按置信度加权排序：ρ = 0.7 * s_comb + 0.2 * tag + 0.1 * recency。
  - **记忆写入**：每个节点写入四个文件（thought.md, scores.json, trace.jsonl, metadata.json），提交到仓库，附加 git note 作为评分，标签作为结果。
  - **可审计性**：可重放（`git checkout <SHA>`），可 diff（`git diff success_X failed_Y -- thought.md` 得到推理文本的行级差异），可合并（`git fetch peer && git merge peer/memory` 实现跨智能体记忆同步并暴露冲突），可搜索（10000个会话即10000个仓库，用 shell 循环查询）。

## 6. 主要结论与发现

1. **假设 H-memory 在新问题上被拒绝**：五种记忆基质（none, markdown, git, vector, graph）在 GPQA 和 MATH-500 上均不能可靠改善新问题的准确率（所有 CI 包含零，且大样本 n=500 时仍不显著）。唯一的例外是自一致性（+3.4 pp*）——这是测试时采样，而非记忆基质。
2. **复制性阈值**：记忆仅在检索案例与当前问题高度相似（余弦相似度 > 0.8，接近重复或同义句）时才有帮助，准确率提升 +12 ~ +13.5 pp（7B）或 +22.5 ~ +28.5 pp（32B）。增益来自答案检索，而非方法迁移。
3. **方法迁移失败**：即使使用 4.5 倍大的模型（32B），方法迁移臂仍然为 null（Δ = -3.6 至 -4.1 pp），证明模型无法从工作示例中提取可迁移的解题方法；规模仅增强了复制效应，而未解锁方法论迁移。
4. **唯一通用杠杆**：测试时采样（自一致性，n=500 时 +3.4 pp*）和基模型强度；记忆基质的价值不在于提高新问题准确率，而在于提供审计性、溯源、diff、合并和重现性，且 accuracy parity 与最优后端。
5. **系统标题的混淆**：GitOfThoughts 在 GPQA 上达到 47%（vs. vanilla 33%），但该增益主要来自 MCQ-aware 扩展和更大计算预算（600s vs. 60s），而非 git 或记忆。论文明确标记为混淆因素。

## 7. 优点

- **方法创新**：首次将 LLM 推理树作为 git 仓库，实现版本控制，使推理可审计、可重现、可合并——这是完整操作层的基础设施，而非简单日志。
- **严格实验**：广泛使用 pre-registered 假设（32B 实验）、配对 bootstrap CI、公平性审计、可重现性验证；主动报告并撤回一个早期趋势（git +15pp 在更大样本中未复制），体现学术诚信。
- **多层次消融**：控制记忆后端的解码路径（避免写入差异）、内容类型（答案 vs. 工作示例 vs. 无答案 lesson）、学科过滤、静态 few-shot、自一致性等，准确分离因果关系。
- **清晰的边界条件**：发现复制性阈值（τ ~ 0.8），将记忆有效性与任务重复性挂钩，有力地解释了先前空结果。
- **工程价值明确**：git 提供 diff、merge、blame、bisect、CI 等成熟工具链，比自定义日志更健壮，且成本极低（写 ~15ms，读 ~48ms）。

## 8. 不足与局限

- **实验覆盖不足**：
  - 未测试前沿模型（如 GPT-4、Claude 等）——论文承认“是否较低阈值”是开放问题。
  - 记忆类型局限于一跳蒸馏的 lessons 和工作示例检索；未测试丰富的情节记忆（完整推理轨迹）。
  - 多智能体设置未验证（仅演示了合并功能，但准确性分析 pending）。
  - ScienceWorld 基底模型太弱（~12%），跨回合实验无效。
- **计算预算不匹配**：系统标题（47% vs. 33%）各臂 wall-clock 不同（60s / 180s / 600s），是混淆因素，不能确定方法本身增益。
- **量化偏差**：32B 实验使用了 AWQ int4 量化，可能影响绝对准确率（但配对 Δ 应无偏）。
- **单种子**：wall-clock 预算基于单种子的测量，未报告方差。
- **应用限制**：对于延迟敏感的推理场景（如实时对话），470 秒/问题不可接受；git 的 merge 操作虽然演示了冲突暴露，但需要精心设计文件布局（按主题而非内容哈希）才能有效，否则矛盾可能共存。
- **统计功效**：n=40 的探索实验置信区间宽（±~12pp），只能检测大效应；n=500 的大规模实验功效充分，但 null 结果仍然受限于测试的模型和后端集合。
