## Abstract
Persistent memory for an LLM agent is a write-heavy substrate: every belief update is a versioned write, and a new claim may contradict a stored one. Production systems use four resolution heuristics (last-writer-wins, evidence-weighted merge, await-confirmation, per-rule policy), yet none declares the isolation level it assumes or the write-time anomalies it admits. We show that contradiction resolution is write-time concurrency control and make the missing contract explicit. TOKI types the four heuristics as one family of bitemporal operators over a dual-row schema, each with an isolation precondition and a provenance annotation that preserves the losing fact in an audit row. Four soundness theorems close the contract across isolation, schema, and provenance, lift the guarantees to operator pipelines, and extend the fold operators to n-ary conflict sets. A tightness companion proves that, within the relational schedule model, keyed logging of the adjudicating judge is necessary for replay consistency, which every audited baseline omits. A verdict matrix over eight systems localizes the gap: every baseline that keeps a language-model judge on the write path admits at least one of three write-time anomalies (replay inconsistency, belief-drift skew, audit erasure); a content-addressed engine-layer comparator avoids them only by removing the judge, and TOKI alone excludes all three while keeping it. On its one natural-workload slice the audit-row defence moves LoCoMo by 0.86, and ablating the typed memory layer removes 0.49 accuracy on 1,444 answerable LoCoMo questions; the cross-system comparison stays underpowered and claims no superiority. The contribution is the contract: a write-time correctness specification, proved sound across isolation, schema, and provenance, pinning the guarantee every production heuristic assumes but no deployed system makes explicit.

本文的核心主张是：矛盾解决本质上就是写入时的并发控制，而现有的生产系统缺少一个显式的正确性契约。作者将四种启发式形式化为统一的双时态算子代数家族，并为每个算子声明隔离前件和来源注释，从而关闭这一契约缺口。

## 2. 方法论：核心思想、关键技术细节

**核心思想**  
TOKI 将四种矛盾解决策略类型化为双时态算子（⊕t、⊕p、⊕?、⊕c），每个算子具备：  
- 隔离前件（isolation precondition）：如 RC、SI、SR，来自经典 Berenson–Adya 异常层次；  
- 双行模式（dual-row schema）：每一行实际由“当前行”（current，存放赢家）和“审计行”（audit，存放输家事实 + 来源多项式）组成；  
- 来源注释（provenance annotation）：基于 K-半环多项式，确保输家事实在半环自然序下可恢复。

**关键技术细节**  
1. **双时态事实与矛盾事件**：核心对象是 subject–predicate–object 三元组加上有效时间区间、系统时间区间、K-关系来源注释和置信度。两个事实矛盾当且仅当共享 subject 和 predicate，但 object 不同，且有效时间区间相交。  
2. **双行模式**：物理表包含 11 个用户可见列和一个隐藏的 CHECK 约束列 `row_kind ∈ {current, audit}`，用于区分当前可见行与审计行。审计行携带 `p_winner ⊕ p_loser` 的合并来源，以及策略标识和时间戳。默认检索仅访问 `current` 行，审计行可通过单独的审计日志切片访问。  
3. **算子定义**：每个算子 ⊕a 接收两个矛盾事实 (f1, f2)，返回一个赢家并系统时间无效化输家，同时输出审计元组。四个算子仅在赢家选择器和策略标记上不同：  
   - ⊕t（LWW）：最后写入者获胜，隔离前件 RC，暴露 P4 丢失更新；  
   - ⊕p（Evi）：证据加权，隔离前件 SI，暴露 A5B 写偏斜；  
   - ⊕?（Await）：等待确认，隔离前件 RC+cb，暴露回调边界；  
   - ⊕c（Rule）：按规则策略，隔离前件 SR policy，暴露 P3 幻影。  
4. **隔离前件与异常映射**：每个算子声明的隔离级别排除了该级别下不允许的经典异常。作者进一步定义了三个 LLM 特有的写入时异常：  
   - **N1 重放不一致**：对同一矛盾重新裁决产生不同赢家；防御措施为对判决法官的键日志进行可串行化读取。  
   - **N2 信念漂移偏斜**：并发的置信度修正破坏 (subj, pred) 分区的一致性；防御措施为对分区采用可串行化隔离。  
   - **N3 审计擦除**：被覆盖的事实在系统中不可恢复；防御措施为审计行模式（保留输家来源）。  
5. **正确性定理**：  
   - **定理1（隔离轴异常正确性）**：算子在工作于隔离级别 L 时排除经典异常集 Φ 当且仅当 L 支配 guard(Φ)。  
   - **定理2（审计擦除模式提升）**：审计行模式保证每个输家事实都被审计行中的合并来源所支配（在半环自然序下），从而排除 N3。而基础模式存在 N3 的调度历史。  
   - **定理3（载体可恢复性）**：审计擦除的恢复能力取决于 K-半环的度结构：仅当单调多项式次数 ≥2 时才能通过形式移位恢复单个写入实例。  
   - **定理4（组合正确性）**：顺序组合的管线在隔离和模式轴上取个步前件的格上确界，从而保持正确性。  
   - **定理5（N1 下界）**：如果系统不满足 H1 合规（即不将判决法官结果记录在键日志中），则在有界非确定性预言机下一定存在 N1 的调度历史。  
6. **算法实现**：参考实现约 2700 行 Python，在无原生双时态支持的 DuckDB 上运行；写入路径确保判决法官日志在算子提交之前写入，从而满足引理1的排序假设。

## 6. 主要结论与发现

1. **契约缺失已明确**：所有生产级智能体记忆系统（保留 LLM 法官者）至少存在一种三种写入异常（N1、N2、N3）之一；WorldDB 通过将法官移出写路径来排除所有异常，而 TOKI 是唯一在保留法官的同时排除所有异常的系统。  
2. **键日志规程是 N1 排除的紧致刻画**：在关系调度模型中，没有键日志的系统必然允许 N1（符合封闭形式 2p(1-p)）；有键日志并置于 SR 下则可排除。  
3. **审计行防御在自然负载上有效**：在 LoCoMo 上开启审计行使准确率提升 +0.86（CI [0.76, 0.94]）。  
4. **类型化内存层承载了几乎全部的事实回想能力**：在 1444 个可回答问题上，移除内存层使准确率从 0.540 降至 0.048（Δ=+0.49）。  
5. **形式化定理获得实证匹配**：所有结构化网格的预测 0/1 边界与观测一致，支持正确性定理。  
6. **载体选择对判据无影响但对令牌召回有影响**：Boolean 载体 N3 无法恢复具体写入身份，而 multilinear 和 multidegree 载体可以（后者 100% 召回）。

## 7. 优点

- **理论贡献明确**：首次为 LLM 智能体持久内存的写入路径引入类型化隔离契约，解决了生产系统长期缺乏显式正确性规范的问题。  
- **衔接经典理论**：将矛盾解决定位为写入时并发控制，优雅地利用 Berenson–Adya 异常层次、双时态数据模型和 K-半环来源，实现了迁移而非从零发明。  
- **形式化证明与实证验证并重**：四个定理加一个下界定理，并配套五个结构化网格和机制剥离实验，使理论可被独立验证。  
- **实验设计分层合理**：从全局判决矩阵到机制分离，再到性能缩放和载体消融，逐步压紧每个断言。  
- **透明度高**：跨系统比较时坦诚承认低统计力和不声明优越性；判决矩阵区分设计路径（Claim）与运行路径（Wire）并报告差异；对每个细胞提供证据卡片。  
- **开源实现和再现性**：提供了完整的参考实现、实验适配器、种子清单、Dockerfile 和 Makefile 目标，便于复现。

## 8. 不足与局限

- **跨系统效用比较统计力不足**：LoCoMo 切片 n=50，power 仅为 0.42（δ=0.05），三个测量的 CI 均覆盖 0，因此无法得出优于其他系统的结论。LongMemEval-S 和 MultiTQ 细胞因结构性原因放弃。  
- **没有覆盖主流模型**：判决矩阵未纳入 MemGPT、HippoRAG、MemOS 等系统，且 WorldDB 仅基于论文分析（无代码）。跨系统比较仅限于 LoCoMo 一个切片。  
- **单节点性能测量**：所有性能实验在单进程 DuckDB 上运行，PostgreSQL 试验也仅测试单机并发。无分布式部署声明。  
- **N1 防御范围受限**：仅适用于固定解码器元组（prompt+seed+model+温度）的部署内重放粒度；跨部署的法官提示漂移可能绕过防御，作者通过“法官提示敏感性引理”量化了这一边界但并未解决。  
- **确定性预言机与引擎层调解器不在定理范围内**：定理5的 N1 下界仅对**有界非确定性**预言机成立；确定性或引擎层调解器（如 WorldDB）需要单独处理。  
- **单一评判模型偏差**：多数实验使用单一评判模型（Claude Haiku）进行自动评估，尽管进行了交叉法官鲁棒性检查（5 个模型，PARTIAL 带），但仍可能存在系统性的输出偏好。  
- **没有披露算力/成本**：未提供 LLM API 调用的具体数量、GPU 小时数、或财务成本，这使可复现性中的资源预期不明确。  
- **理论覆盖不完全**：作者承认 N2 防御仅适用于单个 (subj,pred)

作者承认 N2 防御仅适用于单个 (subj, pred) 分区，无法完全消除跨分区的信念漂移偏斜，因此在实际多分区场景中可能仍有残留的 N2 异常。  
- 此外，整体的评估局限于单后端（DuckDB / PostgreSQL），未在分布式、跨区域或大规模并发环境下验证性能与正确性；论文的主要贡献在于理论契约的建立与形式化，实际部署中的性能开销、横向扩展能力以及长期维护成本仍需进一步研究。  
- 论文未提供 LLM API 调用的具体数量、GPU 小时数或财务成本，这使得资源预期与可重复性评估不够透明。  
- 跨系统比较的样本量较小（n=50），且仅覆盖 LoCoMo 一个切片，LongMemEval-S 和 MultiTQ 因结构性原因放弃，因此结论的外推性有限。  
- 单一评判模型（Claude Haiku）的自动评估可能存在系统性偏差，尽管论文进行了交叉法官鲁棒性检查（5 个模型，PARTIAL 带），但并未完全消除该偏差。  
- 部分基线系统因版本配置差异（如 mem0 v3 在 LoCoMo 上有五个配置差异）而需要在实验中手动适配，这可能引入额外的实验噪声。  
- 理论覆盖仍有缺口：确定性预言机与引擎层调解器（如 WorldDB）不在定理范围内，N1 下界定理仅针对有界非确定性预言机成立；法官提示漂移（跨部署的提示变化）可能绕过 N1 防御，作者虽然量化了该边界但未提供解决方案。
