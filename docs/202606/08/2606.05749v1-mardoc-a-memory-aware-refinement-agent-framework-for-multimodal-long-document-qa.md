## 摘要
迭代式检索-推理智能体近年来在多模态长文档问答中展现出潜力。然而，现有系统大多维护一个单一增长的上下文，将检索痕迹、观察结果和中间推理混合在一起。随着交互的累积，关键证据变得分散且稀释，使得多跳推理变得嘈杂。我们提出MARDoc，一种记忆感知精炼智能体框架，将长文档问答解耦为三个专用智能体：Explorer用于多粒度多模态检索，Refiner用于将交互痕迹提炼为结构化证据和推理记忆，Reflector用于检查证据充分性并提供针对性反馈。在迭代过程中，智能体依赖动态更新的结构化记忆，而非完整的累积交互历史。这种设计减少了上下文噪声，同时保留了答案关键事实及其逻辑依赖性。在MMLongBench-Doc和DocBench上的实验表明，MARDoc取得了强大的结果，优于同骨干基线，并证明了结构化记忆在智能体文档问答中的有效性。

## Abstract
Iterative retrieval-reasoning agents have recently shown promise for multimodal long-document question answering. However, most existing systems maintain a single growing context that mixes retrieval traces, observations, and intermediate reasoning. As interactions accumulate, key evidence becomes scattered and diluted, making multi-hop reasoning noisy. We propose MARDoc, a Memory-Aware Refinement Agent framework that decouples long-document QA into three specialized agents: an Explorer for multi-granularity multimodal retrieval, a Refiner for distilling interaction traces into structured evidence and reasoning memories, and a Reflector for checking evidence sufficiency and providing targeted feedback. Across iterations, the agents rely on a dynamically updated structured memory rather than a full accumulated interaction history. This design reduces context noise while preserving answer-critical facts and their logical dependencies. Experiments on MMLongBench-Doc and DocBench show that MARDoc achieves strong results, outperforming same-backbone baselines and demonstrating the effectiveness of structured memory for agentic document QA.

- **现存问题**：现有方法主要分为三类：端到端OCR模型（难以扩展至长文档）、检索增强方法（证据分散，跨页关联困难）、智能体方法（采用“单一增长上下文”范式，将新检索结果和中间推理不断追加到同一个上下文中）。随着交互轮次增加，无关历史因素稀释上下文，压缩模型有效推理空间；同时缺乏基于记忆的质量控制机制，早期错误可能累积放大。

## 2. 方法论：核心思想、关键技术细节

- **核心思想**：将长文档问答解耦为三个专用智能体（Explorer、Refiner、Reflector），通过“探索-精炼-反思”循环驱动，依赖动态更新的结构化记忆（而非完整交互历史）进行迭代推理。
- **关键技术细节**：

  - **Explorer（勘探器）**：基于ReAct框架，接收查询Q、结构化大纲O、当前记忆M_{t-1}和反思指令R_{t-1}，使用多粒度工具集（搜索、获取段落/页面/图像/表格等）进行检索，生成推理链T_t（公式1-2）。工具集包含7种工具（search、get_section、get_paragraph、get_page_images、get_image、get_table_image、search_metadata），支持粗到细的定位。
  - **Refiner（精炼器）**：在每次勘探迭代后，将勘探器的交互痕迹（推理链T_t）蒸馏为结构化记忆M_t = (M_E, M_R)（公式3）。M_E为证据记忆，记录核心事实及其来源；M_R为推理记忆，提取清晰推理路径并标注依赖关系。精炼器丢弃无关噪声，仅保留答案关键事实和逻辑链，实现上下文的紧凑化。
  - **Reflector（反射器）**：检查精炼后的结构化记忆M_t，判断证据是否充足：若充足则直接输出最终答案A（公式4）；若不充足或存在错误，则生成针对性反馈指令R_t（公式5），引导下一轮勘探。反馈指令总结关键推理线索，如“缺失总数”、“关注特定模型”等。

## 6. 主要结论与发现

- MARDoc在所有对比方法中表现最优或接近最优：在MMLongBench-Doc上使用Qwen3-30B骨干达到57.1% ACC，与使用Claude 3.5 Sonnet的DocAgent相当，但骨干模型更小。
- 结构化记忆设计有效缓解了上下文稀释问题：随着证据页面数量增加，MARDoc性能下降幅度小于DocAgent，说明多跳推理能力更强。
- Refiner和Reflector两者缺一不可：去除Refiner导致性能大幅下降（低于无这两个组件的基线），说明没有结构化记忆，反射器无法在噪声中有效工作。
- 证据记忆和推理记忆功能互补：移除推理记忆主要损害多跳问题，移除证据记忆主要损害不可回答问题（导致幻觉），两者结合才能实现事实准确性和逻辑连贯性。
- 反射指令提供明确的检索指导，提升单跳和多跳问题性能，但略微降低不可回答问题的准确率（模型更倾向预测可回答）。
- 工具和文档处理的质量至关重要：使用更细粒度的文档解析（MinerU2.5）和更丰富的工具集（增加get_paragraph和search_metadata）能显著提升布局和表格相关信息的检索。
- 计算成本方面，MARDoc相比DocAgent额外消耗约22.5k令牌和15.9秒延迟，但准确率提升7.8个百分点，属于合理的“测试时扩展”代价。

## 7. 优点

- **创新性**：首次将长文档问答中的上下文管理从“单一增长流”替换为“探索-精炼-反思”循环，引入结构化记忆蒸馏机制，有效解决信息稀释和逻辑断裂问题。
- **解耦设计**：三个智能体各司其职（检索、蒸馏、验证），通过结构化记忆通信，避免了传统方法中智能体自我错误传播。
- **细粒度证据与推理分离**：记忆分为证据记忆和推理记忆，便于定位错误来源（是证据缺失还是推理错误），增强了可解释性。
- **多粒度工具集**：支持跨页面、跨模态的粗到细检索，结合文档大纲提升检索效率。
- **实验严谨性**：
  - 在两个大规模基准上均采用官方评估协议，使用GPT-4o自动评价减少人为偏差。
  - 消融实验覆盖了组件、超参数、工具设计等多个维度。

- **无需训练**：纯提示工程构建，易于部署和迁移，且展示了扩展到更强骨干（如Qwen3-VL-32B）后性能进一步提升。

- **未进行任务特定微调**：论文承认所有智能体通过提示工程构建，未使用训练优化。引入微调（如对Refiner或Reflector进行监督学习）可能进一步提升性能。

- **资源需求较高**：虽然训练免费，但推理仍需4张A800 GPU，对小规模团队部署可能不友好。
