## 摘要
长期LLM智能体需要持久记忆，能够在不同会话中追踪变化的事实并提供相关证据。现有的记忆系统通常将观测结果存储为孤立的记录、摘要或索引片段，这使得证据聚合、事实修正和记忆维护变得困难。我们提出Infini Memory，一种可维护的基于文本的持久记忆架构，它将智能体记忆视为主题结构化的文档。每个主题文档作为一个语义单元，用于收集相关证据、保留元数据并随时间修正事实。新的观测结果首先暂存于缓冲区，并定期整合成语义连贯的文本上下文。在推理时，代理检索过程允许LLM通过迭代工具调用而非单次检索步骤来读取记忆。在MemoryAgentBench上，Infini Memory取得了64.7%的总分。消融实验表明，主题结构化维护和迭代证据检查能够改善长期记忆使用的互补方面。

## Abstract
Long-term LLM agents need persistent memory that can track changing facts and provide relevant evidence across sessions. Existing memory systems often store observations as isolated records, summaries, or indexed fragments, which makes evidence aggregation, fact revision, and memory maintenance difficult. We propose Infini Memory, a maintainable text-based persistent memory architecture that treats agent memory as topic-structured documents. Each topic document serves as a semantic unit for collecting related evidence, preserving metadata, and revising facts over time. New observations are first staged in a buffer and periodically consolidated into coherent textual contexts. At inference time, an agentic retrieval procedure lets the LLM read memory through iterative tool calls rather than a single retrieval step. On MemoryAgentBench, Infini Memory achieves 64.7% overall score. Ablations show that topic-structured maintenance and iterative evidence inspection improve complementary aspects of long-term memory use.

# Infini Memory：面向长期LLM智能体记忆的可维护主题文档——论文详细总结

## 1. 论文的核心问题与整体含义

- **研究动机**：长期运行的 LLM 智能体需要持久记忆来追踪变化的事实，并在跨会话交互中提供相关证据。然而，现有记忆系统大多将观测结果存储为孤立记录、摘要或索引片段，导致四个典型故障模式：
  - **记忆碎片化**：相同主题的证据散落在多个小记录中；
  - **记忆冲突**：新旧观测矛盾时，追加式存储让两个版本共存；
  - **压缩损失**：长期历史被压缩为摘要后，丢失时间顺序和来源线索；
  - **检索不足**：单次检索返回孤立片段，不足以支撑多跳推理。
- **核心含义**：持久记忆应被视为一个**生命周期维护问题**，需要支持写入、维护和读取三个耦合操作，尤其要解决证据聚合、事实修订和上下文恢复问题。

## 2. 论文提出的方法论

- **核心思想**：将智能体持久记忆组织为**主题文档（Topic Documents）**。每个主题文档在语义上聚合相关证据，保留元数据，并支持随时间修订。通过**缓冲写入 + 周期整合**的分离设计，以及**代理式检索**（Agentic Retrieval）来提升记忆维护与检索能力。

- **关键技术细节**：
  - **主题文档表示**：
    - 每个文档包含元数据头（id、摘要、token数、创建时间、更新日志等）和层次化正文。
    - 正文使用主题/子主题标题组织，每条记忆条目带有可解析的签名：`<seq=..., time=..., source=...>`，保留顺序、时间和来源信息。
  - **缓冲写入与整合（Consolidation）**：
    - 新记忆先追加到短期缓冲区 `CURRENT`，避免频繁扫描主题库。
    - 缓冲区达到阈值（5000 token 或时间窗口）时触发冲洗（flush）：先重写 `CURRENT` 为 `REWRITE_CURRENT` 草案（去重、解决局部矛盾、保留元数据），再通过规划器（planner）将草案路由到现有主题文档或创建新文档。
    - 主题库定期执行分裂（过大文档拆分为更聚焦的子文档）和合并（相似小文档合并），保持主题内凝聚性。
  - **代理式检索**：
    - 推理时，LLM 控制一个多步骤搜索过程，调用工具（全局词搜索、文档内搜索、目录浏览、行范围读取等）来迭代寻找、验证和扩展证据。
    - 提供两种变体：**混合检索（Infini Memory-H）**（LLM 根据摘要选文档，BM25 补充分区匹配）和**代理式检索（Infini Memory-A）**（LLM 全程控制工具调用）。
    - 检索循环在达到停止条件（足够证据、最大迭代次数等）后结束，最终证据集包括选定内容（扩展为最近标题块）和当前缓冲区中的条目。

- **算法流程（文字说明）**：
  - **写入与整合算法**：从交互提取记忆 → 追加到 CURRENT → 缓冲区超阈值时重写为草案 → 规划更新（分裂过大，路由到现有或新文档） → 更新主题库 → 定期合并小文档 → 刷新库元数据。
  - **代理式检索算法**：获取库摘要 → 构造提示（查询+目录） → 循环：LLM 决定是否停止或调用工具 → 执行工具并记录中间结果 → 若停止则整理选中的证据（扩展范围） → 若证据不足则用 BM25 回退 → 加入 CURRENT 条目 → LLM 生成答案。

- **Infini Memory-A 取得最高总体得分 64.7%**，比最强基线（HippoRAG-v2, 45.5%）高出 19.2%，在所有四项能力上均领先，尤其在 Selective Forgetting 上高出 26.5%。
