## 摘要
长期运行的语言模型系统会积累超出上下文窗口的交互历史，因此必须不断进行驱逐。当驱逐策略丢弃了关键细节（例如登录时颁发的访问令牌或下一个调用所需的路径）时，操作就会失败。我们提出LRE（学习相关性驱逐），这是一种仅需几KB、仅使用CPU、无需语言模型的评分器，它通过学习哪些历史单元是关键性的，并通过逐字提取来保留它们。在匹配预算的比较下，在我们的实验中，没有基线在准确性-成本平面上优于LRE。在智能体上，LRE整体上匹配了保留全部历史的准确性。在最简单的任务上，它比无驱逐基线高出27%，同时无需任何压缩器调用，并将峰值上下文大小减少高达52%。一项受控研究追踪显示，LRE完成了其他方法循环的任务，其中在37%的调用次数内就完成了此类任务，比保留所有内容更高效，并解决了14个其他运行策略无法完成的任务。在对话记忆方面，LRE以零神经成本超越了密集编码器和令牌剪枝编码器。在下游评估中，LRE在LoCoMo阅读中提供了最佳预算答案质量，同时读取的令牌减少了68%。其监督也可以无需标注：仅基于系统自身行为进行训练，就能恢复95%的有监督评分器的有效性。我们认为，由于LLM智能体中的记忆驱逐是一个保真度问题，它需要一种可部署的主动策略，其中未来查询不可用且确切状态至关重要，而廉价的已学习相关性就足够了。

## Abstract
Long-running language-model systems accumulate interaction history that outgrows the context window, so they must continually evict. When an eviction policy drops a load-bearing detail, for example an access token issued at login or a path the next call needs, the action fails. We present LRE (Learned Relevance Eviction), a few kilobytes, CPU-only, language-model-free scorer that learns which units of history are load-bearing and keeps them by verbatim extraction. Under a matched-budget comparison, in our experiment, no baseline dominates LRE on the accuracy-cost plane. On agents, LRE matches the accuracy of keeping the entire history overall. On the simplest tasks, it exceeds that no-eviction baseline by 27%, while requiring zero compressor calls and reducing peak context size by up to 52%. A controlled study trace shows LRE completes tasks where the others loop, finishing one such task in 37% fewer calls than keeping everything and solving 14 tasks where no other run policy does. On conversational memory, LRE outranks dense and token-pruning encoders at zero neural cost. In downstream evaluation, LRE gives the best budgeted answer quality on LoCoMo reading 68% fewer tokens. Its supervision can also be annotation-free: training only on the system's own behavior recovers 95% of the supervised scorer's effectiveness. We argue that, because memory eviction in LLM agents is a fidelity problem, it requires a deployable proactive policy where the future query is unavailable and exact state is decisive, and that cheap learned relevance can be sufficient.

### 论文总结：Learning What Not to Forget: Long-Horizon Agent Memory from a Few Kilobytes of Learning

#### 1. 核心问题与整体含义（研究动机与背景）
- **问题**：长期运行的 LLM 智能体/助手会累积大量交互历史，超出上下文窗口限制，必须持续驱逐（evict）信息。现有驱逐策略（如基于最近性 FIFO、LLM 压缩摘要）往往丢失关键细节（如登录令牌、API 路径），导致后续动作失败。
- **动机**：驱逐不同于检索——驱逐发生在写入时，无法预知未来查询，因此需要一种前瞻性、查询盲（query-blind）的保真度策略。作者认为记忆驱逐本质是保真度问题，廉价的学习相关性评分足以胜任。

#### 2. 方法论：核心思想、技术细节与算法流程
- **核心思想**：LRE（Learned Relevance Eviction）——一个超轻量级（几 KB）、仅 CPU、无语言模型调用的评分器，基于因果特征为每个历史单元（对话轮次或智能体动作-观察步骤）计算相关性得分，然后在预算内贪婪地保留得分-密度（得分/令牌数）最高的单元，**逐字提取**（verbatim extraction）而不进行摘要或改写。
- **关键技术细节**：
  - **特征设计**：每个单元使用 6～10 维因果特征（只在前缀上计算，避免未来信息泄露）。例如：相对位置、log(token数)、数字字符数、大写词数、是否含错误、是否为代码、罕见词密度、与上一步的 Jaccard 相似度等（表6）。特征既有通用结构特征，也有领域特定特征（如代码错误指示器）。
  - **评分器**：L2 正则化的逻辑回归，输出 sigmoid 概率作为相关性得分。
  - **驱逐决策**（算法3）：给定预算 B（令牌数或单元数）、永远保留的近期窗口 R_k（如最后5步），对剩余历史单元按价值密度（p_i / c_i）降序贪婪选取，确保不超预算，最后按时间顺序输出。
  - **自监督标签**：无需人工标注，利用系统自身行为生成标签。智能体域：若某单元首次引入的标识符被后续 ≥3 步重复使用，则标为正标签。对话域：若某轮次的令牌与后续答案重叠 ≥40%（召回率），则标为正标签。该标签能恢复有监督模型 95% 的区分能力（表4）。
- **算法流程**（文字说明）：
  1. 系统运行中每新增一个单元（步骤/轮次），若总令牌数超出预算 B，则触发驱逐。
  2. 将历史分为永久保留的近期窗口（R_k）和待驱逐的较老部分。
  3. 对较老部分，用训练好的逻辑回归计算每个单元的保持概率。
  4. 按“概率/单元成本”降序排序，依次放入保留集合直到预算用完（0/1 背包的贪婪近似）。
  5. 将保留的较老单元（按原时间顺序）与近期窗口拼接，作为最终上下文。

#### 3. 实验设计：数据集 / 场景、Benchmark 与对比方法
- **数据集与场景**：
  - **智能体域**：AppWorld（Trivedi et al., 2024）——长时程工具使用基准，包含 168 个测试任务（57 Easy, 48 Medium, 63 Hard），基于隐藏单元测试评估任务完成率（TGC）。
  - **对话记忆域**：LoCoMo（Maharana et al., 2024）——10 个长篇对话（共 5882 轮次），评估查询无关的相关性排名；LongMemEval S（Wu et al., 2024）——500 个问题，每个问题约 50 个会话，评估跨会话记忆。
- **对比方法**（分类列出）：
  - **智能体域**：无压缩（全历史保留，上限）、FIFO（仅保留最近 5 步）、ACON（使用 LLM 进行自适应压缩）。
  - **对话域**：Recency/FIFO、MemoryBank（时间衰减）、内容显著性（TF-IDF 质心余弦相似度）、密集显著性（BGE 编码器）、LLMLingua-2（令牌级剪枝），以及 LRE 的三种变体：有监督、自监督、纯内容（仅 TF-IDF 特征）。

  - 对话：宏观 AUC（衡量相关性排序）、黄金证据召回率、下游 QA 的 token-F1 或 LLM 法官评分。

#### 4. 资源与算力
- **LRE 的资源消耗**：评分器大小仅 1.7 KB（智能体域），全部在 CPU 上运行，无需 GPU 或任何神经网络前向传播。测试中：LoCoMo 在 Apple M2 上，LongMemEval S 在 Modal Linux（8 vCPU + NVIDIA T4 16GB）上，但 LRE 始终仅用 CPU。加速比：LRE 每秒评分 1181 单元，密集编码器为 103（慢 11.5×），LLMLingua-2 为 36（慢 32.8×）。

#### 6. 主要结论与发现
- LRE 在准确性-成本平面上达到帕累托最优：无基线同时更准确且更便宜。
- 在 AppWorld 上，LRE 的总体 TGC（41.1%）接近无压缩上限（44.0%），但无需任何 LLM 压缩调用，峰值上下文减少最多 52%；在简单任务上甚至超过无压缩（+27%）。
- LRE 的保真优势源于逐字提取：14 个任务仅 LRE 能完成，而 FIFO 或 ACON 因丢失确切状态而循环失败。
- 对话域上，LRE 的 query-blind 排序（宏观 AUC 0.708-0.829）超越密集编码器（0.643）和 LLMLingua-2（0.402），且零神经代价。
- 自监督标签（来自系统自身行为）恢复有监督评分器 95% 的区分能力，说明训练信号已在日志中。
- 结论：廉价学习相关性足以支撑前瞻性驱逐，无需神经模型或重复 LLM 压缩。

#### 7. 优点
- **极低成本**：仅 CPU、几 KB、无 LLM 调用，可部署于生产环境。
- **保真提取**：逐字保留关键令牌（如 token、ID），避免压缩导致的丢失。
- **自监督**：从日志自动生成标签，无需昂贵人工标注。
- **跨领域设计**：同一评分框架（仅特征和标签定义不同）同时适用于智能体与对话。
- **评估严谨**：智能体域使用回放还原真实 TGC，避免自报告偏差；对话域采用分组交叉验证、去重保护防止泄露。

#### 8. 不足与局限
- **评估覆盖窄**：仅在 AppWorld（工具使用）、LoCoMo 和 LongMemEval S（对话记忆）上评估，未涉及网页浏览、多模态、多智能体协作或开放域代码等场景。
- **单种子问题**：智能体域仅用一个随机种子，未报告方差，结果可能受偶然因素影响。
- **预算限制**：当任务所需状态超出设定预算（如 AppWorld Hard 的 2048 令牌），无压缩仍更优——LRE 并非全能，需在预算紧张时使用。
- **特征依赖**：特征集是手动设计的，不同部署可能需重新定义/验证，论文未证明其通用最优性。
- **标签阈值固定**：自监督标签的阈值（如 3 次重用、0.4 召回率）在论文中由经验选定，但具体部署需重新校准。
