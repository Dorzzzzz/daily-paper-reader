## 摘要
LLM智能体越来越多地部署在需要跨长时间交互历史持续推理的长期任务上。大规模实现这一目标需要智能体跨会话持久地存储、检索和更新自身记忆。一个丰富的智能体记忆系统生态已出现，涵盖平面检索、LLM中介提取、整合事实存储和智能体控制流。然而，它们的系统级行为尚未被刻画。我们首次对智能体记忆进行系统表征。首先，我们引入一个面向系统的分类法，沿四个轴对智能体记忆系统进行分类。其次，我们构建了一个阶段感知的性能分析工具，将成本归因于构造、检索和生成。第三，我们在两个基准套件上表征了十个代表性系统，揭示了设计选择如何沿写入和读取路径转移成本。最后，我们提出了10条系统建议，涵盖构造调度、能力下限、通过查询量的摊销、新鲜度-延迟权衡以及集群规模管理。

## Abstract
LLM agents are increasingly deployed on long-horizon tasks requiring sustained reasoning over extended interaction histories. Realizing this at scale requires agents to persistently store, retrieve, and update their own memory across sessions. A rich ecosystem of agent memory systems has emerged spanning flat retrieval, LLM-mediated extraction, consolidating fact stores, and agentic control flows. Yet, their system-level behavior remains uncharacterized. We present the first systems characterization of agent memory. First, we introduce a system-oriented taxonomy classifying agent memory systems along four axes. Second, we build a phase-aware profiling harness attributing cost to construction, retrieval, and generation. Third, we characterize ten representative systems across two benchmark suites, uncovering how design choices shift cost across the write and read paths. Finally, we derive 10 system recommendations covering construction scheduling, capability floors, amortization via query volume, freshness-latency tradeoffs, and fleet-scale management.

## 1. 论文的核心问题与整体含义

- **研究动机**：LLM 智能体在长期任务（如个人助手、代码代理、深度研究代理）中需要跨会话持久化、检索和更新自身记忆。现有智能体记忆系统（如平面检索、LLM 中介提取、整合事实存储、智能体控制流）日益丰富，但其**系统级行为**——包括计算成本、延迟、能量、存储扩展性等——尚未被系统化表征。准确性指标（如下游任务精度）掩盖了这些系统在部署规模下的关键差异。
- **整体含义**：首次对智能体记忆工作负载进行系统级刻画，揭示不同设计范式如何沿读写路径重新分配成本，为大规模部署提供定量指导。论文认为，智能体记忆从被动检索目标转变为主动系统组件（写入路径、搜索路径、维护策略），其工作量特征与传统的 LLM 服务显著不同。

## 2. 方法论

- **核心思想**：
  - 提出面向系统的 **四轴分类法**：构建机制（无/确定性/LLM中介/智能体控制）、存储结构（原始缓存/倒排索引/密集向量/知识图谱/混合存储）、检索策略（单次/多阶段/图遍历/智能体循环）、可变性（追加/整合/突变）。
  - 将智能体记忆执行分解为七个阶段：**摄取 → 记忆构建 → 存储 → 检索 → 提示组装 → 生成 → 维护**，并将成本归因于三个逻辑阶段：**构建（write-path）**、**检索（read-path prefix）**、**生成（final answer）**。
- **关键技术细节**：
  - 构建**阶段感知分析工具**，记录每个聊天补全和嵌入请求的API遥测（类型、令牌数、延迟）以及硬件遥测（GPU功率、利用率、HBM带宽），实现每阶段成本归因。
  - 标准化主要可控因素：相同生成LLM（GPT-4.1-mini/GPT-4o-mini或Qwen3系列）、相同嵌入骨干（text-embedding-3-small或Qwen3-Embedding-0.6B），同时保留各系统原生执行模式（缓冲、并行摄取、跨块整合）。
  - 对智能体系统进行最小任务适应（如更新提示模板处理非对话数据、限制工具调用避免本地模型死循环），确保公平比较。

## 6. 主要结论与发现

1. **构建成本主导**：对于LLM中介的智能体记忆系统，构建能量超过300次查询的总查询阶段能量。每正确答案能量跨系统差异达47倍以上（BM25 ~4.1kJ，A-Mem ~116kJ，MIRIX ~144kJ，Letta ~186kJ）。
2. **构建是嵌入和预填充主导的工作负载**：读取长块并输出短结构化记录（中位解码令牌仅占总构建令牌4.6%），与延迟敏感的QA服务存在结构性冲突。
3. **嵌入流量呈双峰性**：范式III.a产生大批量离线索引；范式III.b和IV产生顺序单事件写入，需要不同的嵌入式服务配置。
4. **构造LLM有下限**：无严格输出合同的系统（Mem0, SimpleMem, A-Mem）允许向下缩放LLM，准确率平滑下降；有严格输出合同的系统（MIRIX）在弱模型下完全失效。
5. **没有单一系统同时最优**：BM25在整体准确率上最高（55.8%），但查询延迟约7.4s；Mem0查询延迟最低（~2.2s）但准确率仅26.8%；不同任务类别下优劣反转。
6. **新鲜度-延迟权衡**：慢构建系统在异步调度下累积陈旧状态，每会话构建时间跨5个数量级（BM25 <1ms，Mem0/MIRIX ~10s+），使得新鲜度成为关键约束。
7. **每用户存储和令牌成本增长斜率差异大**：1M令牌时存储差异9倍，但构建令牌成本差异更显著（智能体式系统超线性增长，如Letta在256K后陡增）。
8. **尾部延迟**：确定性系统p95/p50 ~1.3x；LLM绑定系统（GraphRAG 5.9x，Letta 3.9x）需要外部迭代上限。

## 7. 优点

- **系统性**：首次从系统角度而非纯准确性角度刻画智能体记忆，提出四轴分类法覆盖宽广设计空间，解释性强的预见性（如范式决定构建成本形状）。
- **阶段感知分析**：构建精确的成本归因工具，分离构建、检索、生成，揭示各阶段能量、延迟和硬件行为，使建议可操作。
- **实验全面**：横跨两个基准（MemoryAgentBench、MemoryArena）、多种任务类型、远程和本地部署、多尺度历史长度、多种LLM尺寸，提供多维对比（能量/准确率/延迟/存储/新鲜度/尾部）。
- **实际建议**：总结10条具体系统建议（如构建线程池、背景调度、嵌入批处理配置、外部迭代限制等），直接指导工程实践。
- **公平性考虑**：对每个系统做了最小任务适应而非强制统一接口，保留原生执行模型；标准化生成LLM和嵌入模型，控制变量。

## 8. 不足与局限

- **实验覆盖的局限**：
  - 仅使用Qwen3系列作为本地LLM，未测试其他主流模型（如Llama 3、Gemma等），可能影响通用性。
  - 每个系统使用单一配置（如retrieval top-k=10），未做详尽超参数网格搜索，可能不公平地低效某些系统。
  - 未测试多节点、多智能体协作场景；未考虑分布式记忆一致性开销。
  - 多模态记忆（图像、音频）未涉及。
- **偏差风险**：
  - 任务适应可能无意中调整了某些系统的输出使其在某些数据集上更好（如Mem0的ICL提示更改）。

  - 能量计算基于单GPU采样，未计及CPU、内存及其他基础设施。
- **应用限制**：
  - 论文结论基于特定基准（MAB、MemoryArena），真实部署中交互模式可能不同（如更低/更高的会话频率、不同任务混合）。
  - 许多当前系统默认无遗忘策略，长期存储费用未定界；论文建议独立添加修剪策略，但未提供定量分析。
  - 没有提出新的系统架构，仅有分析性建议；缺乏对建议效果的实验验证（如调度优化后的实际延迟改善）。
