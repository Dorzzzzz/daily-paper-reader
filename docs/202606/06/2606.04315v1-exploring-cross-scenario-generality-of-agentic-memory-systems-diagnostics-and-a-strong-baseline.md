## 摘要
大语言模型智能体积累的历史记录会超出其上下文窗口，这激发了越来越多关于记忆系统的研究。然而，现有的大多数设计都针对单一场景（多轮会话或单一轨迹格式）进行了调整，几乎没有证据表明它们能够泛化到智能体在部署中遇到的各种异质轨迹。我们重新审视了八个记忆系统以及一个针对搜索问题的智能体框架，在五个场景上进行了评估：单轮问答、多轮会话、智能体轨迹问答、记忆压力测试以及长期智能体任务。该框架通过工具调用自我管理平面文本文件存储，实现了最佳的跨任务排名，这表明记忆性能的关键在于赋予智能体对存储和检索的主动控制，而不是在固定管道后设置一个被动存储。我们将这一见解实例化为AutoMEM，这是一个具有自管理工具接口的智能体记忆框架，在我们评估的系统中实现了最佳的跨场景泛化能力。

## Abstract
LLM agents accumulate histories that outgrow their context windows, motivating a growing literature on memory systems. Yet most existing designs are tuned to a single scenario (multi-session chat or a single trajectory format), and there is little evidence that they generalize across the heterogeneous trajectories agents encounter in deployment. We revisit eight memory systems plus an agentic harness for search problems, on five scenarios: single-turn QA, multi-session chat, agentic-trajectory QA, memory stress tests, and long-horizon agentic tasks. The harness, which self-manages flat text-file storage via tool calls, achieves the best cross-task ranking, suggesting that memory performance hinges on giving the agent active control over storage and retrieval rather than on a passive store behind a fixed pipeline. We instantiate this insight in AutoMEM, an agentic memory harness with a self-managed tool interface that achieves the best cross-scenario generality among the systems we evaluate.

### 2. 论文提出的方法论
- **核心思想**：记忆性能的关键在于**赋予智能体对存储和检索的主动控制**（agentic control），而非依赖固定管道后的被动存储。一个让智能体通过工具调用自管理平面文本存储的框架（DCI-Lite）在跨场景泛化上表现最佳，但它在需要跨单元聚合信息的场景（如LoCoMo）上仍弱于索引方法。因此最优设计是将主动控制与选择性索引结合。
- **关键技术细节**：
  - 使用**DCI-Lite**作为智能体框架基线：智能体通过 `grep`、`read` 等工具直接操作原始轨迹文件，延迟承诺（deferred commitment）到查询时刻决定哪些证据需要读取。
  - 基于诊断提出**AutoMEM**：一个自管理记忆工具接口的智能体循环。算法流程（Algorithm 1）：
    - 初始化空证据跟踪 `trace` 和反馈 `hint`；
    - 循环最多 `Kmax` 步：每步由 `PLAN` 生成一个动作（来自 `{rg, read, dump, index_query}`），由 `EXECUTE` 执行工具调用得到证据，追加到 `trace`；
    - `JUDGE` 判断证据是否足够，若足够则终止循环，否则返回缺失的提示 `hint` 并重新规划；
    - 最后 `ANSWER` 基于 `trace` 组成最终答案。
  - **索引组件**：默认使用 LightMem 摘要索引构建的 Cypher 图（边的类型为 `SAID_BY`, `OF_TOPIC`, `FOLLOWS`），也可替换为 PlugMem 的多存储图。索引仅当在循环中调用 `index_query` 时使用，不会预先提交检索结果。
  - 还引入了两种优化：KV-cache友好聊天布局（提升前缀缓存命中率）和单遍模式（`Kmax=1`，同时执行所有工具调用）。

### 6. 论文的主要结论与发现
1. **无任何方法在所有场景上占据主导**。DCI-Lite智能体框架在**平均泛化排名**上最好（3.67），但并非在所有指标上最优。
2. **索引方法在智能体轨迹QA上存在两个根本失败模式**：
   - **表示级失败**：构建时的schema丢弃了步骤索引、动作标签等关键信息（如HippoRAG的实体-事实KG无法编码步骤）。
   - **检索级失败**：被动检索（如嵌入相似度）无法找到存储中已保留的证据（如PlugMem的存储包含答案但路由器选错分支）。
3. **长上下文比通常认为的更强且成本有竞争力**：长上下文在很多任务上表现优于复杂的索引方法，且当未来查询数量有限时，其总成本可能更低。
4. **在动态agentic任务（ALFWorld）上，记忆方法效果有限**：即使手动构建黄金过程记忆，仍无法完全闭合与GRPO训练的差距（Gap 1：弱智能体无法自我蒸馏过程记忆；Gap 2：规则文本无法编码状态条件决策）。这表明非参数记忆的性能天花板受限于智能体的先验能力。
5. **AutoMEM结合了智能体循环与选择性索引**，在LoCoMo上实现67.3分（比DCI-Lite提升22.3pp，比长上下文提升5.8pp），并在所有12个任务列中取得最佳平均排名（3.10）。

### 7. 优点
- **视角新颖**：首次系统探究跨场景泛化性，不止于单一任务优化。
- **诊断深入**：通过Oracle存储可回答性测试和受控探针，清晰分离表示级和检索级失败，为改进提供方向。
- **实验设计全面**：覆盖广泛的任务类型、方法类别，并跟踪token成本和延迟两个实际维度。
- **提出简单有效方案**：AutoMEM仅需在智能体框架上加一个索引工具，不需要重新训练，且提供效率优化。
- **分析透彻**：结构率指标很好地预测了索引方法的收益时机；对动态任务“策略受限”的分析连接到后续工作（SkillRL、OpenClaw-RL），具有启发性。

### 8. 不足与局限
- **无分层预算路由**：AutoMEM的所有步骤（规划、判断、回答）使用同一个骨干（Qwen3-32B），而规划与判断难度较低，可以通过路由到廉价模型显著降低成本，论文将此作为未来工作。
- **LC判断提示协议敏感**：宽松的judge提示可能反转方法排名；论文使用严格事实judge，但未做提示消融，绝对分数可能受作者选择影响，但相对排序应当稳健。
- **实验子集规模有限**：LoCoMo和HotpotQA各仅200个问题，AMABench每个域抽样未知（但Table 4是60个），MemoryAgentBench 200个，ALFWorld 60个，规模偏小，可能存在偏差风险（作者已解释为控制成本）。

- **未涉及持续学习或概念漂移**：所有测试为一次性构建+固定查询，未测试在多轮交互中更新记忆的性能消耗。
