## 摘要
传统操作系统围绕确定性程序、显式控制流和人类发起的工作流设计。其核心抽象——进程、线程、系统调用、文件和权限——假设有界行为和可预测的交互模式。智能体AI系统引入了一种不同的执行模型：长寿命、目标导向的实体，它们进行概率推理，动态调用工具，并根据反馈调整行为。尽管智能体目前可以作为用户空间应用程序实现，但其执行特征在调度、内存和状态管理、安全性、可观测性和治理方面给操作系统边界带来了压力。本文引入了智能体操作系统（AOS）的概念，这是一种将智能体控制平面集成到现有操作系统中的系统架构，在某些模型中，随着时间的推移，它还会接管部分操作系统的职责。我们提供了AOS的精确定义、明确的假设和非目标，并将AOS职责结构分解为调度器、上下文和内存管理、工具和能力注册表、策略和信任执行，以及可观测性和审计。我们分析了经典操作系统抽象在智能体工作负载上的局限性，提出了从用户空间运行时到分布式控制平面的集成模型，并将AOS概念映射到Linux和Windows原语上。我们讨论了安全性和保障性影响，包括智能体特定的威胁模型，并定义了强调确定性执行、可审计性和操作员可理解性的评估标准。目标不是完全取代操作系统，而是为智能体计算建立一个严谨的系统基础，使其在大规模下保持可控、可问责和安全。

## Abstract
Traditional operating systems were designed around deterministic programs, explicit control flow, and human initiated workflows. Their core abstractions processes, threads, system calls, files, and permissions assume bounded behavior and predictable interaction patterns. Agentic AI systems introduce a different execution model: long-lived, goal-directed entities that reason probabilistically, invoke tools dynamically, and adapt behavior based on feedback. While agents can be implemented as user-space applications today, their execution characteristics stress OS boundaries in scheduling, memory and state management, security, observability, and governance. This paper introduces the concept of an Agent Operating System (AOS), a systems architecture that integrates an agentic control plane into existing operating systems or, in some models, subsumes selected OS responsibilities over time. We provide a precise definition of an AOS, explicit assumptions and non-goals, and a structured decomposition of AOS responsibilities into schedulers, context and memory management, tool and capability registries, policy and trust enforcement, and observability and audit. We analyze limitations of classical OS abstractions for agent workloads, propose integration models from user-space runtimes to distributed control planes, and map AOS concepts onto Linux and Windows primitives. We present security and safety implications, including agent specific threat models, and define evaluation criteria that emphasize deterministic enforcement, auditability, and operator comprehensibility. The objective is not to replace operating systems wholesale, but to establish a rigorous systems foundation for agentic computation that remains controllable, accountable, and secure at scale.

## 1. 核心问题与整体含义（研究动机和背景）
- **核心问题**：传统操作系统（如Linux/Windows）的抽象（进程、线程、系统调用、文件、权限）是为确定性程序设计的，无法有效支持智能体（Agent）工作负载——这些智能体是**长寿命、目标导向、概率推理、动态调用工具、适应反馈**的执行实体。
- **背景**：当前智能体的实现通常作为用户空间应用，但生产系统中出现了**调度错位**（依赖外部事件而非CPU时间）、**内存模型不匹配**（状态包括上下文、记忆、来源元数据等，而非仅堆内存）、**安全不完整**（需要作用域化权限调用工具）、**可观测性不足**（需要决策溯源而非仅资源指标）、**治理缺失**（安全策略必须在概率推理中保持确定性执行）等系统性缺口。
- **研究意义**：需要为智能体计算建立**可控、可问责、安全的系统基础**，而非彻底替换传统OS。论文提出**智能体操作系统（AOS）** 作为结构化答案，将智能体控制平面集成到现有OS之上或部分接管OS职责。

## 2. 方法论：核心思想、关键技术细节
### 核心思想
- **AOS定义**：一个系统软件层，管理目标导向智能体的生命周期、执行、协调和治理，通过扩展或重新解释经典OS职责，同时在系统边界保持确定性行为。
- **三大分离平面**：
  - **推理平面**（Reasoning Plane）：概率推理、规划，可视为非可信。
  - **执行平面**（Execution Plane）：确定性工具调用、系统调用、副作用，强制执行策略。
  - **策略平面**（Policy Plane）：授权、风险检查、合规约束、预算控制，默认拒绝模糊的请求，并记录决策。
- **可信计算基（TCB）**：包括策略引擎、能力验证管道、中介层、执行沙箱控制、审计子系统等确定性组件；LLM推理引擎等概率组件在TCB之外，其输出必须经过确定性执行路径才能产生副作用。

### 关键技术细节与组件
1. **智能体生命周期管理器**：定义状态（创建、初始化、活跃推理、等待事件、执行、挂起、终止），管理持久标识、能力授权、上下文存储指针、确定性终止清理（取消飞行中请求、撤销令牌等）。
2. **智能体调度器**：区别于CPU调度，优化目标为**目标进度**，受策略、风险、预算约束。输入包括优先级、预算、依赖图、风险状态等；输出包括推理切片时间、工具调用时机、人工审批触发、限速/暂停/隔离。推理资源和执行资源分离。
3. **上下文与内存管理**：分为四类——短暂上下文、持久记忆、检索知识、执行记录。关键要求：上下文构建需确定性；检索集记录；摘要记录源输入和版本；过滤需确定性且可日志化；内存隔离命名化，保留和删除策略驱动并记录。
4. **工具和能力注册表**：工具定义包括名称、版本、输入模式、副作用分类、所需能力、速率限制、预检、后条件、审计要求。能力需明确且最小权限，允许批量拒绝。工具调用通过标准化管道：模式验证→策略检查→风险检查→预算检查→最小权限沙箱执行（媒介）→输出后检查→附加审计日志。
5. **策略、权限与信任**：分层策略——静态授权、能力约束、上下文策略、风险策略、治理策略。信任状态包括正常、受限、隔离、审查，状态转换基于确定性信号。
6. **可观测性与审计**：最小堆栈包括资源指标、进度指标、决策轨迹（提议+策略决定）、工具轨迹、数据溯源。审计记录需结构化、附加日志，支持确定性重放策略决策（不要求重放推理内部）。

### 集成模型
- **用户空间运行时**（低风险、可移植，但需防止绕过）
- **OS扩展**（通过LKM/eBPF/Windows钩子实现更强执行，增加复杂度）
- **分布式控制平面**（在Kubernetes等编排器上增加语义层）
- **长期部分子sumption**（如高层调度、策略，底层资源管理仍由内核负责）

## 6. 主要结论与发现
- **结论**：AOS通过引入智能体作为第一类实体，在调度、上下文/内存管理、工具中介、策略执行和审计方面扩展了OS责任，同时保持确定性执行边界。它不取代传统OS，而是提供控制平面，使智能体计算可预测、可审计、安全。
- **关键发现**：
  - 经典OS抽象（进程、线程、调度、权限）对智能体工作负载**不完全**，导致用户空间碎片化。
  - 将**推理与执行分离**、**策略与执行分离**是核心安全属性。
  - 可使用现有OS原语（cgroups、seccomp、namespace、job objects、ETW等）部分实现AOS，但需额外中介层。
  - 智能体威胁模型需要**状态性组合攻击**检测（不仅单动作检查），但异常检测可能依赖概率分类器，需平衡一致性与灵活性。
- **推荐路径**：用户空间运行时结合OS级强制执行（如强制网络出口经代理）是近期可行路径；长期可朝分布式控制平面和部分OS子sumption演进。
