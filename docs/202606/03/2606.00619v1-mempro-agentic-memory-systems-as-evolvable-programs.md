## 摘要
长程自主主体需要记忆系统来保留历史信息、追踪演化的状态，并在有限的上下文窗口之外重用相关知识。现有的主体记忆系统通常遵循记忆构建-检索（MCR）流水线，但往往主要调整记忆库，而在部署后保持周围流水线固定。这种固定流水线设计难以处理异构的任务特定失败模式，并且可能随着时间的推移与在规模和结构上演化的记忆库失调。为解决这些限制，我们提出了MemPro，一种系统级演化框架，将整个MCR流水线视为可演化程序，而不仅仅是调整记忆库或提示文本。MemPro维护一个可运行记忆系统实现的版本树，其中演化代理迭代地选择有前景的版本，诊断重复出现的失败，并通过失败模式引导的编辑-调试精炼创建改进的子版本。在LongMemEval、LoCoMo、HotpotQA和NarrativeQA上的实验表明，MemPro在少量迭代内持续优于强静态和提示级演化基线，随着演化持续改进，并取得了良好的性能-成本权衡。代码可在https://github.com/wanghai673/MemPro获取。

## Abstract
Long-horizon autonomous agents require memory systems to retain historical information, track evolving states, and reuse relevant knowledge beyond finite context windows. Existing agentic memory systems typically follow a memory construction-retrieval (MCR) pipeline, but often adapt mainly the memory bank while keeping the surrounding pipeline fixed after deployment. This fixed-pipeline design struggles to handle heterogeneous task-specific failure modes and can become misaligned with memory banks that evolve in scale and structure over time. To address these limitations, we propose MemPro, a system-level evolution framework that treats the entire MCR pipeline as an evolvable program rather than adapting only the memory bank or prompt text. MemPro maintains a version tree of runnable memory-system implementations, where an Evolving Agent iteratively selects promising versions, diagnoses recurring failures, and creates improved child versions through failure-mode-guided edit-debug refinement. Experiments on LongMemEval, LoCoMo, HotpotQA, and NarrativeQA show that MemPro consistently outperforms strong static and prompt-level evolving baselines within a few iterations, continues to improve with evolution, and achieves a favorable performance-cost trade-off. Code is available at https://github.com/wanghai673/MemPro.

## 1. 论文的核心问题与整体含义（研究动机和背景）

**核心问题**：  
现有的智能体记忆系统（agentic memory systems）通常遵循固定的“记忆构建-检索”（MCR）流水线。部署后，仅记忆库（memory bank）可以更新，而流水线本身（包括构建、检索、整合等逻辑）保持不变。这种固定设计带来两个关键缺陷：

- **任务异构性**：不同长期记忆任务（如时间推理 vs 跨会话推理）具有不同的失败模式，但固定流水线无法针对性地调整策略。
- **记忆-流水线失调**：随着记忆库在规模和结构上演变，固定流水线可能不再适配记忆的组织与使用方式，导致检索不完整、证据噪声或记忆利用低效。

**整体含义**：  
论文提出应将整个MCR流水线本身视为可演化的程序，而不只是调整记忆库或提示文本。通过系统级的自我演化，使记忆系统能够自适应任务需求与记忆库变化，从而提升长期自主智能体的性能。

## 2. 论文提出的方法论：核心思想、关键技术细节

### 2.1 核心思想
- **将MCR流水线作为可演化程序**：每一个流水线版本包含可执行代码（如构建、检索、整合、回答的逻辑）以及相关的提示文本（prompts）。
- **维护版本树**：每个节点是一个可运行的水线版本，并关联评估日志（包括总体得分、类别得分、父节点、综合评估等）。
- **迭代演化**：通过演化代理（Evolving Agent）执行选择、扩展、评估三步循环，逐步优化流水线。

### 2.2 关键技术细节
1. **初始化**：从初始的MCR流水线（v₀）开始，在训练集上评估得到日志。
2. **选择**：演化代理根据所有节点日志，基于整体得分高、改进方向泛化好、频繁失败模式等标准，选择最有前景的节点作为父节点，同时输出诊断分析。
3. **扩展**（内循环）：
   - 演化代理从父版本出发，在每一步选择动作：**EDIT**（修改流水线代码/提示）、**DEBUG**（选取诊断示例运行，获取执行迹，但不修改代码，仅更新诊断分析）、**TERMINATE**（结束扩展，输出新版本）。
   - 通过多次内循环逐步精炼，避免过早提交未验证的更改。
   - 调试阶段仅运行少量诊断示例，避免全训练集重评估，提高效率。
4. **评估**：在完整训练集上执行新版本，收集执行迹，由演化代理生成评估日志（包括总体得分、类别得分、父节点、综合评估）。
5. **版本树增长**：新节点加入树，后续迭代可从任何历史节点分支（不限于最新节点），从而保留强版本并探索不同方向。

### 2.3 关键设计特点
- **系统级演化**：不仅修改提示，还能修改可执行代码（如检索策略、整合逻辑、答案生成方式）。
- **版本树 vs 链式演化**：树结构允许从强历史版本分支，避免线性路径的局部最优。
- **编辑-调试循环**：扩展阶段内嵌诊断，逐步定位失败模式并针对性改进。
- **检索工具组合**：BM25关键词、嵌入向量检索、页面ID结构化检索三者互补。

## 3. 实验设计：数据集、基准与对比方法

### 3.1 数据集
- **长期记忆基准**：
  - **LongMemEval**：500个问题，6个类别（时间推理、多会话、知识更新、单用户、单助手、单偏好）。

- **长上下文QA基准**：
  - **HotpotQA**：三种上下文长度（56K、224K、448K tokens），各128个问题。
  - **NarrativeQA**（全文设置）：340个问题，使用文档全文。

**训练/测试划分**：  
- LongMemEval & LoCoMo：随机抽取10%样本用于演化训练，剩余90%为测试集。
- HotpotQA：从每种长度中抽取30个问题（23%）训练，其余98个测试。
- NarrativeQA：随机抽取40个问题（12%）训练，其余300个测试。

### 3.2 基准方法
- **直接上下文方法**：Full Text（全部历史输入）、Naive RAG（检索相关块）。

- **提示级演化方法**：GEPA（提示优化）、MetaMem（元记忆演化）。
- **系统级演化**：MemPro（本文方法），包含MemPro-5/10/15（分别对应5/10/15次演化迭代）。

### 3.3 评估指标
- **LongMemEval & LoCoMo**：LLM-as-a-Judge（使用GPT-4o-mini作为评判模型），输出正确/错误标志。

### 3.4 骨干模型设置
- 推理模型：GPT-4o-mini 和 Qwen3-30B-A3B-Instruct-2507（部分实验用Qwen2.5-14B）。

## 6. 论文的主要结论与发现

1. **系统级演化优于仅提示级演化**：MemPro在多个基准上以少量迭代超越所有静态和提示级演化基线（GEPA、MetaMem等），表明同时优化可执行代码和提示可以获得更大提升空间。
2. **版本树结构比链式演化更有效**：消融实验显示，去掉版本树（仅从最新版演化）导致性能下降，证明分支探索能力的重要性。
3. **持续改进潜力**：MemPro在达到SOTA后仍随迭代次数提升（5→10→15次），说明版本树带来的搜索空间尚未饱和。
4. **良好的性能-成本权衡**：MemPro在推理时token开销低于Full Text，与GAM、GEPA相近，但准确率更高。
5. **检索工具互补**：BM25、嵌入、PAGE-ID三者联合使用效果最佳，尤其是BM25贡献最大。
6. **类别差异分析**：在LongMemEval的Single-Assistant类别上，MemPro在GPT-4o-mini骨干下弱于部分基线，但这一差距在更强的Qwen骨干下消失，表明问题源于骨干模型与稀疏演化信号，而非方法本身。
