## 摘要
基于LLM的智能体能够通过将推理与环境反馈相结合来解决多步骤交互任务，然而每个回合都从相同的固定上下文开始，并且在此过程中发现的任何有用策略在任务结束后都会丢失。现有方法要么将学习限制在当前任务上，要么将所有经验汇集到一个单一的无类型存储中，而不区分知识类型、通过使用追踪质量或平衡库中仍缺少的内容。我们引入了统一上下文演化（UCE），一个无梯度框架，将智能体经验外部化为一个不断演化的类型化可演化上下文单元（ECU）库。UCE将经验分解为四种互补类型（记忆、策略、工作流程和技能），每种类型从特定条件下的轨迹生成，在决策时检索，通过重复使用结果评分，并在不再有价值时修剪。一个调度模块将每个周期的生成预算分配给库中最弱的类型。在两个交互基准测试中，UCE将ALFWorld的成功率从75.4%提高到96.3%，将WebShop的任务得分从45.1%提高到61.3%，并且累积的库可以迁移到替代的智能体骨干网络而无需重新训练。

## Abstract
LLM-based agents can solve multi-step interactive tasks by combining reasoning with environment feedback, yet each episode starts from the same fixed context and any useful strategy discovered along the way is lost once the task ends. Existing approaches either limit learning to the current task or pool all experience into a single untyped store, without distinguishing knowledge types, tracking quality through use, or balancing what the library still lacks. We introduce Unified Context Evolution (UCE), a gradient-free framework that externalizes agent experience into an evolving library of typed Evolvable Context Units (ECUs). UCE decomposes experience into four complementary types (Memory, Strategy, Workflow, and Skill), each generated from trajectories under type-specific conditions, retrieved at decision time, scored through repeated usage outcomes, and pruned when no longer valuable. A scheduling module allocates each cycle's generation budget toward the types where the library is weakest. Across two interactive benchmarks, UCE raises ALFWorld success from 75.4% to 96.3% and WebShop task score from 45.1% to 61.3%, and the accumulated library transfers to alternative actor backbones without retraining.

## 1. 核心问题与整体含义（研究动机和背景）

- **核心问题**：基于LLM的智能体（LLM agents）在解决多步交互任务时，每个回合（episode）都从相同的、固定的上下文（系统提示、少样本示例、工具 schema）开始。智能体在任务执行过程中发现的任何有用机制或策略，在任务结束后立即丢失，无法跨任务积累和复用。
- **现有方法的局限**：
  - **强化学习方法**（如WebRL、RAGEN）需要梯度访问和大量训练基础设施，不适用于闭源模型。
  - **任务内自适应方法**（如Reflexion、Self-Refine）改进仅限于当前任务，任务结束后改进消失。
  - **跨任务知识库方法**（如ExpeL、Voyager、Agent Workflow Memory）要么将所有知识混合存储在一个无类型池中，要么只专注于单一知识形式；它们通常通过一次性LLM评估来判断质量，而不是通过重复使用的实际效果；也没有机制来动态分配生成资源到不同类型的知识上。
- **研究意义**：提出一种无梯度的框架，使智能体能够通过上下文本身进行学习，将经验持久化到外部库中，实现跨任务的持续改进，且不依赖模型权重更新。

## 2. 方法论：核心思想、关键技术细节

- **核心思想**：Unified Context Evolution (UCE) 将智能体的经验外部化为一个不断演化的、带类型的**可演化上下文单元（ECU）库**。每个ECU是一个带有类型标签的知识条目，从收集到的轨迹中生成，在决策时检索并注入到智能体提示中，通过使用结果评估价值，并在不再有价值时被修剪。UCE将经验分解为四种互补的ECU类型，每种类型有独立的生成条件、检索边界和淘汰规则。通过**知识收益调度（KYS）**模块动态分配每个周期的生成预算到库中最弱的类型。
- **关键技术细节**：
  - **ECU的定义与表示**：每个ECU是一个五元组 `e = (z_e, τ_e, w_e, c_e, f_e)`，其中 `z_e` 是功能类型（memory, strategy, workflow, skill），`τ_e` 是任务类型（skill使用∅表示跨类型适用），`w_e` 是自然语言检索条件，`c_e` 是注入到智能体提示的知识内容，`f_e` 是适应性评分。
  - **四种ECU类型**：
    - **Memory**：捕捉环境机制，从单条轨迹生成，回答“环境如何工作？”（例如“水槽可以清洁物品，无需打开水龙头”）。
    - **Strategy**：编码在分支点的条件决策规则，从同一任务类型的多条轨迹生成，回答“在条件下应该选择什么？”（例如“如果放置失败，打开容器重试”）。
    - **Workflow**：描述任务类型的标准执行序列，从同一任务类型的成功轨迹生成，回答“应该遵循什么执行顺序？”（例如“找到目标，转换它，然后放到目标容器”）。
    - **Skill**：指定跨任务类型可复用的多步子操作方法，从多个任务类型的轨迹生成，回答“如何执行一个可复用的操作？”（例如“搜索容器，打开关闭的容器，找到目标时取出”）。
  - **检索公式**：在执行任务 `t_i` 前，检索器对每个ECU计算得分：`score(e, t_i) = sim(h_{w_e}, h_{d_i}) + β·1[τ_e = τ_i] + λ·(f_{τ_i}(e) - 0.5)`。其中 `h` 是句子Transformer嵌入，`β` 和 `λ` 是权重。每个类型独立排名，取前K个注入到四个专门提示段落中。
  - **适应性评分**：每个ECU跟踪一个拉普拉斯平滑的适应性分数：`f_e = (s_e + 1)/(u_e + 2)`，其中 `u_e` 是累积使用次数，`s_e` 是累积结果信用（成功+1，失败+0；连续奖励则加最终奖励）。新ECU的分数为0.5（表示未验证）。
  - **演化周期**：每个演化周期c执行5个阶段：
    1. **Evaluate**：在保留的评估任务集上运行智能体，记录成功率，不更新适应性分数。
    2. **Collect**：在不相交的收集任务集上运行智能体，存储轨迹，仅从收集结果更新适应性分数。
    3. **Schedule (KYS)**：读取库概况、收集成功率、上一周期实际生成计数和名义预算B，生成每种类型的整数生成预算。KYS有三层：
       - 层1（可行性过滤）：检查是否还有未覆盖的任务类型缺少相应ECU类型。
       - 层2（需求评估）：根据覆盖缺口和质量缺口计算需求 `d_c^{(k)}`。
       - 层3（收益追踪）：维护每种类型历史收益的指数移动平均 `y_c^{(k)}`。
       - 最后融合得分 `s_c^{(k)} = α_c d_c^{(k)} + (1-α_c) y_c^{(k)}`，分配预算。
    4. **Generate**：使用类型特定的生成器提示，从收集轨迹中提取候选ECU，包含质量反馈示例和重洗测试，去重后加入库。
    5. **Cleanup**：移除使用足够但分数低的ECU，在每个类型+任务类型组内只保留最高分数的ECU（当成员有足够使用后）。

## 6. 主要结论与发现

- **性能提升**：
  - ALFWorld：UCE峰值成功率达到96.3%，相比ReAct基线提升20.9个百分点（从75.4%）。最弱的子任务类型（Look从50%到100%，Pick2从52.9%到82.4%）提升最大。
  - WebShop：购买成功率从30.0%提升到42.0%，任务分数从45.1%提升到61.3%。
- **早期增益**：大多数ALFWorld收益在早期周期出现（初始库后从75.4%升至86.6%，一次更新后升至94.0%）。

  - ALFWorld：Workflow单独达到97.0%，接近全场最佳，说明可复用过程骨架是主要增益来源。Strategy（91.0%）、Memory（86.6%）、Skill（86.6%）各有贡献。
  - WebShop：没有单类型能匹配全UCE，说明购物任务需要多种知识类型协同。
- **错误分析**：WebShop主要失败模式是属性不匹配（50%）和步数超时（27%），提示UCE擅长捕捉环境和决策知识，但精确属性选择仍需策略优化方法。
- **案例研究**：展示了全UCE通过组合多种ECU类型（如Memory解释子标签只读、Strategy提供返回主页面恢复动作、Workflow提供搜索-购买流程）成功解决单一类型陷入陷阱的任务。

## 7. 优点

- **创新性**：首次提出带类型的、多类型协同的知识演化框架，解决了现有方法无类型混合或单一形式的不足。
- **模块化设计**：四种ECU类型覆盖从环境机制到决策规则、流程、可复用技能的不同粒度，检索时按类型独立排名，防止单一类型挤占其他类型。
- **实用性**：无梯度方法，不需要模型权重更新，兼容闭源LLM；库可独立于actor骨干，实现零成本迁移。
- **自动化调度**：KYS模块通过可行性过滤、需求评估、收益追踪三层信号，自适应分配生成预算到最弱的类型，避免浪费在已饱和类型上。
- **质量追踪**：基于重复使用结果的适应性分数，比一次性LLM评估更客观；包含条件分数（按任务类型统计）和全局分数回退机制。

## 8. 不足与局限

- **实验覆盖有限**：
  - 仅测试了两个基于文本的交互环境（ALFWorld和WebShop），动作空间离散、观察为文本，未涉及连续动作、多模态观察或更长规划视野的场景（如AndroidWorld, VisualWebArena）。

  - 仅使用单一闭源模型对（`gpt-4.1-mini` + `gpt-5.2`），无法区分改进来自框架设计本身、生成器的蒸馏能力、还是环境的规律性。
