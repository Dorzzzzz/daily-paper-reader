## 摘要
LLM在智能体记忆管道中的位置——位于检索已存储事实（广泛基准测试）的召回平面与通过替代、释放、清除（基本未测试）来改变它们的控制平面之间——塑造了系统可恢复哪些遗忘失败模式。在385个案例的对抗性表面上比较13种系统配置，我们观察到了三种具有部分互补覆盖范围的放置机制：确定性原语足以处理词汇/时间类别，但在规范化上失败（标识符混淆5%，跨语言0%）；写入时LLM恢复规范化（100%），但无法处理意图感知删除（前缀冲突和复合事实0%）；变异时钩子恢复意图感知删除（78-85%），并同时提升几乎所有类别（总体91.7-93.2%，每次385案例运行0.17美元，每个案例变异延迟2.3秒 vs. 确定性64-191毫秒/案例，召回路径不变）。我们通过ForgetEval揭示了这一权衡，包括一个1000案例的模板套件和一个385案例的对抗层（132个人工编写+253个LLM起草并经预言机验证），通过确定性子串匹配评分，并配有一个六种方法的适配器协议，采用诚实的N/A评分，允许异构记忆存储在130行代码中进入。10名标注者的IAA（Fleiss' kappa = 0.958）和77个外部编写子集（四位盲注贡献者）证实了接纳，该子集复制了规范化不对称性并放大了联合放置提升（+27.8个百分点）。生产故障主要是遗忘故障而非召回故障，但现有基准仅测量召回。ForgetEval和所有适配器均在MIT许可下发布。

## Abstract
Where an LLM sits in an agent memory pipeline -- between the recall plane that retrieves stored facts (extensively benchmarked) and the control plane that mutates them via supersede, release, purge (largely untested) -- shapes which forgetting failure modes the system recovers. Comparing thirteen system configurations on a 385-case adversarial surface, we observe three placement regimes with partly complementary coverage: deterministic primitives suffice for lexical/temporal categories but fail canonicalization (5% on identifier-obfuscation, 0% on cross-lingual); inscribe-time LLM recovers canonicalization (100%) but cannot help intent-aware deletion (0% on prefix-collision and compound-fact); a mutation-time hook recovers intent-aware deletion (78-85%) and brightens nearly all categories simultaneously (91.7-93.2% overall, $0.17 per 385-case run, 2.3s/case mutation latency vs. 64-191ms/case deterministic, recall path unchanged).   We expose the trade-off via ForgetEval, a 1000-case templated suite plus a 385-case adversarial layer (132 hand-crafted + 253 LLM-drafted oracle-validated) scored by deterministic substring match, paired with a six-method Adapter Protocol with honest N/A scoring that lets heterogeneous memory stores enter in 130 lines. Admission is corroborated by 10-annotator IAA (Fleiss' kappa = 0.958) and a 77-case external-authored subset (four blind contributors) that replicates the canonicalization asymmetry and amplifies the joint-placement lift (+27.8 pt). Production failures are predominantly forgetting failures rather than recall failures, yet existing benchmarks measure only recall. ForgetEval and all adapters are released under MIT.

## 1. 论文的核心问题与整体含义（研究动机和背景）

- **研究动机**：现有LLM智能体记忆基准（如LongMemEval、MTEB、BEIR、LOCOMO等）仅测量**召回平面**（recall plane）的性能，即检索已存储事实的能力；但生产环境中的失败主要是**遗忘失败**（forgetting failures），例如用户轮换的密码仍被推荐、GDPR删除的记录仍出现、用户信息在多会话间冲突等。这些失败是“检索得太好”，而非“检索不到”。然而，控制平面（control plane）——通过 supersede（替换）、release（释放）、purge（清除）等操作改变存储事实的能力——几乎未被测试。
- **核心问题**：LLM在智能体记忆管道中的放置位置（写入时、变异时、还是仅确定性原语）如何影响系统能够恢复的遗忘失败模式？不同放置策略是否互补？
- **整体含义**：遗忘失败是比召回失败更关键的生产故障，但领域内缺乏系统性评估。本文通过构建专门的遗忘基准和比较13种系统配置，揭示了LLM放置位置对遗忘能力的关键影响，并提供了可复现的评估框架。

## 2. 论文提出的方法论：核心思想、关键技术细节

- **核心思想**：遗忘不是二元的，而是可分解为5个结构性家族（supersession、decay、amnesia、purge、drift），每个家族对应不同的控制平面原语。LLM的放置位置（确定性原语、写入时LLM、变异时LLM）决定了系统能恢复哪些遗忘失败模式。
- **关键技术细节**：
  - **ForgetEval基准**：包含1000个模板案例（5个家族各4个子模板，确定性生成）和385个对抗性案例（132个人工编写+253个LLM起草并经预言机验证），覆盖10个攻击类别（substring_trap、prefix_collision、paraphrase_supersession、negation_trap、temporal_qualifier、shared_attribute、compound_fact、identifier_obfuscation、cross_lingual_identifier、recursive_supersession）。
  - **评分方式**：完全确定性子串匹配（top-10召回中 must_contain 子串全部出现且 must_not_contain 子串全部不出现），无需LLM裁判。
  - **Adapter协议**：6个方法的接口合约（reset、inscribe、recall_texts、supersede、release、purge），支持N/A评分（原始缺失视为未实现），允许异构记忆系统在约130行代码内接入评估。
  - **控制平面放置分类**：通过比较13种系统配置，归纳为6种放置机制（无删除、确定性向量存储、仅向量、写入时LLM、KG抽象、写入+变异联合、变异时挂钩）。
  - **变异时挂钩**：使用窄的JSON格式提示调用LLM，仅修改变异操作（supersede/purge/release），召回路径完全不变，不引入LLM延迟。

## 6. 论文的主要结论与发现

- **三种放置机制互补**：
  - 确定性原语：在词汇/时间类类别（temporal_qualifier: 100%, negation_trap: 95%）表现完美，但在规范化（identifier_obfuscation: 5%, cross_lingual: 0%）和意图感知删除（prefix_collision: 31-82%因系统而异）失败。
  - 写入时LLM（A-MEM、Mem0+v3、Letta）：恢复规范化（100%），但无法处理意图感知删除（prefix_collision: 0%, compound_fact: 0%）。
  - 变异时LLM挂钩（LETHE+LLM、LangGraph+LLM）：同时恢复规范化（92-100%）和意图感知删除（compound_fact: 78-85%, prefix_collision: 79%），整体通过率达91.7-93.2%（排除compound_fact后93.3-94.2%），成本极低（$0.17/385案例）。

- **LLM挂钩架构无关性**：同样的窄JSON挂钩应用于不同后端（LETHE、LangGraph、Letta），提升效果一致（Δ +28-30 pt），且跨LLM（DeepSeek-V3 vs Qwen-2.5-72B）也稳健（但Qwen提升较小 +13 pt，Llama无法解析JSON导致回退）。

- **Recall-Forgetting权衡**：不同记忆系统占据不同位置：LETHE在遗忘轴领先但召回轴较弱，LangGraph在召回轴领先但遗忘轴较弱，MemPalace在两者均被主导。LLM挂钩在不改变召回的前提下提升遗忘轴。

- **现有基准的局限性**：MemPalace在召回记忆基准Memora上得40%，但在ForgetEval-Adv上得0/385；FactConsolidation（仅测试单跳/多跳召回）与ForgetEval完全正交，LLM挂钩在该基准上无效。

## 7. 优点

- **新颖的研究问题**：首个系统研究LLM在控制平面中的放置对遗忘模式影响的论文，填补了召回-遗忘轴上的空白。
- **全面的基准构建**：ForgetEval覆盖5个遗忘家族和10个攻击类别，包括模板和对抗案例，且有高人工标注一致性（Fleiss' kappa = 0.958）。
- **公平的适配器协议**：使用N/A评分允许缺失原语系统诚实比较，避免偏袒。评分完全确定性，可复现。
- **跨验证充分**：通过外部作者子集、跨LLM消融、跨架构消融、人工审核等多种方式验证结论的稳健性。
- **实用导向**：变异时挂钩设计极简（窄JSON提示），召回路径零修改，实际部署成本极低，且提示开源。
- **严格的方法论自省**：详细记录LLM裁判的失败模式（语义等价过度拒绝等），公开所有审计信息。

## 8. 不足与局限

- **子串评分盲点**：30%的确定性失败是评分伪影（集中在prefix_collision和子句级替换），影响整体通过率估计，但核心结论类别（规范化和跨语言）无伪影。未来需升级为ID感知或NLI评分。
- **英语为主，语言覆盖薄**：cross_lingual_identifier仅覆盖9个脚本，部分脚本仅1-3个案例，不能统计区分LLM挂钩间的差异。韩语、阿拉伯语、印地语等长尾脚本未来需扩展。
- **记忆系统覆盖不全**：未评估Redis Semantic Memory、AutoGen Memory等商业/托管系统（因API或账户要求），且部分系统（Cognee）因API不兼容未纳入。社区贡献适配器是自然扩展。
- **LLM质量依赖性**：变异时挂钩的提升高度依赖LLM的JSON遵循能力（DeepSeek-V3 +28-30pt, Qwen-2.5-72B +13pt, Llama 失败），弱模型提升有限。
- **外部子集难度高**：外部作者编写的案例使部分类别（negation_trap、compound_fact、recursive_supersession）完全无法通过，表明ForgetEval的难度分布不均匀，未来需平衡难度。
- **生态有效性**：虽然映射了GDPR删除、凭据泄漏等生产故障类型，但缺乏对实际生产部署的实证关联研究（如系统在ForgetEval高分是否真的泄漏更少），这是未来工作。
- **compound_fact是原语存在性测试**：该类别测试部分编辑原语，不是遗忘能力本身。不含该类别时LLM挂钩提升仍达+22.6~24.1 pt，但需读者注意此区别。
