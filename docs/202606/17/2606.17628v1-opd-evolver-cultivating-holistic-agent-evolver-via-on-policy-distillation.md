## 摘要
记忆已成为自演化智能体的标准基础，但保留经验并不等同于学习如何通过经验进行演化。现有的记忆智能体可以存储轨迹、检索反思或积累技能，但往往缺乏整体能力来选择有用经验、据此行动、撰写可重用知识并维护不断增长的存储库。我们提出OPD-Evolver，一个快慢协同演化框架，通过同策略自蒸馏培养这样的智能体演化器。在快循环中，OPD-Evolver与四级记忆层次交互，以读取、使用、撰写和维护经验，实现快速的测试时演化。在慢循环中，结果校准的记忆归因与特权后见将这些能力蒸馏到可部署策略中。跨多领域基准测试，OPD-Evolver超越诸如ReasoningBank的记忆系统高达11.5%，超越诸如Skill0的基于训练的方法约5.8%。进一步分析表明，OPD-Evolver内化了高价值经验和记忆管理，使OPD-Evolver-9B能够挑战诸如Qwen3.5-397B-A17B和Step-3.5-Flash等巨量对手，标志着超越记忆增强智能体，迈向真正合格的智能体演化器。

## Abstract
Memory has become a standard substrate for self-evolving agents, yet retaining experience is not the same as learning how to evolve through it. Existing memory agents can store trajectories, retrieve reflections, or accumulate skills, but often lack the holistic competence to select useful experience, act on it, write reusable knowledge, and maintain a growing repository. We introduce OPD-Evolver, a slow-fast co-evolution framework that cultivates such an agent evolver through on-policy self-distillation. In the fast loop, OPD-Evolver interacts with a four-level memory hierarchy to read, use, write, and maintain experience for rapid test-time evolution. In the slow loop, outcome-calibrated memory attribution and privileged hindsight distill these four abilities into the deployable policy. Across multi-domain benchmarks, OPD-Evolver surpasses memory systems such as ReasoningBank by up to 11.5%, and training-based methods such as Skill0 by ~5.8%. Further analysis shows that OPD-Evolver internalizes high-value experience and memory management, enabling OPD-Evolver-9B to challenge giant counterparts such as Qwen3.5-397B-A17B and Step-3.5-Flash, pointing beyond memory-augmented agents toward genuinely qualified agent evolvers.

## 1. 核心问题与整体含义（研究动机和背景）

- **研究背景**：自演化智能体依赖记忆（存储轨迹、检索反思、积累技能）来改进行为，但现有记忆系统只能“存储经验”，而无法“学会如何从经验中演化”。大多数方法仅优化演化过程的单一环节（如检索、使用、蒸馏或记忆架构），缺乏整体的演化能力。
- **核心问题**：如何训练一个智能体，使其具备从经验中持续进化的整体能力——即成为一个合格的智能体演化器（agent evolver）？具体需要四项耦合能力：
  1. **经验选择**：从嘈杂的仓库中识别有用记忆；
  2. **经验驱动的执行**：将选中的经验转化为有效的多步行动；
  3. **经验撰写**：从新轨迹和反馈中提取可重用知识；
  4. **经验管理**：随时间对记忆评分、合并、更新和淘汰。
- **整体含义**：真正的自演化不应只是记忆增强，而应是一个闭环的“任务-记忆-行为-更新”过程。论文由此提出OPD-Evolver，旨在培养这类整体进化者。

## 2. 方法论：核心思想、关键技术细节

- **核心思想**：采用**快慢双循环协同演化框架**。
  - **快循环**（Fast Evolution Loop）：智能体在线与环境交互，利用四级记忆层次（轨迹、技巧、技能、工具）快速进行测试时演化，包括选择、执行、撰写和定期维护。
  - **慢循环**（Slow Evolution Loop）：将任务结果和特权后见（privileged hindsight）转化为同策略自蒸馏信号，训练智能体自身的演化能力。

- **关键技术细节**：
  1. **四级经验记忆**：`M_t = M_traj ∪ M_tip ∪ M_skill ∪ M_tool`，分别存储：
     - 轨迹（episodic evidence）
     - 技巧（局部警告或启发式）
     - 技能（可重用程序）
     - 工具（可执行命令/代码模板）
  2. **检索与选择**：查询 `z_t = [x_t; e_t]`，对每层记忆通过嵌入余弦相似度检索前K个候选，然后由智能体自身的选择器 `Sel^ℓ_θ` 压缩为紧凑上下文 `c_t`。
  3. **执行与撰写**：智能体条件于上下文 `c_t` 生成动作，任务结束后，同一智能体根据任务结果决定写入哪些记忆（可写入任意层级，数量由智能体自定）。
  4. **定期维护**：每Q=30个任务，智能体通过 `{lookup, merge, delete}` 工具调用进行存储库维护。
  5. **结果校准归因**（Outcome-calibrated Attribution）：利用环境反馈 `R_t` 估计每个记忆的分数 `V(m)`，公式考虑任务分组内被选中/未被选中的任务回报差异及置信度。
  6. **统一后见自蒸馏**：对选择、执行、撰写、维护四种决策，学生仅看到公共输入 `z_k`，教师额外看到特权后见 `h_k`，然后计算学生生成前缀上的KL散度作为损失 `L_slow(θ)`。

- **算法流程**（文字说明）：
  - 初始化空记忆库和智能体策略。
  - 对于每个任务：构造查询，从各层检索候选，由智能体选择上下文，执行动作得到轨迹和回报，再由智能体撰写新记忆并更新库。
  - 每Q个任务执行一次维护。
  - 记录所有日志。
  - 慢循环：对每条记忆估计分数，构造四类决策的 (z, h) 对，学生采样输出，教师以学生前缀为条件输出蒸馏目标，最小化KL散度。
