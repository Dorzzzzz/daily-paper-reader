## Abstract
Despite their success in specific scenarios, existing foundation agents still struggle to generalize across various virtual scenarios, mainly due to the dramatically different encapsulations of environments with manually designed observation and action spaces. To handle this issue, we propose the General Computer Control (GCC) setting to restrict foundation agents to interact with software through the most unified and standardized interface, i.e., using screenshots as input and keyboard and mouse actions as output. We introduce Cradle, a modular and flexible LMM-powered framework, as a preliminary attempt towards GCC. Enhanced by six key modules, Information Gathering, Self-Reflection, Task Inference, Skill Curation, Action Planning, and Memory, Cradle is able to understand input screenshots and output executable code for low-level keyboard and mouse control after high-level planning and information retrieval, so that Cradle can interact with any software and complete long-horizon complex tasks without relying on any built-in APIs. Experimental results show that Cradle exhibits remarkable generalizability and impressive performance across four previously unexplored commercial video games (Red Dead Redemption 2, Cities:Skylines, Stardew Valley and Dealer's Life 2), five software applications (Chrome, Outlook, Feishu, Meitu and CapCut), and a comprehensive benchmark, OSWorld. With a unified interface to interact with any software, Cradle greatly extends the reach of foundation agents thus paving the way for generalist agents.

## 1. 核心问题与整体含义（研究动机和背景）
- **问题**：现有基础智能体（Foundation Agents）在特定场景中表现良好，但难以泛化到不同虚拟场景，主要原因在于各环境的观测空间和动作空间高度定制化，缺乏统一接口。
- **动机**：计算机是连接人类与数字世界最通用的界面，若智能体能通过统一的人类交互方式（屏幕截图输入、键盘鼠标输出）操作任意软件，则可规避机器人硬件的限制，成为通往通用人工智能（AGI）的可行路径。
- **含义**：本文提出**通用计算机控制（General Computer Control, GCC）** 设定，旨在构建能通过同一界面掌握任意计算机任务的智能体，并实现首个初步框架 Cradle，极大拓展了基础智能体的应用边界。

## 2. 方法论
### 核心思想
- Cradle 是一个**基于大型多模态模型（LMM）的模块化框架**，仅以屏幕视频为输入，输出键盘鼠标操作的 Python 代码，不依赖任何内置 API。
- 包含**六大关键模块**：
  - **信息收集（Information Gathering）**：从视频帧中提取文本（OCR）和视觉信息（布局、图标、动画等），并可借助 Grounding DINO、SAM 等工具增强目标检测与定位。
  - **自我反思（Self-Reflection）**：评估上一动作是否成功、任务是否完成，分析失败原因，用于后续纠正。
  - **任务推断（Task Inference）**：根据当前状态和反思结果，决定继续当前任务还是提出新任务，并推断任务优先级和时长。
  - **技能管理（Skill Curation）**：生成、更新、检索技能（以 Python 函数形式封装底层键盘鼠标操作），可来自游戏教程、手册或自我探索。
  - **行动规划（Action Planning）**：从技能库中选择合适技能并实例化参数（位置、时长等），输出可执行动作序列。
  - **记忆（Memory）**：包括**情景记忆**（存储关键截图、推理结果、短期和长期摘要）和**程序记忆**（存储技能代码及其嵌入向量，通过余弦相似度检索）。

### 关键技术细节
- 使用 **GPT-4o** 作为骨干模型，温度设为 0，嵌入模型采用 `text-embedding-ada-002`。
- 动作空间覆盖所有键盘和鼠标操作（按压、释放、移动、滚动等），支持组合键和复杂时序。
- 为提升 LMM 的视觉理解，采用**分网格描述**（如 3×5 网格）、**颜色增强带**、**SoM 式标注（SAM2SOM）** 等视觉提示方法。
- 游戏环境（如 RDR2、Stardew Valley）在等待 LMM 响应时暂停，其他应用连续运行。

## 3. 实验设计
### 使用的场景与基准
- **视频游戏**（4款商业游戏）：
  - *Red Dead Redemption 2*（AAA 级 3D RPG）—— 第一、二章主线任务（13 个子任务），含导航、战斗、搜索等。
  - *Stardew Valley*（2D 像素风农场模拟）—— 农场清理、耕种、购物。
  - *Dealer’s Life 2*（当铺模拟）—— 一周店铺管理（议价交易）。
  - *Cities: Skylines*（城市建造）—— 从零建设城市并最大化人口。
- **软件应用**（5款）：Chrome、Outlook、CapCut、Meitu、Feishu，每款设计 5 个代表性任务。
- **综合基准**：OSWorld（369 个真实计算机任务，涉及多种桌面应用）。

### 对比方法
- **React-like**：仅有信息收集、技能管理、行动规划和程序记忆。
- **Reflextion-like**：在 React-like 基础上增加自我反思和情景记忆。
- **Voyager-like**：将图像转为文本描述再输入（失去视觉信息）。
- 使用不同骨干模型（GPT-4o vs. Claude 3 Opus）进行对比。
- 消融实验：依次移除信息收集、自我反思、任务推断、情景记忆等模块。

- **实验数量**：

  - OSWorld 基准直接使用官方评价脚本，运行一次。
  - 消融实验：在 RDR2 的 6 个连续子任务上进行，每种子任务运行 5 次。

  - 消融实验验证了每个模块的必要性，自我反思和信息收集影响最大。

## 6. 主要结论与发现
- Cradle 首次使 LMM 驱动的智能体能够完成 AAA 级游戏（RDR2）的主线剧情任务（约一小时时长），并在多个商业游戏和软件中表现出较好的泛化能力。
- 在 Dealer’s Life 2 中，Cradle 的总利润率达 +39.6%，甚至超过人类玩家（+17.3%），主要归因于其谨慎且持续的议价策略。
- 在 Cities: Skylines 中，Cradle 建造的城市人口达 450 人（最高 860+），但与人类玩家持平；主要失败点在于水管连接不足导致的局部缺水。
- 在 OSWorld 基准上，Cradle 以 7.81% 的总体成功率超越无额外 API 的基线方法（GPT-4o 为 5.03%），在专业领域提升尤为明显（20.41%）。
- 消融实验证实，信息收集和自我反思模块对复杂任务至关重要，情景记忆在长时任务中不可或缺。
- 局限仍然存在：LMM 对非写实风格图像（如像素画）识别困难、空间感知不足、响应延迟高、未处理音频模态、调用成本较高等。

## 7. 优点（方法/实验设计亮点）
- **统一性**：提出 GCC 设定，仅需屏幕截图和键盘鼠标操作，无需任何内置 API，真正实现跨环境泛化。
- **模块化设计**：六大模块功能清晰、可替换，便于后续改进；记忆模块（情景+程序）有效支持长时任务。
- **自主学习能力**：通过自我反思和技能管理，智能体可像人类一样从教程和探索中习得新技能，并不断调整策略。
- **广泛的应用覆盖**：同时涵盖复杂3A游戏、模拟经营游戏、日常办公软件、图像视频编辑工具以及操作系统级任务，场景极其丰富。
- **实用的视觉增强**：采用 SoM 风格标注（SAM2SOM）、网格分割、颜色提示等手段，显著改善了 LMM 对 GUI 元素的空间定位能力。
- **首次实现 AAA 游戏的主线任务完成**：在 RDR2 中，智能体可自主完成长达一小时的连续任务，展示出强大的长时规划和执行能力。

## 8. 不足与局限
- **LMM 能力瓶颈**：当前 GPT-4o 在非真实风格（如像素画 Stardew Valley）、细粒度空间定位、图标识别等方面仍显不足，导致部分任务成功率低。
- **延迟与实时性**：LMM 推理延迟（可达 1 分钟/次）迫使游戏暂停，无法处理需要快速反应的场景（如实时战斗），且暂停时游戏世界仍可能变化。
- **未使用音频模态**：游戏中重要提示常通过音频传递，本文未考虑，限制了任务理解。
- **成本高昂**：单次完整实验约 5,400 美元，难以大规模重复，统计可靠性受限。
- **模块调用频繁**：每个模块独立调用 LMM，导致大量冗余计算和极高 token 消耗（如 RDR2 输入 6 亿 tokens），未来可考虑合并部分模块为单一请求。
- **实验重复次数有限**：由于时间与成本，每个任务仅运行 5 次，部分任务标准差较大，结论的统计显著性有待加强。
- **未覆盖所有计算机任务**：仅测试了少数代表性游戏和应用，泛化到其他软件（如 CAD、编程 IDE 等）仍需验证。
- **安全与伦理风险**：可能被用于开发游戏外挂、误操作删除文件、隐私泄露等，需引入错误处理和人类监督机制。
